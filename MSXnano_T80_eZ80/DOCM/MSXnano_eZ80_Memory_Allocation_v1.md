# MSXnano eZ80 メモリ割当・予約バンク仕様 v1

作成日: 2026-10-10
対象: Tang Nano 20K、8MiB SDRAM、T80由来eZ80拡張CPU
状態: メモリ接続に向けた割当仕様。以下のeZ80直接アクセスは未実装。
参照資料: ユーザー提供「SDRAMメモリマップ.md」（MSXnano-Z80X 実装検証版）。

## 1. 方針

1バンクを64KiB（65536バイト）とし、eZ80アドレスの上位8bitを論理バンク番号とする。
VRAM 256KiBを4バンク、MegaRAM/SCC 2MiBを32バンクとしてeZ80空間に固定予約する。
既存のCPU拡張バンク01h～1BhとMSX互換バンク00hを維持する。

今回新規に決める予約番号は、MegaRAM=40h～5Fh、VRAM=60h～63h。
これらの番号は対応するSDRAM物理アドレスの上位バイトと一致させ、変換を簡単にする。
01h～1Bhは既存案を維持するためオフセット変換を用いる。

予約バンクは汎用ヒープ・スタック・プログラム配置に自動割当しない。
MegaRAMとVRAMは既存機能が使う同じSDRAMへの別名参照（alias）とする。
新しい専用メモリを増設したり、既存MegaRAM/VDPを自動的に無効化したりする仕様ではない。
MegaRAMをeZ80専用ワーク領域にする場合は、利用ソフトが既存MegaRAM/SCC使用を停止し、
双方の所有権を調整してから使用する。切替用の新規I/Oポート番号は本書では追加しない。

## 2. eZ80論理バンク割当

すべてのアドレス範囲は両端を含む。KiB/MiBは1024/1048576バイト単位。

| 論理バンク | eZ80論理アドレス | バンク数 | 容量 | 用途 | 接続先 |
|---|---|---:|---:|---|---|
| 00h | 000000h～00FFFFh | 1 | 64KiB | MSX互換窓 | 既存スロット・BIOS・Mapper経路 |
| 01h～1Bh | 010000h～1BFFFFh | 27 | 1,728KiB（1.6875MiB） | CPU拡張RAM | SDRAM 650000h～7FFFFFh |
| 1Ch～3Fh | 1C0000h～3FFFFFh | 36 | 2,304KiBの論理空間 | 将来用／未接続 | なし |
| **40h～5Fh** | **400000h～5FFFFFh** | **32** | **2MiB** | **MegaRAM/SCC予約枠** | **SDRAM 400000h～5FFFFFhと共有** |
| **60h～63h** | **600000h～63FFFFh** | **4** | **256KiB** | **VRAM予約枠** | **SDRAM 600000h～63FFFFhと共有** |
| 64h～FFh | 640000h～FFFFFFh | 156 | 9,984KiBの論理空間 | 将来用／未接続 | なし |

「論理空間の容量」は実装RAM容量ではない。未接続範囲を実装済みRAMとして扱わない。
00hの読出し・書込み可否は既存MSXスロットのROM/RAM属性に従う。

## 3. SDRAM物理配置（既存配置を維持）

SDRAM物理アドレスは23bit、000000h～7FFFFFhの8MiB。

| 物理アドレス | 容量 | 既存用途 | eZ80側の対応 |
|---|---:|---|---|
| 000000h～3FFFFFh | 4MiB | Memory Mapper | バンク00hの既存MSX窓から参照。直接の全域aliasは予約しない |
| 400000h～5FFFFFh | 2MiB | MegaRAM/SCC | バンク40h～5Fh |
| 600000h～61FFFFh | 128KiB | 現在のVDP VRAM実使用分（参照資料による） | バンク60h～61h |
| 620000h～63FFFFh | 128KiB | VRAM拡張予約 | バンク62h～63h |
| 640000h～64FFFFh | 64KiB | 物理予備領域 | 今回は未割当 |
| 650000h～7FFFFFh | 1,728KiB | CPU拡張RAM | バンク01h～1Bh |

論理バンク64hを物理640000hへ自動接続しない。
物理予備64KiBと、論理バンク64hは別の概念である。
MAIN-ROM/SUB-ROM/ロゴは参照資料に従いBSRAM配置を維持し、SDRAMの予約枠へ移さない。

## 4. アドレス変換規則

B = eZ80アドレス[23:16]、O = eZ80アドレス[15:0]。
メモリアクセスのみを以下の規則で振り分け、I/O・リフレッシュ・割込み応答は区別する。

| 条件 | 処理／物理バイトアドレス |
|---|---|
| B=00h | 既存MSX経路。Oをスロット／Mapper等のデコードへ渡す |
| 01h≦B≦1Bh | P = 640000h + (B×10000h) + O |
| 40h≦B≦5Fh | P = B×10000h + O（MegaRAM共有） |
| 60h≦B≦63h | P = B×10000h + O（VRAM共有） |
| その他 | 読出しFFh、書込み無視。SDRAM要求なし |

CPU拡張RAM用の「640000hを加算する」規則をMegaRAM/VRAM予約バンクに適用しない。
デコードと範囲判定を24bitで行い、合法な物理アドレスだけを23bitのSDRAM経路へ渡す。
上位bitを先に捨てて8MiBへ折り返す実装は禁止する。

### 変換例

| eZ80論理アドレス | SDRAM物理アドレス／経路 |
|---|---|
| 008000h | MSX窓の8000h。選択中のスロット／Mapperに依存 |
| 010000h | 650000h |
| 1BFFFFh | 7FFFFFh |
| 400000h | 400000h（MegaRAM先頭） |
| 5FFFFFh | 5FFFFFh（MegaRAM末尾） |
| 600000h | 600000h（VRAM先頭） |
| 63FFFFh | 63FFFFh（VRAM予約枠末尾） |
| 640000h | 未接続（物理640000hへのaliasではない） |
| FF0000h | 未接続 |

## 5. 予約枠内のバンク番号

### MegaRAM/SCC

バンク40h+i（i=0～31）はMegaRAM先頭からi×10000hの位置を指す。
eZ80側では16KiBのカートリッジバンク切替に依存せず、2MiBの予約枠を線形に参照する。
既存MSX経路のMegaRAMバンク設定を変えるアクセスではなく、同じ保存領域への直接アクセス。
SCCのI/O・波形レジスタ操作はこのメモリaliasに含めない。対応づけは実際のRTLで確認する。

### VRAM

| バンク | VRAM内オフセット | 容量 | 用途 |
|---|---|---:|---|
| 60h | 00000h～0FFFFh | 64KiB | 現行VRAM下位 |
| 61h | 10000h～1FFFFh | 64KiB | 現行VRAM上位 |
| 62h | 20000h～2FFFFh | 64KiB | 拡張予約 |
| 63h | 30000h～3FFFFh | 64KiB | 拡張予約 |

256KiBを予約することと、VDPが256KiB全体を表示・コマンド処理に使用できることは別である。
現在のVDP側アドレス幅が17bitなら、62h～63hをVDPから参照するには別途幅拡張が必要。
eZ80側を256KiB対応で実装する際も、17bit切捨てによる60h/61hへのaliasを発生させない。
VDPのパレット・レジスタ・ステータス等はVRAMのメモリaliasに含めない。

## 6. 調停・データ共有の要件

- 拡張バンクへのCPUアクセスでは、下位16bitが一致しただけでBIOS・Mapper・MegaRAMなどの
  既存MSX経路が同時に書き込まれないよう、要求の発行と応答データ選択を分離する。
- 参照資料のZ80X24版で発生したMapper要求との競合を回帰テストに含める。
  CPU拡張要求を既存CPUメモリ要求より優先するか、既存要求を抑止して排他的にする。
- この優先処理でVDPの専用タイムスロットを奪わない。VRAMとMegaRAMもSDRAMコントローラを
  通して調停し、CPUとVDP／既存MSX側が同時に直接SDRAM端子を駆動しない。
- **VRAMアクセスの競合時は、VDPの読出しをCPUの読出し・書込みより優先する。**
  VDPの描画用読出しに必要なタイムスロットを確保し、同じサイクル／SDRAM資源を
  eZ80 CPUが要求した場合は、CPU側にWAITをかけてアクセスを保留する。
  CPUはVDP読出しと競合しない利用可能なスロットで処理する。
- CPUへのWAITは、競合解消だけで直ちに解除せず、保留したCPU要求の読出しデータ確定、
  または書込み完了を確認してから解除する。読出し・書込みの両方を対象とする。
  CPUの待機中もVDPとSDRAMコントローラのクロック・状態進行は停止させない。
- WAIT中はアドレス、書込みデータ、要求種別を保持し、1要求に1完了応答を返す。
- VRAM直接アクセスはVDPポート98h等のエミュレーションではなく、保存メモリの共有。
  VDPコマンドや描画と競合すると書込みが混ざるため、ソフト側でも完了・利用タイミングを調整する。
- 同じ物理領域のaliasなので、eZ80による書込みは既存MegaRAM/VDP側にも見える。
  メモリ所有権と更新完了を共有する。eZ80汎用RAMとして無条件には再利用しない。

## 7. 実装時の検証項目

| 検証 | 確認内容 |
|---|---|
| バンク00h回帰 | BIOS、DOS、既存Mapper、ゲーム動作を保持 |
| CPU拡張RAM | 01h/1Bhの先頭・末尾、バンク間独立性、Mapperへの誤書込みなし |
| MegaRAM予約枠 | 40h/5Fhの先頭・末尾、既存MSX経路との相互読出し |
| VRAM予約枠 | 60h～63hの独立性、特に62h/63hが60h/61hへ折り返さない |
| 範囲外 | 1Ch、3Fh、64h、FFhの読出しFFh・書込み無視、予備領域を壊さない |
| 境界転送 | 16bit/24bit幅の規則に応じた境界越え、終端の次バンクを再デコード |
| 同時要求 | CPU＋VDP、CPU＋Mapper、CPU＋MegaRAM、WAIT途中停止・再開 |
| VRAM優先順位 | CPU読出し／書込みとVDP読出しが競合したとき、VDPを先に処理しCPUはWAIT。VDP読出し期限の維持、CPU要求保持、完了後のWAIT解除と二重書込み防止 |
| 共有領域 | VDPコマンドとCPUアクセス、MegaRAM/SCC使用中の所有権調整 |

各テストは実際に接続を実装してから行う。本書作成時点でPASS済みとは扱わない。

## 8. 現在の実装との差分

現在のeZ80 v5はPC/命令取得24bit化の基盤までで、MSXトップの24bitメモリ接続は未実装。
本書はその接続時に使う割当仕様を定めるもので、v5のソース／ビットストリームを変更しない。
ユーザー提供の参照資料にあるZ80X24版の追加ポート・実機検証は、eZ80版の実装済み事項ではない。
実装前にeZ80版top、memory_ctrl、VDP側のアドレス生成を照合する。
旧独自CPUのM0/M1/M2やF0h/F1h/F2h MMU設定は、本書からeZ80仕様へ自動的に持ち込まない。
本書では固定デコード方式の予約枠を採用し、MMUテーブルや新しいモード命令は追加しない。
