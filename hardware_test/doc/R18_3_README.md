# R18.3 — RST開始要求の登録・比較版

## 目的と現時点の判断

R17を再ビルドした実機でEZ80MEM P1:PASS、R18で同じ試験が失敗したため、R17→R18で追加したRST判定の共有制御経路への影響を切り分ける版です。実機不良の原因を確定した修正ではありません。GOWIN合成、LUT/CLS使用量、STA、実機動作は未確認です。

R18のRSTは既にCALLと共通のframe_pushを使用していました。本版もその処理を維持し、要求の判定時点を分けます。命令の追加やテストの期待値変更はありません。

## RTL変更

- フェッチT2で受理したIRと幅指定を、通常CPUが実際に進むフェッチT3で参照し、RST開始対象かを1ビットのFrame_Rst_Pendingへ登録します。
- 元の「正常RST開始 OR 非正規幅指定RSTのガード開始」は、RST AND (幅指定あり OR MADL)にまとめられます。この共通部分だけを登録します。正常／ガードの振り分け条件は従来どおりです。
- フェッチT4のFrame_Readyには登録済みの要求を接続します。CPU_RunへRSTの幅一致／不一致判定を直結する経路を外します。フレーム開始時点は従来と同じT4です。
- CEN停止、WAIT、BUSRQでCPUが進まない間は要求を保持し、共通フレーム完了時に消去します。リセット値は0です。
- RSTの最初のスタック更新に必要な選択条件からFrame_Readyへの依存を除きます。選択結果が使用されるのは従来と同じ受理済み開始時です。
- CALLと共通のframe_push、SP/SPL更新、戻りアドレス、モード復帰フレーム、フレーム中のWAIT処理は維持します。

RTL上で制御用FFを1ビット追加します。GOWINでのLUT/FFの増減、経路遅延の改善量は未測定です。新しい命令パイプラインや新しいメモリ要求段を追加した版ではありません。

## 変更を限定した範囲

公開R18のFPGAファイルと比較し、変更は以下の2ファイルだけです。

1. fpga/G80A_eZ80/t80_ez80.vhd：上記のRST開始要求とスタック選択条件。
2. fpga/tang20k.sdc：前回監査で適用済みの27/54MHz生成クロック定義2行を継承。PLLの108MHz出力からの4分周／2分周を指定。

G80Aラッパー、機能識別値、命令分類関数、マイクロデコーダ、レジスタファイル、メモリブリッジ、SDRAMコントローラ、top、GPRJ、CSTは公開R18と同一です。16bit/24bitアドレスバス分離、拡張アクセス時のMSXバス遮断、VDPとの既存調停はそのままです。新しいfalse path/multicycle指定はありません。

要求ラッチ→SDRAM受付FSMの経路自体は変更していません。前回の−2.922nsやHold違反を直接解消したとするものではなく、比較後も捕捉条件とSTAの確認が必要です。

## ビルド

ZIPを新しいフォルダへ展開し、次のプロジェクトを開いて、GOWINの合成から配置配線まで再実行してください。

`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj`

古いimplやbitstreamはこのZIPには含めていません。前回と同じ合成・配置配線オプションで比較してください。R18.3_BUILD_ID.txtとFPGA_SHA256.jsonでソースを識別できます。

## 実機確認の順序

1. R18.3から新しく生成したbitstreamを書き込み、再起動。
2. 同じEZ80MEM.COMで `EZ80MEM /RUN`。期待表示は `EZ80MEM P1:PASS`。
3. PASSしたら、同じEZ80RW2.COMで `EZ80RW2 /RUN`。版表示は変更せず `EZ80RW2 R18.2: PASS`。各パターンのEXP/IND/ABSの一致も確認。
4. 両方PASSしたら `RUNALL.BAT`。各テストの既存表示で判定。
5. 既存回帰がPASSした後で `EZ80RS8 /RUN`。期待表示は `EZ80RS8 R18: PASS`。
6. SofaRunからスペースマンボウを起動し、プレイを確認。

失敗時は最初の試験名・Stage・ADDR/EXP/ACTを記録し、以降のRST試験は保留してください。EZ80MEMが再度失敗する場合は、再起動してEZ80RW2を単独実行した結果も比較します。

新しいCOMへの交換は不要です。公開R18の全COMはバイト単位で維持し、公開R18.2のEZ80RW2も同じバイト列で同梱しています。従って表示はR18.3には変わりません。変更したのはFPGA側です。

## 検証の読み方

本版の結果は `verification_r18_3/summary.json` と同フォルダのログ／結果JSONに集約しています。古いリリースの結果を本版の証拠として扱わないため、配布ZIPの実行結果ファイルは今回の検証分だけを収録します。doc内の旧版資料は履歴です。

GHDLから生成したシミュレーションモデルに限り、受理されたフェッチT4で、登録済み要求が元R18のRST開始条件と一致するかを検査するassertionを追加しています。この検査はVHDLのFPGA回路へは追加していません。

メモリ試験は実際のCOMバイト列、CPU、メモリブリッジ、SDRAMモデルを使います。EZ80RW2の試験にはBDOSスタブによるEIと実際のIM1受付を含め、DOS呼び出し後に割り込み禁止状態が維持されると仮定していません。MSX-DOS/BIOS全体や実機の配置配線遅延を再現するものではありません。

GHDL/IcarusでのPASSは論理検証です。実機のFF/33誤読は今回の検証でも再現しておらず、実機復旧、タイミング収束、LUT削減を保証する結果ではありません。
