# MSXnano T80 eZ80 restart R15 — TST命令

通常版R14を基準に、eZ80のTST A,r／TST A,n／TST A,(HL)を追加した版です。工程9「残るeZ80追加命令と命令別検証」を進めます。R14.1のマトリックス化は採用していません。

## 実機での確認

GOWINでビルドするプロジェクト：

`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj`

```text
EZ80TST /RUN
```

期待表示：`EZ80TST P2: PASS`

続けて `EZ80MEM /RUN`、`EZ80MIX /RUN`、`EZ80MAD /RUN`、`RUNALL.BAT` を実行してください。RUNALLでNOT READYとなるのは **EZ80LDH、EZ80LDXの2本**です。それ以外はPASSを期待します。SOFARUNからスペースマンボウを起動し、PLAYも確認してください。

**既存20本のCOMとBATはR14と同一です。FLASH内のCOMを更新する必要はありません。** EZ80TSTは先に配布したテストをそのまま使います。COMはZIP直下・プロジェクト直下・hardware_testの3か所に同一内容を収録しています。

EZ80TST.COM：12,968バイト、CRC32=`08ADDC8B`。

テストはDOS／BIOS呼出し後にDIをやり直し、ADL・MBASE・MADLを戻してから結果を表示する既存構成を維持しています。シミュレーションのDOS代替ルーチンもEIするため、システムコールをまたいでDI状態が続く前提を置いていません。メモリアクセス失敗時のアドレス・期待値・実値の表示も維持しています。

## 追加命令と共用

| 形式 | オペコード | 動作 |
| --- | --- | --- |
| TST A,r | ED 04/0C/14/1C/24/2C/3C | B/C/D/E/H/L/AとAをANDしてフラグだけ更新 |
| TST A,n | ED 64 n | 即値8bitとAをANDしてフラグだけ更新 |
| TST A,(HL) | ED 34 | HLが指す1バイトとAをANDしてフラグだけ更新 |

A、ソースレジスタ、HL、メモリは変更しません。S/ZはAND結果、P/Vはパリティ、H=1、N=C=0です。X/Yは既存AND演算器と同じ結果ビットを採用します。メモリ指定はData_Longに従い、短い形式ではMBASE:HL16、長い形式ではHL24を使います。リセット直後・拡張ロック中は従来Z80の動作です。

既存のAND演算器、フラグ生成、入力バス、メモリ読み出し、PC増加を共用しています。デコードでALU_Op=ANDを選択し、Save_ALUでフラグを書き込み、Read_To_Reg/Read_To_Accを0にしてデータの書き戻しを抑えます。専用演算器、ワークレジスタ、FSM状態、制御FFは追加していません。合成後のLUT増減はGOWINでの確認が必要です。

FPGA変更は `t80_mcode_ez80.vhd` と `g80a_ez80.vhd` の2ファイルです。後者は機能マスクのTSTビットを有効にします。診断あり83BF／診断なし03BF、C4=BF、C6=40となります。CPU本体・ALU・レジスタファイル・pack、GPRJ、DualPinと言語設定、CST、SDC、top、ブリッジ、SDRAM、VDPはR14のままです。

TSTIO（ED74）は追加しません。上位I/Oアドレスを00固定するIN0/OUT0/TSTIOや追加ブロックI/Oは未実装の方針です。ED74は従来T80のNEG別名動作を維持し、新しいI/Oアクセスを発生させません。拡張無効時のED64も従来のNEG別名です。

## 検証

- 全体回帰570シナリオ、別枠の異常検出24シナリオ。
- TST専用15シナリオ（ADL／拡張有効Z80／拡張ロック中）と2つの異常注入。全256種類のA、全7レジスタ指定、即値、メモリ、全4種類の幅プレフィクス、非ゼロMBASE、境界付近のアドレス、WAIT／CEN停止を確認。
- 全256×256のAとオペランドの全組合せを走査したものではありません。全A値に対して異なるオペランドを与え、既存AND演算器を共用する構成を検証しています。
- TST後のA・ソース・フラグを確認し、メモリ形式では短長で異なるデータを配置して上位バンク選択も確認。
- ED74のNEG別名、拡張ロック中のED04/ED64、MSX16と拡張24の分離も確認。
- 実COMをCPU＋ブリッジ＋SDRAMで実行。診断ありは通常・故障注入・未要求・拡張無効・WAIT／CEN停止、診断なしでも実COMがPASSすることを確認。
- R14とのデコード差分は、意図したTSTの2,304入力プロファイルを除く8,386,304組合せで全49出力を比較。TSTの新動作は上記の専用試験で検証。
- 既存MEM／ALU／BLK／MUL／LEA／FETCH／制御／割り込み／MBASE／MADL／混在CALL・RETなどを回帰。

`python tools/verify_r15.py` が全体再実行の入口です。GHDL、Icarus Verilog、patchを使用します。実行環境に合わせてGHDL／IVERILOG／IVL_ROOT／VVPを指定してください。個別結果はverification_groups、実行ログはverification_logsに収録しています。

R15のGOWIN合成・配置配線・実機動作・タイミング達成は未確認です。ボード全体や完全なMSX-DOS／BIOSをシミュレーションしたものではありません。

## R14.1比較の結論とタイミング課題

| 項目 | 通常版R14（採用） | R14.1マトリックス版（不採用） |
| --- | --- | --- |
| LUT | 16,647 | 16,836（+189） |
| Logic | 18,878 | 19,067 |
| CLS | 10,047 | 10,061 |
| 54MHz系Fmax | 33.854MHz | 34.718MHz |
| 最悪Setup Slack | −5.510ns | −5.142ns |
| 最悪Hold Slack | −2.678ns | −2.974ns |

両版ともLogic表示は92%でした。LUTが増えたら戻す方針に従い、R15は通常版R14から作成しています。マトリックスのソースは含めず、通常版のWriteデコードを維持します。

通常版R14でもCPUからラッパの要求アドレス捕捉までの経路とSDRAM書き込み側のHold課題が残っています。今回のTST追加はそれらの修正ではありません。CPUのクロックイネーブル間引きだけで違反を無効とせず、捕捉タイミングと保持期間を証明できる経路だけを個別に扱う方針を維持します。制約の一律緩和は行いません。

## 残る工程
