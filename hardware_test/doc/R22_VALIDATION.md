# R22 検証結果

GHDLで現在の6個のCPU VHDLソースを変換し、Icarus Verilogで実RTLを実行。合成出力のVerilog識別子補正のみ行い、CPUの動作モデルへの置換はしていない。

| 検証 | 範囲 | 結果 |
| --- | --- | --- |
| 新規反復I/O | 8命令×2開始モード×5幅条件、通常/WAIT・CE停止/IRQ/NMI、ロック中無操作、BC境界 | 648ケースPASS |
| EZ80IOR実COM | 32ケースの通常実行、32ケースのCE停止実行、故障検出、拡張無効、/RUNなし、旧機能識別、診断なし | 7プロファイル、期待結果一致 |
| 既存IO2 | 通常/WAIT・CE停止/IRQ/NMI、ロック中 | 244ケースPASS |
| EZ80IO2実COM | 既存16ケースを新RTLで実行 | PASS |
| EZ80MEM実COM | 通常4位相、故障注入4条件、拡張無効 | 9プロファイル、期待結果一致 |
| EZ80D3/EZ80CTL実COM | 実ラッパ/ブリッジ/SDRAM制御とSDRAMモデル、異なるCE位相・停止 | 2プロファイルPASS |
| 幅＋DD/FD CB d | 全suffix、割込み挿入位置、WAIT・CE停止、感度確認用故障 | 1952ケースPASS、注入故障1件を検出 |
| IM0 | 全256 IACK値×3コンテキスト×通常/WAIT・CE停止 | 1536ケースPASS |
| EZ80MR4実COM | R21.3の記録選択リンク・メモリ観測を新RTLで確認 | 通常1プロファイルPASS |
| VHDL-93 | CPU関係6ファイルの解析 | PASS |

故障注入プロファイルは意図したFAIL/ADDR/EXP/ACT表示を検出する試験。機能未提供のプロファイルではUNSUPPORTED/NOT READY、/RUNなしではREADYを期待する。
個別ログと集計JSONは `verification_r22` に同梱。

## 試験の限界

- GOWINの合成・配置配線・実機確認は未実施。面積とSetup/Holdの改善を主張しない。
- 新規COMは内部診断I/Oで転送処理を検査する。外部I/O機器の電気的な動作確認ではない。
- BC初期0から最大回数を最後まで回す試験は行っていない。1反復後のIRQ内で、幅に応じたラップと非0を比較する。
- 実COM試験のDOS呼出しは意図的にEIするスタブ。MSX-DOS全体のモデルやゲームのシミュレーションではない。
- 対象命令の全データ・全形式・全クロック条件の証明ではない。制御命令suffix監査と独立ISA検証は継続。
