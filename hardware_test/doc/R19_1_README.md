# R19.1 — 幅プレフィクスと DD/FD CB の処理修正

R19の実機確認済みソースを基準に、幅指定＋インデックスCB命令の不具合を修正しました。新機能SLPの実装は今回に含めず、プレフィクス処理と割り込み境界を先に検証しています。R19.1のGOWIN合成・配置配線・実機動作・Logic使用率は未確認です。

## 基準の実機結果

R19はユーザー確認済みです。EZ80IM0 R19:PASS、EZ80MEM P1:PASS、EZ80RW2 R18.2:PASS、EZ80RS8 R18:PASS、RUNALL.BAT全項目PASS。SofaRunからスペースマンボウを起動してPLAYできています。

## 原因と修正

通常の命令はM1で幅プレフィクスを取り込みますが、DD/FD CB d op の最終オペコードはM7で読みます。R19ではその形式で幅指定を取り込む処理が抜けていました。そのため、インデックスアドレスの計算時に長さ指定が反映されず、保留中の幅指定が次の命令へ残りました。保留を残すことは割り込みの受付境界にも影響します。

R19.1ではDD/FD後のCBを受け取るM1/T2の成立時に幅指定を取り込みます。これによりM6のアドレス計算前に幅が確定します。WAIT中には取り込まず、既存の割り込み抑止条件を共用します。CPUの状態保持FF、ワークレジスタ、FSM状態はRTL上追加していません。GOWINでのLUT増減は未測定です。

FPGAソースの変更は `fpga/G80A_eZ80/t80_ez80.vhd` と `g80a_ez80.vhd` の2ファイルです。後者はテスト用識別値 CC=01/CD=FE の追加のみです。R19のCA=01/CB=FEは維持し、EZ80IM0.COMを含む既存COM 27本は変更しません。

GPRJ・DualPin・SystemVerilog設定・SDC・CST・マイクロデコーダ・SDRAM・メモリブリッジ・VDP・topはR19と同じです。16bit MSXバスと24bit拡張バスの分離、拡張アクセスをFFFFセカンダリスロット判定から遮断する処理を維持します。マルチサイクルやfalse pathの追加はありません。

## 新しい実機用テスト

`hardware_test/EZ80PFX.COM` とプロジェクト直下の同名ファイルを収録します。

```text
EZ80PFX /RUN
```

期待表示は `EZ80PFX R19.1: PASS` です。42667バイト、CRC32 `ABC368EA`。

32ケースで、Z80/ADLの命令ストリーム、IX/IY、.SIS/.LIS/.SIL/.LIL、IRQなし/ありを組み合わせます。SET/RESの対象・別幅の別名アドレス・次の幅指定なしLD DE・スタックの復元を確認します。IRQありではEI直後から幅指定＋DD/FD＋CBを実行し、1命令の完了後に受け付けたフレームの戻りPC、タグ、全バイトとSPLを照合します。最初の不一致はStage・ADDR・EXP・ACTを表示します。

実機テストは既存の診断IRQを使い、MSX/DOSベクタを書き換えません。私有領域は、コード/結果が0A:6000/7000/8000/8100/9000および0E:8200、ベクタが0F:0038、スタックが05:0001近傍です。データは03:0000、03:FFFF、0E:0000、0E:FFFFを使います。MegaRAM/VRAM予約枠は触りません。試験用データは上書きされます。

私有試験中にはDOS/BIOSコールを行いません。既存D8診断窓が外部IRQを遮断し、試験内で意図したIRQを受け付けます。終了時はDI、Z80/MBASE=0、MADL=0、元のDOSスタック、IM1、診断停止・拡張ロックへ戻します。表示のDOSコール内でEIされることを考慮し、コール後にもDIしてIX/IYを戻し、最後にEIして終了します。

/RUNなしはREADYのみです。R19以前はCC/CD識別がないためNOT READYとして私有領域へ進みません。拡張無効時はUNSUPPORTED、診断なしはNOT READYです。今回の実機COMはNMIを直接試験しません。NMIのプレフィクス境界はCPU単体シミュレーションで確認しています。

## ビルドと実機での確認順

ZIPを新しいフォルダへ展開し、`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj` をビルドしてください。古いimpl/bitstreamは含めません。

1. Logic、LUT/ALU/FF、CLS、Setup/Holdの結果を記録。
2. `EZ80MEM /RUN`、`EZ80RW2 /RUN`。
3. `EZ80PFX /RUN`、`EZ80IM0 /RUN`、`EZ80RS8 /RUN`。
4. `RUNALL.BAT`。このBATは既存のままで、新しいPFX試験は別途実行します。
5. SofaRunからスペースマンボウを起動してPLAY。

失敗時は表示全体を記録し、再起動後の単独実行と比較してください。テストだけZIPには既存27本＋新規1本とBATをまとめています。

## ローカル検証

結果・ログは `verification_r19_1/summary.json` に集約します。

- インデックスCBの文書化されたメモリ形式31種×4幅×IX/IY×Z80/ADL×通常/WAIT・CEN停止＝992ケース。
- IRQ/NMI×注入箇所5点×通常/ストレス×代表3命令×16幅/モード/インデックス＝960ケース。幅指定、DD/FD、CB、変位、最終オペコードの各受信後に要求を注入し、戻りPC、全フレーム書き込み、復帰、次命令の幅を検査。
- 故障を注入したデータ不一致の検出を確認。
- 修正前のR19でも同じ試験を実行し、短幅の次命令への幅漏れと、長幅の対象アドレス誤りの2件を再現。
- 実際のEZ80PFX.COMをCPU＋ブリッジ＋SDRAMモデルで実行。通常、CEN/WAITストレス、故障検出、READY、UNSUPPORTED、旧識別値、診断無効を検査。DOSスタブ内部でEIし、DOS側IM1の受付と復帰も確認。
- 既存IM0、RST、混在CALL/RET、IRQ、メモリ、ロック時互換性の回帰とVHDL-93構文解析。

再実行用の入口は `tools/verify_release_r19_1.py` です。GHDL・IVERILOG・IVL_ROOT・VVPを使用環境に合わせて指定します。旧版R19での不具合再現結果もログとして収録します。

これは機能シミュレーションです。全MSX-DOS/BIOS、物理周辺機器、全eZ80命令の網羅、GOWINでの配置配線やタイミング収束を証明する結果ではありません。プレフィクスの順序は公式の幅指定→DD/FD→CBです。文書化されていないCBレジスタコピー/SLLは今回の検証対象に含めません。

R18.3時点のSTAは54MHzに対してFmax32.095MHz、Setup違反790、Hold違反42でした。R19の実機PASSでこのSTAが解消したとは判断しません。R19.1でも一律の制約緩和は行わず、最新GOWIN詳細レポートで別途評価します。

## 次の残項目
