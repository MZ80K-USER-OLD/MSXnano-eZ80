# R21.1 実機診断とimpl比較

## 実機画像から読み取れた結果

LOCAL EXP=31 ACT=31。各行のA1/A2/I1/I2はすべて同じ値で、HL表示は試験アドレスと一致。

| 論理アドレス | A方式・期待31の実測 | I方式・期待CEの実測 | HL |
| --- | --- | --- | --- |
| 010100 | 20 | 56 | 一致 |
| 070100 | A8 | DE | 一致 |
| 07FFFE | 28 | 1E | 一致 |
| 080000 | 70 | 86 | 一致 |
| 0A6000 | F0 | 26 | 一致 |

画像の07FFFEは28/1Eであり、先行するEZ80MEM単独試験のACT20とは異なる。別プログラム・別実行の値として記録し、20に統一しない。
画像の最終表示はEZ80MR2 R21D: FAIL (see rows)。

単純な1回目だけの読出し異常ではない。両方の書込み指定と両方の読出し指定に共通する経路が候補。
ただし絶対指定とHL指定はラッパ以降の共通回路を使うため、これだけでSDRAMへの書込み不成立と断定できない。
LOCAL一致も、全Z80命令/全DOS経路/全レジスタの正常を証明しない。

## R21.2で追加する観測点

ブリッジの受理時に、最後の拡張書込みの物理アドレス23bit＋データ8bitを31bitのFFに記録。
読出しは既存のram_addr/resultを参照し、追加FFなし。
既存診断セレクタのF0〜F7を使い、専用I/Oポートを増やさない。

| セレクタ | 読出し値 |
| --- | --- |
| F0 | 最後にブリッジが受け付けた書込みデータ |
| F1/F2/F3 | その物理アドレスの下位/中位/上位（最上位bitは0） |
| F4 | ブリッジが最後の読出し完了時に保持したデータ |
| F5/F6/F7 | 最後の要求の物理アドレスの下位/中位/上位（MR3では最後の読出し先） |
| FB/FC | 調査版識別02/FD |

注意: 読出し側アドレスは既存要求ラッチを再利用し、次の拡張要求で更新される。MR3は読出し完了後、次の拡張要求を出す前に診断値を読む。
記録は一般的なイベント履歴FIFOではなく、専用COMの順序を前提とした最終値。
W記録は書込み要求を受け付けた証拠であり、SDRAMセルへの書込み完了の証拠ではない。
R記録はブリッジが受け取ったSDRAM制御回路の返答。物理DQピンの独立測定ではない。

## 切り分けの解釈

- W物理アドレスが違う: CPUアドレス生成、ラッパ要求保持、ブリッジ変換を対象。
- Wデータが既に違う: CPU出力データからブリッジ受理までを対象。
- Wが期待値、Rが違う: ブリッジより後の要求受け渡し、SDRAM書込み/読出し、返答を対象。
- Rが期待値、A1/A2/I1/I2が違う: ブリッジ出力からtopのcpu_din、ラッパDI_Reg、CPU取込を対象。
- RとWが正しくなりMR3がPASSしても、追加回路による配置変化の可能性がある。原因確定・STA合格と同義ではない。

R21.2は調査版。修復済み版として扱わない。
