# MSXnano T80 eZ80 再構築 R11.1：タイミング経路の改善

R11の機能範囲を維持し、要求アドレス・書込みデータ・種別の保持と、命令境界での条件判定、クロック定義を修正した版です。
**R11.1のGOWIN合成・配置配線・実機は未確認です。タイミング達成や資源削減を保証する結果ではありません。**

基準のR11は、ユーザー実機でEZ80IRQ／EZ80IM2／EZ80NMIのP2: PASSと、SofaRunからスペースマンボウのプレイを確認済みです。
GOWINの正確な値はLogic 17,944/20,736（87%）、CLS 9,790/10,368（95%）、BSRAM 44/46（96%）。元のタイミングレポートには違反があります。

## ビルド

ZIPを短いパスの新しいフォルダに完全展開してから、次のプロジェクトを全ビルドしてください。

`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj`

GPRJとCST、Dual Purpose Pin設定は従来どおりです。SystemVerilog 2017を確認してください。
**SDCはこの版のものへ更新が必要です。** クロックを入力27 MHz→PLL108 MHz→CLKDIV27/54 MHzとして定義し直しています。
音声は44.1 kHz分数分周の最短間隔でモデル化しました。VideoDHClk／VideoDLClkはメモリ制御に入力されるデータ位相信号として、実際の送出FFのクロックで解析します。
新しいfalse path／multicycle指定や、既存max_delayの緩和はありません。

## 実機確認

**先行配布P2のCOM20本をそのまま使用できます。FLASHへの追加・更新はありません。** ZIP直下、プロジェクト直下、hardware_testに同じCOMを収録しています。

`RUNALL.BAT`で一括実行できます。各結果を確認してください。BAT自体は総合PASSを判定しません。

| テスト | R11.1の期待結果 |
|---|---|
| EZ80D3 | R3: PASS（引数不要） |
| EZ80MEM／ALU／BLK／MUL／LEA／ADL /RUN | P1: PASS |
| EZ80F9 /RUN | R9: PASS |
| EZ80CTL /RUN | R10: PASS |
| EZ80IRQ／IM2／NMI／I16／RST /RUN | P2: PASS |
| EZ80MAD／MIX／MB／TST／LDH／LDX /RUN | 未実装のためNOT READY |

その後SofaRunからスペースマンボウを起動してプレイしてください。
メモリ不一致は既存テストと同じADDR／EXP／ACT形式です。MSX-DOS／BIOSがEIする可能性を考慮した試験手順も維持しています。

## 変更と検証

- CPU出力ポートの内部読返しを、内部アドレス・バンク・データ・書込み信号へ置換。
- ラッパでT1の立下りに要求を保持。書込みデータはT1/T2で捕捉し、実行中・WAIT中に保持。I/OとIACKはバンク0、リフレッシュもバンク0。
- この契約を満たす接続だけで、ブリッジのバンク判定から生のIORQ経路を除去。汎用接続の既定動作は維持。
- フェッチT2で前命令のフラグと分岐条件を捕捉し、レジスタ読出し→フラグ→条件分岐→上位レジスタ制御の経路を分割。
- リセット中の設定保持を27 MHzのFFへ変更し、クロック開始前にも従来の起動設定となる初期値を指定。分数音声分周器の初期値とpow引数も整理。

検証入口：`bash tools/run_checks.sh`（GHDLとIcarus Verilogが必要）。結果：`verification_result.json`。
検証内容・実際の捕捉時点・残課題は `doc/TIMING_R11_1.md` を参照してください。
元のG80A、SDRAM制御器、VDP優先仲裁、メモリ割当、実機COMは変更していません。

## GOWIN再測定で確認する項目

LogicだけでなくCLS、BSRAM、セットアップ／ホールド違反、未定義クロック、適用制約のオブジェクト一致を確認してください。
**PR1014（入力クロックの一般配線）は今回のRTLシミュレーションで解消確認できません。** CSTを推測で変更せず、再配置配線の結果で判断します。
旧SDC由来の既存例外も、今回すべての妥当性を証明したわけではありません。

工程7の通常ADL割込みはR11で実機合格、R11.1は工程10のタイミング改善を先行しています。
ADL IM0、MBASE／MADL、混在CALL／RET／割込みフレームは引き続き未実装です。上位00h固定の追加I/O命令は除外方針を維持します。
