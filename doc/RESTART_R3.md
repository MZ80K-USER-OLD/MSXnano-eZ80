# 再構築R3：交換、SP転送、複数バイトの絶対メモリアクセス

## 基準と到達点

R2を基準とする。R2のGOWINビルド、EZ80D2 PASS、試験後のSofaRunとスペースマンボウの
起動・プレイはユーザーによる実機確認済みとして記録する。R3の実機確認はまだ行っていない。
この段階でもPC=16bit、SPS=16bit。独立SPLとデータレジスタの24bit化を先に検証する。

変更するFPGAソースは `G80A_eZ80/t80_ez80.vhd` と `t80_mcode_ez80.vhd` のみ。
元T80、ラッパー、ALU、レジスタ下位16bit、トップ、ブリッジ、SDRAMコントローラ、
GOWINプロジェクト設定・CST・SDCはR2と同一。制約緩和や新たなfalse_pathは追加しない。

## 追加した範囲

| 命令／機能 | R3での扱い |
|---|---|
| EX.LIL DE,HL | 上位8bitも含めて交換。通常の短いEXは元T80の下位16bit交換 |
| EXX | 同一のAlternate選択で上位配列と下位レジスタを切替。主／裏の24bit値を独立に保存 |
| LD.LIL SP,HL/IX/IY | 上位を含む24bit値をSPLへ。通常のLD SPはSPSへ |
| LD.LIL (nnn),rr | BC/DE/HL/IX/IY/SPLの3バイトを24bitの絶対アドレスへ格納 |
| LD.LIL rr,(nnn) | 24bit絶対アドレスから3バイトを読んでレジスタへ |
| LD.LIS (nn),rr / rr,(nn) | 2バイトの即値アドレスを消費し、3バイトのデータを転送 |
| LD.SIL (nnn),rr / rr,(nnn) | 3バイトの即値アドレスを消費。データは2バイト、短いデータ空間のバンク00 |
| LD.SIS と無指定 | 元T80の2バイトデータ・2バイトアドレス経路 |

rrのうちSPはデータ幅が長ければSPL、短ければSPSを使う。
MBASE未実装のため短いデータ空間はバンク00固定。プレフィクスはDD/FD/EDの前へ置く。
SIS/LIS/SIL/LILの即値長とデータ幅は別々に決定する。
LISで最初の実効アドレスは00:nnnn。長いデータの連続アドレス更新は24bitで行う。
短いデータは16bitでラップする。絶対メモリ命令でもPCの即値取得自体は16bitのまま。
レジスタの短いロード後に未規定の上位値へ依存してはならない。

まだ対象外：ADLフェッチ、ADL割込み、24bit CALL/RET、EX(SP),HL/IX/IYの24bit化、
24bit ADD/ADC/SBC、ブロック転送、MBASE/MADL、バイト絶対ロードの24bit化、追加eZ80命令群。
一般的な全レジスタ間24bit転送が完成したという意味ではない。
未対応のプレフィクス付き命令を検出するトラップも未実装。

## 内部サイクルと境界

即値アドレスは2または3バイト、転送データは2または3バイトなので最大7マシンサイクルとなる。
元T80のサイクル6/7はインデックス変位処理にも使われる。
新しい絶対転送中は、インデックス変位用の一時アドレス計算・戻り先選択を起動しないよう分離した。
この分離が不足していると、前に実行したインデックス命令の履歴によってサイクル7の戻り先が変わり、
命令列の続きをデータとして消費する不具合になる。R2の全試験を先行実行する条件で検出した。
新しい転送中は転送完了で通常の命令フェッチへ戻す。既存のインデックス命令は元の経路を維持する。

実効アドレスの上位／下位は同じT_Resで登録し、連続転送の加算では必要に応じて上位へキャリーする。
各バイトは従来の要求ラッチ・VDP優先・WAITを使い、保持済みアドレスとデータをSDRAMへ渡す。
CPUの高位アドレスを既存MSXの16bitデコーダへ直接接続しない。
高位バンクではMSX側アドレス0000h、MREQ非アクティブとするR1/R2の分離を維持する。

## EZ80D3.COM

生成元は `hardware_test/build_data_r3.py`。実行したCOMそのものと、hex、DEFBリスト、ラベルJSONを同梱。
前のビットストリームではR3の試験にならないため、必ずR3と組にする。

| stage | 試験 |
|---|---|
| 1..8 | R2と同じバンク、間接、プレフィクス、SP、INC/DEC、PUSH/POP、通常スタックの回帰 |
| 9 | 24bit DE/HL交換、主／裏3組の独立性、HL/IX/IYからSPLへの転送 |
| A | 6種類のペアでLIL/LISの複数バイト格納と読出し。07FFFEh→080000hの64KiB境界 |
| B | 独立した1バイト書込みから各ペアへの3バイト読出し。09FFFEh→0A0000hの境界 |
| C | SILの3バイト即値消費と短いデータ空間、SPS保存、通常CALL/RETでDOSへ復帰 |

ペア格納は、転送後のメモリを個別のHLバイトアクセスで比較する。
ペア読出しは、読み込んだレジスタをPUSHし、別のHLバイトアクセスでメモリを比較する。
SP読出しはSPLスナップショットの3バイトを比較する。
格納と読出しの誤りが相殺されるのを避けるため、stage Bは1バイト書込みで別途初期化する。
EXX試験では主と裏に異なる24bit値をロードして、各3組の全9バイトを確認する。

### 不一致表示

最初の不一致の取得値を保存し、期待値と意図した論理アドレスを対応付ける。

```
EZ80D3 R3: FAIL stage A
ADDR=07FFFE EXP=56 ACT=57
```

読出し後のペア上位値が不正だった場合、例えば次のように格納先スナップショットを指す。

```
EZ80D3 R3: FAIL stage B
ADDR=060102 EXP=A7 ACT=A6
```

これらは故障注入シミュレーションの例であり実機観測値ではない。
ADDRは比較対象の論理アドレスで、実際のSDRAM端子観測ではない。
ACTを後の再読出し値で置き換えない。正常時の出力はPASSだけ。

### 破壊するRAM

R2に加え、060100h..060108hをペア退避へ使用する。
07FFFEh、07FFFFh、080000hには3バイト格納試験で書き込む。
09FFFEh、09FFFFh、0A0000hには独立したバイト書込みで読出し試験の値を配置する。
R2から継続する領域は、018000h..1B8000hの各バンク1バイト、020100h..020103h、
030000h、02FFFFh、01FFFFh、04FFFEh..050000h。
COM自身の低位バッファと通常SPSも使う。VRAM/MegaRAMはこの実機COMでは書き換えない。
専用RAMの物理アドレスは論理+640000h。例：07FFFEh→6BFFFEh。
試験領域の既存内容を保存・復旧するプログラムではない。

### DOS/BIOSとEI

DI中はDOS/BIOSを呼ばない。成功・失敗・未対応の全出口で拡張をロックする。
診断の16進変換は通常Z80のCALL/PUSH/POPとSPSで行い、EI後にBDOS9で表示する。
表示後は拡張テストを再開しない。BDOS9モデル自身もEIし、DIが保たれるとの仮定を置かない。
拡張解除中にIFF1が有効ならテストベンチが失敗する。NMIとADL割込みは対象外。
通常のMSX-DOSコマンド入口のZ80状態・割込み許可を前提とする。

## 検証と限界

現行結果は `verification_result.json`。
元T80とのロック状態比較16ケース、実COM実行10ケースを行う。
実COMは正常4位相、バンクの誤共有、既存のデータ破損、スタック書込み破損、
新規ペア格納破損、新規ペア読出し破損、拡張無効の組合せ。
故障注入ではstageとADDR/EXP/ACTの文字列まで照合する。

GHDLで変換したCPU、実際のCOMバイト列、ブリッジ、SDRAMコントローラとモデルを使用する。
低位メモリとBDOS9は簡易モデルで、実MSX-DOS全体・BIOS起動完了の検証ではない。
部分Verilog構文確認は周辺VHDL・ベンダプリミティブをブラックボックスにしている。
GOWIN合成・配置配線・タイミング・HDMI表示・実機動作は未確認。
R2と同じメモリRTLの独立メモリ26ケースは再実行せず、今回の実COM経路で回帰する。

## 再生成

```
python3 tools/rebuild_from_t80.py
python3 tools/extend_r2.py
python3 tools/extend_r3.py
python3 hardware_test/build_data_r3.py
```

GHDL・Icarus Verilog・vvpの環境で `tools/run_checks.sh` を実行する。
実機のEZ80D3 PASSと試験後の通常MSX動作を確認してから次段階へ進む。
