# R21.2 メモリ要求・返答の観測用調査版

R21.1実機: EZ80MEM最初の読み戻しFAIL。EZ80MR2はLOCALとHL一致、拡張RAMは全試験行FAIL。
**不具合原因は未確定。本版は修復ではなく、観測点を追加する調査版。GOWIN/実機未確認。**

## ビルドと実行

1. 本ZIPを別フォルダに展開。
2. fpga/project_eZ80/MSXNanoTang20K_eZ80.gprjで再合成・配置配線し、実機へ書き込む。
3. 新しいhardware_test/EZ80MR3.COM（ルートにも同じファイル）をDOSドライブへコピー。
4. 電源再投入後、`EZ80MR3 /RUN`を単独実行。
5. LOCAL行と、各アドレスのA/I行、I1/I2/HL行、W/R行、最後のPASS/FAILを報告。画面写真でよい。
6. Logic使用率とR21.2のimpl ZIPも保存。

MR3はR21/R21.1ではNOT READYとなる。新しいR21.2 bitstreamが必要。
以前のEZ80MEM、EZ80IO2、RUNALL等の30 COMは変更なし。MR3はRUNALLに追加していない。
不一致があっても全6試験行を表示して最後にFAIL。フリーズ時は最後の表示を記録し、再起動。

## 表示例

```
A 07FFFE E31 A1=31 A2=31
I1=31 I2=31 HL=07FFFE
W=6BFFFE/31 R=6BFFFE/31
```

- 行頭A: 絶対指定で31Hを書込む。行頭I: HL間接指定でCEHを書込む。
- A1/A2: 絶対指定での連続2回の読出し実測値。
- I1/I2: HL間接指定での連続2回の読出し実測値。
- HL: 読出し後のHLをCOM内RAMへ保存した値。
- W: ブリッジが受け付けた書込みの **物理アドレス/データ**。
- R: 最後の読出しの **物理アドレス/ブリッジ返答データ**。
- E31/ECE: CPUが期待する値。

試験先は010100、070100、07FFFE（論理）。対応する物理アドレスは650100、6B0100、6BFFFE。
6行×3表示行＋START/LOCAL/最終結果で、40桁・24行画面に収まる構成。
新IO2命令、ADLコードフェッチ、FFFFH境界試験は使わない。
DOS/BIOSがEIすることを前提に、DOS呼出し前は拡張をロックしZ80/MBASE0、呼出し後すぐDI。SPSとIX/IYを復帰。

例: `W=6BFFFE/31 R=6BFFFE/20` なら、書込み受理時は31、メモリ制御から戻った値は20。
WはSDRAM書込み完了の独立測定ではない。詳しい判定と限界はdoc/R21_1_HARDWARE_ANALYSIS.md。

## FPGA変更

- ブリッジ: 観測用の31bit書込み記録。読出し記録は既存ラッチを共用。
- ラッパ: 既存E7E7H診断インターフェースで記録を読むF0〜F7と識別FB/FCを追加。
- top: 上記記録の接続。
- CPU本体、マイクロコード、ALU、レジスタ、パッケージはR21.1と同一。
- メモリブリッジの状態遷移、要求/WAIT/完了処理は同一。SDRAM制御、MSX16/拡張24分離、SDC、GPRJも同一。
- LUT/FFの実合成増分は未測定。調査用記録は解決後に削除する対象。
- SLPは非対応NOP、TRAPは非対応のまま。

## 検証

- 実MR3 COM: 通常、CPU許可停止、人工的な20H故障注入、拡張無効、/RUNなしの5プロファイル。
- 旧版の識別値を模擬: NOT READY、拡張RAMに触れないことを確認。
- 既存EZ80MEM: 9プロファイル。既存EZ80IO2: 7プロファイル。
- 計22プロファイルで期待結果。故障注入/READY/NOT READY/UNSUPPORTEDを含む。
- VHDL-93で6ファイル解析。
- topと変換CPU/ブリッジの接続をIcarusで確認。GHDL変換時にgenericを固定したCPUモデルを使い、未提供モジュールは省略しており、全FPGA合成の代替ではない。
- CPU命令実装は同一なので、R21.1の312条件およびマイクロコード比較は履歴として残す。本版で183万比較や312条件を新たに全再実行したとの主張はしない。

人工故障注入での20Hは診断表示の検証であり、実機不具合の再現ではない。
GOWIN/配置配線/電気条件と実機動作は未確認。

EZ80MR3.COM: 3967バイト、CRC32 9E4C6E36。
旧版ドキュメントは履歴。本版の状況はこのREADMEとverification_r21_2/summary.jsonを参照。
