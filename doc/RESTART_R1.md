# 再構築R1の実装範囲と検証

## 基準

V33配布物内の `fpga/G80A` にある元T80の6ファイルを出発点にした。
元のファイルは変更しない。`tools/rebuild_from_t80.py` が別名の6ファイルを生成する。
`doc/provenance.json` は出発点のハッシュ。V34系のCPUデータパス／ADL状態機械は移植しない。
MSX周辺回路・GOWIN設定はV33を基準とし、拡張メモリブリッジのMREQ先行WAIT修正を引き継ぐ。

## この段階で実装したもの

| 項目 | R1の動作 |
|---|---|
| PC | 常に16bit。フェッチはバンク00 |
| SPS | 元T80の16bit SP。CALL/RET/PUSH/POP/割込みは引き続きこれを使う |
| SPL | 独立した24bit SP。今回の試験では即値ロードと読出しだけ |
| BC/DE/HL/IX/IY | 既存の下位16bitに上位8bitを追加。上位配列は代替レジスタの位置も確保 |
| リセット | 拡張ロック、上位バンク00。ADLモードそのものを追加していない |
| メモリ | バンク00は既存MSX、01..1Bは専用RAM。高位アクセスはMSX MREQと16bitアドレスを遮断 |
| バス | 外部データ8bit。CPU要求のWAITで完了を待つ |

### 明示プレフィクス

公式eZ80 CPU User Manual UM0077のデータブロックと即値長の区別に従う。
出典: https://www.zilog.com/docs/UM0077.pdf (Single-Instruction Memory Mode Changes)

| バイト | サフィックス | データレジスタ／間接アドレス | 即値長 |
|---|---|---|---|
| 40 | .SIS | 16bit、バンク00 | 2バイト |
| 49 | .LIS | 24bit | 2バイト |
| 52 | .SIL | 16bit、バンク00 | 3バイト |
| 5B | .LIL | 24bit | 3バイト |

即値長が3でも、PC自体は16bitのまま。今回MBASEは実装せず短いアクセスはバンク00固定。
短い書込みで規定されないレジスタ上位値は、R1での決定値または保持値であり、ソフトが依存してはならない。
`.LIS LD rr,nn` は上位00を設定し、`.SIL LD rr,nnn` は第3即値を消費して下位16bitを使う。

対応する拡張命令の範囲:

- `LD rr,即値` (BC/DE/HL/IX/IY/SP)、明示プレフィクス。
- `LD A,(BC/DE)` と逆方向。
- 既存の `LD r,(HL)` / `LD (HL),r` / `LD (HL),n` の間接データアドレス。
- 既存のLD系IX/IY+d間接データアドレス。加算のキャリー／ボローを上位8bitへ反映。
- SPLの読出し専用として `LD.LIS (nn),SP` (`49 ED 73 lo hi`) の3バイト格納。

プレフィクスはDD/FD/EDの前へ置く。その他のプレフィクス付き命令はR1の契約範囲外であり、
対応済みとみなして実行してはいけない。未対応命令を検出するトラップはない。
ADLフェッチ、24bit演算、24bit PUSH/POP、CALL/RET、割込み、RETI/RETN、MBASE、MADL、
eZ80新規命令群、プレフィクス付きの一般的な絶対アドレスロード／ストアは今後の工程。
EX DE,HLなどによる上位レジスタ交換も未検証・未対応。全eZ80互換コアではない。

### 実行時の解除

全16bit I/OアドレスE7E7hへOUT(C),AでA5h、5Ahを順に書いて解除、00hでロック。
別のI/O書込みは解除キーの連続性を破棄する。INでE0h=ロック、E1h=解除。
これはこのFPGA試験用の制御で、Zilog仕様のレジスタではない。全MSX周辺機器で未使用との保証はない。
標準GOWINプロジェクトの `EZ80_EXTENDED=1` は回路を存在させる設定。リセット時ロックとは別。
今回は拡張を有効にした回路の配置配線結果で評価する。

## EZ80D1.COM

実体のバイト列は `hardware_test/build_data_r1.py` で生成する。外部アセンブラは不要。
COM、hex、解決済みDEFBリスト、ラベルJSONを同梱する。

| stage | 試験 |
|---|---|
| 1 | 27バンクへ別々の値を書き、逆順に読んでバンクの誤共有を検出 |
| 2 | BC/DE/IX/IY経由の読み書き |
| 3 | IXの正方向キャリー、IYの負方向ボロー、01FFFFhへのアクセスとMSX遮断 |
| 4 | .SIS/.LIS/.SIL/.LILの即値長とデータ幅、プレフィクスの命令間漏れ |
| 5 | SPL=05FEDChと003456hの3バイト読出し、通常SPSの前後比較、Z80 CALL/RET |

期待出力は `EZ80D1 R1: PASS`。`FAIL stage N`は該当段階の不一致。
`UNSUPPORTED`は解除状態を確認できなかった場合。このR1と組にして使う。

破壊する専用RAMの論理アドレス:

- 018000h、028000h、…、1B8000h（各1バイト）。
- 020100h..020103h、030000h、02FFFFh、01FFFFh（各1バイト）。

専用RAMの物理アドレスは論理+640000h。例えば018000h→658000h、030000h→670000h。
COM自身の低位ワーク領域と通常スタックも使用する。VRAM/MegaRAMはこの実機テストでは書き換えない。
SPLを設定しても、そのアドレスへスタック書込みは行わない。SPSによる通常CALL/RETは別経路。
テストはIX/IYを保存復帰する。通常のMSX-DOSコマンド呼出し（Z80状態・割込み許可）を前提とする。

### DOS／BIOS呼出しがEIする場合

入口のIX/IY保存後にDI。解除・全テスト・拡張ロックまでDOS/BIOS呼出しはゼロ。
成功／失敗／未対応の全出口を共通FINISHへ集約し、ロック後にEIとBDOS9の結果表示を行う。
結果表示後は拡張アクセスを再開しない。システムコールがEIしても試験区間へ漏れない。
検証用BDOS9ルーチン自身にもEIとNOPを入れた。
CPUが拡張解除中に割込み許可になるとシミュレーションを失敗させる。
DIによりINTを禁止する試験であり、ADL割込みを通した試験ではない。NMIは対象外。

## 要求の捕捉と保持

| 経路 | 捕捉タイミング | 保持期間／使用点 |
|---|---|---|
| 拡張CPU→bridge | 54MHz側、IDLEで高位MREQとRD/WR有効、前ACK低 | physical addr/data/writeを登録しREQを上げる。次要求受付までpayload保持 |
| bridge→SDRAM | 108MHz側、REQ二段同期後、未処理要求の受付 | ext_addr/data/writeを登録し、完了まで保持。VDPスロットを奪わずCPUスロットで使用 |
| 通常Mapper/MegaRAM | モジュールのclk_27m入力（基板では54MHz）でsdram_seq=1 | addr/data/選択先を同時に保持。dataは次要求受付まで保持 |
| SDRAM書込みDQ | 108MHz側でSdrDatを登録 | CPU生出力でなく保持済みdataから生成 |
| 拡張読み出し返却 | SDRAM完了後ext_dout登録→ACK二段同期後bridgeのresult登録 | 次要求の返却まで保持 |

通常側のアドレスは元実装でも登録済みだったが、dataだけCPU出力を直参照していたため修正。
返却先も受付時のMapper/MegaRAM選択へ固定する。writeの有効期間は従来のスロット制御を維持。
payload保持試験では受付直後に入力アドレスとデータを変え、保持値で書かれることをSDRAM端子側で確認。
ただしこれらは機能上の保持条件。捕捉FFまでの実際のsetup/hold成立にはGOWIN STAが必要。

## 制約の扱い

既存SDCの有効なmulticycle指定は、CPU向けもSDカード向けも証明がないためコメント化した。
周期を広げたり、新規false_pathを追加したりして違反を隠してはいない。
既存の他のfalse_path／max_delay／クロック定義は変更せず、正当性を保証したという意味ではない。
特にPSG/RTC/OCM等の広いfalse_path、cpu_dinのmax_delay、PLL生成クロックは今後の監査対象。
各違反の開始点・終点・実捕捉エッジ・保持期間・slackの対照表は、現行R1のGOWINレポート取得後に作る。
過去版の同梱timing_pathsを現行違反の証拠に流用しない。

## 検証と限界

`verification_result.json` と `verification_memory_result.json` が今回の結果。

- 元T80とのバス比較16ケース：拡張回路有効／無効、WAIT、値／キャリー初期条件。
- 実COM実行7ケース：正常4位相、バンクの誤共有、データ破損、解除非対応。
- メモリ26ケース：デコード、16位相のSDRAM読書き、元コントローラとの端子比較4位相、payload保持4位相、電源投入待ち1回。別途、旧来のCPU直結データmuxへ戻した負例が失敗することも確認。
- GHDL→Verilog変換はシミュレーション用。生成Verilog識別子の衝突だけを置換し、CPU RTLの意味は変更しない。
- 部分的なtop Verilog構文確認。他言語／ベンダプリミティブ／周辺回路はブラックボックス。

SDRAMモデル、低位メモリモデルとBDOS9の小さな実行ルーチンを用いた機能試験。
実MSX-DOS全体、BIOS起動完了、HDMI表示、GOWIN合成／配置配線／タイミング、実機は未検証。

## 次の合格条件

まずこの構成でMSXが起動し、EZ80D1 R1: PASSとなること。
配置配線後の違反を捕捉・保持条件と照合し、必要ならRTLを修正する。
その後に24bit演算とスタック、ADLフェッチ、単一モードの割込み、混在モードを順に追加する。
版数は合格条件の代わりにしない。
