# R14更新

混在CALL／RET.Lのbit3を追加し、診断あり839F／なし039F、C4=9F、C6=60へ更新。C5／C7とC8／C9は同じ。EZ80MIX /RUNはP2: PASSを期待し、診断注入なしでも実行可能。P2版、COM20本とBATはR13.1と同一。未準備はLDH／LDX／TSTの3本。

bit3は表14の4形式のCALLとRET.L、条件付き命令を対象とする。混在／MADL RST、ADL IM0、短いサフィックス付きRET等を完成済みと示すものではない。現行READMEとRESTART_R14.mdを優先し、以下は履歴と契約。

# R13更新

MADL割り込みフレーム対応bit8を追加。機能マスクは診断あり8397h／なし0397h、C7はそれぞれ7Ch／FCh。C9は現在のMADL。EZ80MAD /RUNはP2: PASSが期待値。最初のZ80 IRQのIM1指定を補ったEZ80MAD.COMへ更新する。他19COMは同一。

bit8はSTMIX／RSMIXとMADL IM1／IM2／NMI・RETI.L／RETN.Lを示す。混在CALL／RETのbit3は0を維持。MADL IM0とMADL RSTは未対応で、このビットは全ての混在制御命令の完成を示さない。現行READMEとRESTART_R13.mdを優先し、以下は契約と履歴。

# R12更新

MBASE対応bit4を追加。C4=97h、C6=68h、C8はMBASE。診断接続あり8297h／なし0297h。EZ80MB /RUNはP2: PASSが期待値。COMのバイト列は変更なし。MADL／混在／新規ロード／TSTは未対応のまま。以下は契約と旧版履歴。

# P2 実機テスト用の対応機能照会・入力制御契約

これはMSXnano再構築CPUに追加する**将来の診断インタフェース**であり、Zilog eZ80の命令仕様ではない。先行P2配布時にはRTL未実装。R11はIM1／IM2／NMI／I16／通常RSTと診断接続を実装し、残る機能は未実装。詳細はRESTART_R11.mdを参照。R10のE1h応答だけでは機能対応を判定できないため、P2はこのインタフェースを持つCPUだけを実行対象とする。
CPUの機能が実装・検証できた段階で対応ビットを有効にすれば、同じCOMを使用できる。CPUの完成を示す版番号ではない。

## ポート

既存の16bit I/OアドレスE7E7hだけを使用する。BC=E7E7h、OUT(C),A／IN A,(C)を使う。上位00h固定I/O命令は追加しない。
既存のA5h→5Ahによるゲート開放、00hによるZ80モードでのロック、通常のE0h／E1h応答を維持する。A5h→5Ahによる開放時には照会選択を解除し、従来COMの直後のINがE1hを返すようにする。
拡張有効中に次の照会コマンドをOUTし、直後のINで値を得る。照会はADL／幅・レジスタ・IFFを変更しない。ゲートを閉じたら照会選択を解除する。

| OUT値 | 直後のIN値 |
|---|---|
| C0 | 45h |
| C1 | 5Ah |
| C2 | 02h（このP2契約の版） |
| C3 | A7h |
| C4／C5 | 対応機能16bitマスクの下位／上位 |
| C6／C7 | 上記それぞれのFFhとのXOR |
| C8 | 現在のMBASE |
| C9 | 現在のMADL、0または1 |

P2実行の入口はZ80、MBASE=00、MADL=0。DOS用の通常状態を要求する。
/RUN指定、既存ゲートE1h、署名・版・マスクとその反転値、入口状態、必要な対応ビットをすべて照合する。どれかが不成立なら、高位コードのロード・将来命令・割り込み入力制御を始めずNOT READYで終了する。ゲート自体がなければUNSUPPORTED。引数なしはREADY。
R10はC0後もE1hを返すので、署名の最初でNOT READYとなる。E1hだけを対応済み扱いしない。

## 対応ビット

| bit | 必要な実装 | COM |
|---|---|---|
| 0 | ADL IM1／RETI、EIの1命令遅延、HALT復帰 | EZ80IRQ |
| 1 | ADL IM2、16bit I、24bitベクタ3バイト読出し | EZ80IM2 |
| 2 | ADL NMI／RETN、IEF2保持・復元、HALT復帰 | EZ80NMI |
| 3 | STMIX／RSMIX、4種類の混在CALLとRET.L | EZ80MIX |
| 4 | LD MB,A／LD A,MB、短いデータのMBASE利用とバンク付きZ80フェッチ | EZ80MB |
| 5 | TSTレジスタ／即値／(HL) | EZ80TST |
| 6 | (HL)とペアの新規ロード／ストア、短い・長い形式 | EZ80LDH |
| 10 | (IX+d)／(IY+d)とペアの新規ロード／ストア、短い・長い形式 | EZ80LDX |
| 7 | 16bit IのLD I,HL／LD HL,I | EZ80I16 |
| 8 | STMIX／RSMIX、Z80／ADL起点のMADL IM1とRETI.L | EZ80MAD |
| 9 | 通常ADL RSTとRET、全8ベクタ | EZ80RST |
| 15 | 下記の実際の割り込み入力・ベクタ試験接続 | IRQ／IM2／NMI／MAD／RSTに加えて必須 |

各ビットはR10相当の既存データ命令・幅指定・長いSPL読出し・ADLフェッチ・JP.SIS／JP.LILが成立していることを前提にする。bit1は16bit I転送も必須。EZ80NMIはRETN後のIEF1をIRQ受付で確認するため、bit2に加えてbit0も必須。
未実装の機能に対してビットを立てない。bit15はテスト用接続がない通常ビルドでは0にする。

## 入力制御とベクタ接続（bit15）

MSXのBIOSベクタを書き換えず、将来のCPUラッパー／バス側の試験接続で行う。未接続でbit15を立ててはならない。

| OUT値 | 動作 |
|---|---|
| D8 | 診断接続を有効化。通常VDP等のINTを一時マスクし、下記ベクタ読出し先を切替。試験IRQ／NMIを解除 |
| D1 | 試験INT_nを低レベル保持。CPU入力の通常の同期・受付経路へ接続 |
| D2 | NMIを予約。次にHALT_nが有効になってから、CPU入力NMI_nへ少なくとも8 CPU許可クロックの低パルスを1回与える |
| D4 | 試験IRQ／NMI予約を解除。通常INTのマスクとベクタ切替は維持 |
| D0 | 試験入力・予約・ベクタ切替・通常INTのマスクを解除し、通常MSX接続へ復帰 |

有効中のCPUメモリ読出し000000h〜00007Fhは、論理0F0000h〜0F007FhのプライベートSDRAMを参照する。000038h／000066hのJP本体と後続即値も含むため、M1の1バイトだけを切り替える実装にしない。MSXのBIOS ROMへの書込みは不要。
切替はCPUからSDRAMへ入る要求の捕捉前に行い、MSX側デコーダを遮断する。捕捉後の要求アドレス・データは保持し、VDP優先とCPU WAITを維持する。
通常VDPの表示・メモリ仲裁は継続する。マスクするのはCPUへ渡す通常INTだけ。
IM2の試験INTのIACKデータはFEh（偶数）とし、通常メモリ読出しのDIへ影響させない。NMIは内側のフラグを直接立てず、NMI_nの同期・エッジ検出から検証する。

IRQケース1はD1による保留要求を作ってEI→LD A,A6hの次で割り込ませ、復帰PCとAを照合する。ケース2はEI→HALT。
NMIはDI中とEI後のHALTで試験する。NMI ISR内でIEF2を記録し、その後D1でIRQを保留する。RETN後のDIより前にIRQを受けるかを照合し、IEF1の復元を確認する。要求が届かない場合はHALTから戻らないため、基板リセットが必要。bit15を入力経路まで確認してから有効にする。

この接続は追加のCPU命令ではない。実装時は診断接続の資源・タイミングを別途確認する。通常ビルドに接続を含めるか、診断ビルドだけに含めるかは後続の合成結果で判断する。P2のCOMはどちらでも変更不要で、接続がない版ではNOT READYとなる。
