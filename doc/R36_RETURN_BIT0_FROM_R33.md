# R36：R33を基準に、復帰フレームのbit0判定へ限定

## 目的

R33の実機確認済み構成へ戻り、復帰フレームの上位7bit形式判定だけを取り除く比較版。R35のCPU内入力FF移動を取り込まず、ラッパーの8bit入力保持FF、捕捉条件、WAIT、バス制御をR33のまま維持する。

R33→R35の実装レポートでは54MHz系報告Fmaxが42.927→35.650MHz、CPU内最悪Setup slackが-2.454→-5.442nsへ悪化した。変更範囲を絞り、形式判定削除の効果を別に測定する。R36のGOWIN配置配線結果は未取得であり、改善を確定した版ではない。

## 変更

| 場所 | R36の処理 |
| --- | --- |
| g80a_ez80.vhd | 入力選択とDI_Regの8bit保持を維持。上位7bit比較およびDI_Frame_Valid_Regのみ除去 |
| t80_ez80.vhd | 復帰フレームのframe_mode状態で、保持済みDI_Reg(0)をFrame_Mode_Bitへ保存。形式不一致によるframe_fault分岐を除去 |
| t80_pack_ez80.vhd | 使用しなくなったINPUT_FRAME_PREDECODEジェネリックとDI_FRAME_VALIDポートの宣言を削除 |

入力DI_CAPTURE_ENABLEポートやINPUT_CAPTUREジェネリックは追加していない。入力FFはCPUへ移動していない。

## 判定が有効になる範囲

bit0による復帰モード選択は、CPU内部の既存復帰フレーム制御がframe_mode状態に入ったときだけ行う。デコーダによるフレーム対象命令の選択、条件付き復帰の成立判定、MADL条件はR33から変更していない。

- bit0=0：保存されていたZ80モードへ復帰。
- bit0=1：保存されていたADLモードへ復帰。
- 上位7bit：モード判定に使わない。上位7bitが02h/03hの形式に一致しなくても形式不一致で停止しない。
- 通常のRET、メモリ読出し、I/O読出しを新たに復帰フレームとして扱う変更はない。
- frame_modeはIM0のNOP相当完了にも再利用されるため、既存のIRQ_IM0優先分岐を保持。この場合は入力バイトを復帰モードとして解釈しない。

Stream_Longは命令側で確定した復帰フレーム構成・読出しバイト数に引き続き必要。bit0による保存モード判定と混同しない。ADL_Modeそのものは戻りアドレス/スタック復元が完了する既存位置で更新される。

スタックへ保存するモードバイトは従来どおり02h/03h（上位7bit=0000001、bit0=保存ADL）。スタックレイアウトや既存プログラムのABIは変更していない。上位7bitの破損をこのチェックで検出する機能はなくなる。その他の未対応フレーム等の保護分岐は維持する。

## 入力とバス

R33の以下の構造を維持する。

1. 入力選択：E7E7状態読出し、診断E6ループバック、診断IACK、通常DIの既存優先順位。
2. CLK_n立下り、clk_falling=1、TState=011、BUSAK_n_i=1でDI_Regへ8bit取り込み。
3. 条件外では保持。WAITの捕捉は既存位置・条件のまま。
4. CPUは保持済みDI_Regを読む。通常命令/実行デコード、ADL/MADL/MBASE制御、SPS/SPL制御は判定削除部分以外変更なし。

MSX16bitバスと拡張24bitバスの分離、MBASE窓、$FFFF隔離、要求保持、SDRAM、VDP、UART、SDC/CST、GPRJは変更なし。GSRは引き続き保留。

## ローカル検証

最終件数はR36_VALIDATION.jsonを参照。ソース差分・生成モデル・実COM試験は別々の確認であり、いずれも物理タイミングの収束を保証するものではない。

- GHDL：通常・診断・拡張無効の3プロファイルでVerilogモデル生成。VHDL93の6ファイル解析。
- 全256バイト×Stream_Long 2通り=512ケース：実際の入力保持を経由してframe_modeの保存bit0、次状態、SPL、カウント、アドレスを検証。状態入口はシミュレーション上の強制条件。全CPUの実行試験とは区別。
- 上の試験に保存bit/ストリーム幅の誤りを注入する2つの負例が、期待どおり失敗することを確認。
- frame_idleとIM0のNOP相当完了：各256バイト、計512ケースで入力バイトが保存モードやスタックを変えないことを検証。通常命令実行を保持した状態の切り出し試験。
- 入力選択・捕捉・保持：通常/診断の両プロファイルでR33と比較。データFFを強制せず入力源選択だけを切り出す。
- 幅/プレフィクス保持64ケース。
- MSX-DOS呼出しがEIする条件を含む既存BDOS治具を使用。実機用COMは既存のDI区間・復帰処理を変更しない。
- 実際の30COMをR33とクロック半周期ごとに比較。バス、保持入力、上位レジスタ、PC、SPL、F、IncDecZを比較。
- 追加12COM：CPU_DIV=4、位相3、CEN停止、実SDRAM RTLのWAITを含めてR33と比較。
- 合成生成モデルで8bit保持FFがラッパーに残り、上位7bitタグが存在しないことを確認。
- 全FPGAファイルをR33のSHA256と比較。変更3ファイル内も限定した差分から再構成して照合。COM30本とRUNALLの既存基準ハッシュを確認。両GPRJ各123参照を検査。

シミュレーションの時間は論理動作を検証するための設定であり、GOWINの物理遅延を再現するものではない。GOWINのタイミング収束・実機動作は未確認。

## 実機手順

通常版は fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj をビルド。以前のimplから生成物を再利用せず、このR36のフォルダを展開して使用する。プロジェクト設定自体はR33と同一。

既存のFLASH上のCOMをそのまま使用できる。新しいCOMの書込みは不要。

1. EZ80MEM /RUN
2. EZ80MR4 /RUN
3. EZ80MIX /RUN、EZ80MAD /RUN
4. EZ80MX0 /RUN、EZ80MX1 /RUN、EZ80MX2 /RUN、EZ80MA1 /RUN
5. EZ80IRQ /RUN、EZ80IM2 /RUN、EZ80NMI /RUN
6. RUNALL.BAT
7. SOFARUNからスペースマンボウを起動しPLAY。

既存COMの表示版番号は変更しない（例：EZ80MEM P1、EZ80MR4 R21.3、MX0/1/2/MA1 R29.1）。ビットストリームの版番号ではない。

確認後のimplをR33/R34/R35と同一の設定・有効制約で比較する。Logicの百分率だけでなくLUT整数、54MHz系Fmax・TNS・違反終点、CPU内最悪Setup、半周期経路、Holdを確認する。制約を緩めて改善したように見せる変更はしていない。

## 再現

環境変数GHDL、IVERILOG、IVL_ROOT、VVPにツールを設定し `python3 tools/verify_r36.py` を実行する。GHDLモデル化用の限定的なVerilog信号名修正は既存検証方式を継承し、FPGAソースへ適用していない。

R33_to_R36.patchにRTL差分、sim/reference_r33に完全なR33 CPU/ラッパー6ファイル、doc/R36_BASELINE_R33_SHA256.jsonにR33全FPGAファイルの基準ハッシュを格納。旧版の資料・スクリプトは履歴として残し、本版の検証入口はverify_r36.pyとする。旧DI_Frame_Valid_Regを必須とするcheck_gowin_cpu_r29_2.pyはR36へ適用しない。
