# 先行実機テストの範囲

## 仕様と方針

Zilog eZ80 CPU User Manual UM007715-0415を一次資料とする。
https://www.zilog.com/docs/UM0077.pdf

参照する紙面ページ：ADC 85–87、ADD 94–97、EX(SP) 145–146、CPI/CPIR 126–128、
LDI/LDIR/LDDR 239–241、LEA 242–245、MLT 246–247、PEA 275–276、
メモリモード切替25以降、割込み36以降。
公式の命令意味から期待値を先に固定し、現在のRTLの出力を正解として採用しない。
対象は公式eZ80の拡張で、別プロジェクトのM0/M1/M2仕様を混ぜない。

共通のE7E7h解除は本FPGAだけの制御。Zilog命令仕様の一部ではない。
全機能の完成を検出する能力ビットはまだないため、通常は将来機能の本体へ入らない。
/RUNは実行要求の指定だけであり、機能の有無を保証しない。

## 実行形式と準備済みケース

- MEM：絶対1バイト5アドレス、EX(SPL)3組。01FFFFhと64KiB境界を含む。
- ALU：ADD/ADC/SBCの24ケース。BC/DE/SPL入力、上位キャリー、ゼロ、符号反転、借り、半桁。
- BLK：コピー4ケース、比較2ケース。単発の24bit BC減算と短いリピートを区別。
- MUL：BC/DE/HL各5組、SPL/SPS各3組、計21ケース。積の上位24bit未規定部分へ依存しない。
- LEA：24ケース、PEA2ケース。+1、-1、-128、FFFFFFh境界。
- ADL：ローダとnativeコードによる1ケース。01FFFEhからのフェッチと即値が020000hをまたぐ。
- LOG：既存データアクセスだけによる診断1ケース。

JSONのシナリオ数は計87。比較バイト数・全命令網羅率とは異なる。
上記は各機能の最初の合否判定であり、全オペランドや全命令の網羅試験ではない。
全追加命令、I/O拡張、TST、MLTの全65536入力、CPDR等は今後の追加対象。

## 観測方法

レジスタの24bit結果は、R2/R3で成立したPUSHと独立したバイト読出しによって比較する。
EX(SPL)は返却レジスタを低位SNAPへ格納してからメモリを確認する。
これにより、HLをチェック用アドレスへ書き換えて結果を失うことを避ける。
フラグは結果比較より先に通常のPUSH AFで保存する。FLAGSの低位バイトがF。
FはS/Z/H/PV/N/CだけをマスクD7hで比較し、未規定のビットへ依存しない。
ADD/ADCのHはマニュアルのbit11からのキャリー、SBCのHはbit12への借りとして期待値を計算する。

CPI/CPIRはBC残量、HL終点、フラグを確認する。
コピーはBC/DE/HLを同時に退避してから、コピー先の各バイトを比較する。
65537回などの長いリピートは実行せず、24bitカウントの境界は単発LDI/LDDで確認する。
各試験は破壊的な専用RAMテストで、試験前の内容を復旧しない。

## メモリ割当

全COMが自身の低位バッファと通常SPSを使用する。
共通のペア結果確認には060100h..060108hを予約する（各試験が必要な部分を使用）。
専用RAMの物理アドレスは論理アドレス+640000h。例えば070800h→6B0800h。

| 試験 | 主な高位書込み先 |
|---|---|
| MEM | 07FFFEh、07FFFFh、080000h、01FFFFh、1BFFFFh、03FFFFh..040001h |
| ALU | 共通ペア退避060100h..060102h |
| BLK | 02FFFFh..030001h、08FFFFh..090001h、共通ペア退避 |
| MUL | 主に低位SNAP/FLAGS。SPS変更時は保存済みSPSを復帰してからPUSH/CALLする |
| LEA | 共通ペア退避、04FFFEh..050000h |
| ADL | payload 01FFFEhから27バイト、030100h..030103h、CALLフレーム04FFFEh..050000h |
| LOG | 070800hの1バイト |

COMはVRAM/MegaRAMを直接試験しない。書込み先の詳細はvectors内の各シナリオと生成元を参照。
`writes`欄は明示的に列挙した初期化／転送先で、共通の退避領域や低位バッファを全列挙したものではない。

## ADL用ローダ

R3で成立した明示プレフィクスのバイト書込みでpayloadを高位RAMへ置く。
DI状態でJP.LIL 01FFFEhへ移行し、native LDで結果3バイトを030100hへ記録する。
native SPL=050001h、native CALL/RETで3バイトの復帰アドレスと境界を確認する。
最後にJP.SISでバンク00のADL_RETURNへ戻り、通常のデータテストで結果とSPLを比較する。
その後に拡張ロック、EI、BDOS表示へ進む。nativeコードからDOS/BIOSを呼ばない。

このローダを動かすにはADLのフェッチだけでなく、native LD、CALL/RET、JPモード遷移が必要。
ADL RETURNへ戻れない不具合を、ソフトのタイムアウトだけで必ず回収できるとは保証しない。

## 割込み・混在モードの後続試験

先に固定できるケースは `doc/INTERRUPT_MATRIX.json` に整理した。
ADL割込みの実機COMはまだ生成していない。MSXの既存割込みと競合しない発生源・
書換え可能なベクタ領域・I16/IM2の統合方法・終了時の復旧を確定する必要があるため。
NMI発生には外部入力またはFPGA側注入が必要であり、MSX-DOS COM単体では保証できない。
この条件が決まり次第、期待するSPとフレームを固定してCOM化する。

## 検証済み／未検証

静的検証：COMとDEFBの完全一致、SHA256、命令バイト位置、期待値の独立再計算。
実行検証：R3のCPU・ブリッジ・SDRAMモデルで通常起動と診断自己試験を確認。
BDOS9モデルにはEIがある。拡張解除中にIFF1が有効なら実行検証を失敗させる。
通常起動で将来機能の本体や高位RAM要求へ進んだ場合も失敗させる。
拡張無効で/RUNした場合はUNSUPPORTEDで戻る条件を確認。

将来機能の本体の実行は、対応RTLと実機ができるまで未検証。
`PLANNED`は合格ではなく、`EZ80LOG`のSELFTESTも未実装命令の合格ではない。
実MSX-DOS全体、BIOS起動、GOWIN合成、配置配線、実機動作はこの作成作業では検証しない。
