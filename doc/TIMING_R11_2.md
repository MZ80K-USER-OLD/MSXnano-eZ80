## デコード経路

実ネットリストには、IRをアドレスとする`pROM Read_To_Reg_r_4_s43`が存在する。
R11.1のクリティカルパスは、このBSRAM出力→EX_SP_Long→レジスタ選択→上位レジスタ書込制御で25段、26.897 ns。
同じ始点から要求ラッチへの半周期経路にも16.448 nsのデータ遅延がある。

R11.2では、IRと同じ場所・同じ条件で6bitのOpcode_Classを取り込み、EX(SP)、長いPUSH/POP、INC/DEC、絶対バイト／ペアの分類を保持する。
通常フェッチだけでなく、IRQで強制されるRST／NOP、DDCB等の別取込み箇所も同時更新する。幅フラグ・ISet・割込み状態の資格条件は維持する。
さらにT80_eZ80エンティティにsyn_romstyle="logic"を指定し、CPUデコードにBSRAMが自動推論される構成を避けるよう指示する。

公式仕様：[GowinSynthesis SUG550](https://cdn.gowinsemi.com.cn/SUG550E.pdf)、syn_romstyle項。
これは配置配線の遅延制約を緩める操作ではない。GHDLはベンダ属性を物理割当には使わないので、属性が効いたか、CPUデコードのpROMが除かれたか、Logic／CLSが収まるかは次のGOWIN出力で確認する。

## EX(SP),rrのワーク方式

対象は既実装の長い幅のHL／IX／IY。BC／DE用の新しい交換命令を追加していない。

| 時点 | 処理 |
|---|---|
| M1/T3 | EX_SP_AddressへSPLを保持し、最初の読出しアドレスを準備 |
| M1/T4 | rrの上位8bit＋下位16bitをEX_SP_Sourceへ保持 |
| M2〜M4 | 3バイトをEX_SP_Readへ読み込む |
| M2/M3の受理T2 | アドレスワークを1増加 |
| M4の受理T2 | アドレスワークをSPLへ戻し、書戻し先を準備 |
| M5〜M7 | EX_SP_Sourceの下位・中位・上位を順に書き戻す |
| M5/M6の受理T2 | アドレスワークを1増加 |
| M7/T3 | EX_SP_Readをrrへ反映 |

SPL自体を進めない。WAIT中とCPUイネーブル停止中はアドレス・保持元を変更しない。命令途中のIRQ／NMIは保留し、最終書込み完了境界で受け付ける。
M1/T3でアドレスを準備するのは、次のM1/T4が次サイクルの外部アドレス捕捉点だからである。同じT4で準備すると旧ワーク値を使ってしまう。

新規シミュレーションはHL／IX／IY×IRQ／NMI×読出し中／書戻し中の12条件。各条件にWAITとCEN停止を入れ、3読出し→3書込み、バンク境界、F保存、SPL復帰、ISRが命令完了後に実行されることを確認する。
通常の16bit交換は元の経路を維持し、元G80Aとのサイクル比較と既存回帰で確認する。

## SDRAMの捕捉時点と保持期間

旧経路も単純な毎周期取込みではない。要求をext_meta→ext_syncで同期し、pending／selected／doneがない時だけ保持済みデータを受け取る。
R11.2では、その受理条件をext_capture_armedへ登録し、次の受信クロックでデータを捕捉する。

1. ブリッジがアドレス・書込みデータ・方向とram_reqを同時に保持する。
2. 受信側でmeta、sync、capture_armedを順に通す。
3. 最も早い場合も、最初の要求サンプルから受信3周期後に捕捉する。
4. pending／selected／doneとワンショット自身により再捕捉を防ぐ。
5. 送信側は応答の同期受領までpayloadを変更しない。次の要求は応答解除を待ってから出す。

実機の受信108 MHzでは3周期は約27.78 ns。ここでの安全性は、上記の捕捉許可と保持契約が満たされる通常要求・共通リセットの場合に限定する。
トップのreset3_nはbus_reset_nで0となり、その後段階的に1へ解放される信号で、実行中に単独で再アサートする回路ではない。送信側だけを任意にリセットする別接続まで保証したものではない。

専用試験では送信側54 MHz相当クロックだけを0／2／5／8 nsずらし、受信側と旧VDP／SDRAMスケジュールの関係は維持する。
全メモリバンクの読書き、VRAM／MegaRAM共有、VDP競合、リフレッシュ、起動待ち、共通リセットを実コントローラ＋SDRAMモデルで実行する。
捕捉前3周期、payload保持、要求1回につき1捕捉を監視し、早過ぎる捕捉と保持データ改変の2故障注入を検出する。拡張要求がない時は旧コントローラと4条件でピン比較する。
これは任意の位相で既存VDPコントローラ全体が動くことを検証したものではない。

## クロック定義と未解決事項

R11.1のホールド詳細ではPLLのクロック経路に3.599 nsが計上され、CLKDIV側の開始点は0 nsだった。これだけで75件を全て誤検出とは断定しない。
R11.2では27／54／108 MHzを共通の外部入力から周波数比で定義し、段階的な生成クロック定義の遅延計上を再評価する。
入力クロックの一般配線PR1014はCSTを推測変更していない。手入力のset_clock_latencyによる差引きも行わない。

false path、multicycle、max_delay等の例外はR11.1から変更していない。今回の保持契約を理由に一括でホールド解析を無効にすることもしていない。
新しいレポートで、クロック起点・スキュー、ホールド、CPUデコードの実割当、CLS残量を確認する必要がある。

## 通常のメモリ書込みと共通ワーク

通常書込みにも、CPUのData_Out_Reg（8bit）が既に共通の出力ワークとして存在する。
その後はRequest_Data→ram_din→ext_data_latchedで保持し、SDRAMの書込み期間中に生のレジスタファイルやALU出力を直接参照しない。
これらはCPU要求、ブリッジ取引、クロック境界それぞれで保持期間が異なるため、単に同じレジスタへまとめることはしない。
CALL／RSTにはCtrl_Return、PEAにはEA_Result、今回のEX(SP)にはEX_SP_Sourceという複数バイトの保持元があり、そこから共通8bit出力ワークへ1バイトずつ渡す。
R11.2はこの方式を維持し、全メモリ命令を新たな24bitワーク一個へ統合する変更は行っていない。将来の共有化は、各命令の捕捉時点と既存ワークの寿命が重ならないことを確認して判断する。
