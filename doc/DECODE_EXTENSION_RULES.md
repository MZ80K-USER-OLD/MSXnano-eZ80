# 命令追加時のデコード配置

R15.3ではTSTの末尾上書きをED内へ移した後に実機回帰が回復した。R22で反復I/Oを末尾上書きとして追加し、既存メモリ試験にも実機不良が報告された。R22.2は反復I/OもED内へ移した比較版で、実機回復は未確認。

1. ED追加命令は原則として既存のED opcode caseの専用行でデコードする。新命令のために全命令ページの最終出力を上書きする段を追加しない。
2. raw opcodeを全命令共通の別opcodeへ変換するMUXを追加しない。分類情報は命令取得時の既存保持フィールドを使い、命令ページ・拡張有効・割込みサイクルの資格を明示する。
3. ALU・増減器・レジスタ書込ポート・要求保持を共用し、命令ごとの演算器・カウンタ・FSMの追加を避ける。
4. 旧命令の制御出力比較と、実COMのメモリ・スタック・割込み・WAIT回帰の両方を行う。論理等価性は配置配線後のタイミング保証ではない。
5. GOWIN実レポートで捕捉時点と保持期間を照合する。見かけ上の違反を消すための一律制約緩和はしない。

R22.2には`tools/verify_decode_scope_r22_2.py`を置き、反復I/OがED内の専用行にあり、末尾上書きやED未定義NOP行との重複がないことを確認する。この文字列構造検査は、VHDL全体の一般的な構文解析・タイミング検証を代替しない。
