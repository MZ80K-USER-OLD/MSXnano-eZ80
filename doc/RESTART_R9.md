# R9：工程5 ADL状態・PC24・命令フェッチ

追記：R9はその後ユーザーのGOWIN合成・実機EZ80F9 PASS・スペースマンボウPLAYで合格。LUT84%。以下はR9配布当時の範囲を残す履歴で、現在の工程6の範囲はRESTART_R10.mdを参照。

## 基準と範囲

R8のGOWIN合成、実機のEZ80LEA P1: PASS、その後SofaRunからスペースマンボウをプレイできたことをユーザー報告として記録する。
大工程の番号は `doc/ROADMAP.md` の10工程に統一する。工程1〜4は実機合格、工程9のMLT／LEA／PEAは先行して実機合格。**現在は工程5**。

R9ではPCを24bit化し、ADL状態を保持する。リセット直後は従来どおりADL=0・拡張ロック状態。
SPSは16bit、SPLは24bit。ADL=0のPCは16bitで折返し、ADL=1のPCは24bitで折り返す。
変更はG80A_eZ80内のCPU本体、mcode、mcodeのポートを宣言するpackの3ファイル。
元G80A、ラッパー、トップ、メモリブリッジ、SDRAM、GPRJ、CST、SDC、Dual Purpose Pin／SystemVerilog設定はR8と同じ。
マルチサイクル指定やfalse_pathを追加しない。
R9のGOWIN合成・配置配線・タイミング・リソース量・実機動作は未確認。

## 状態と単一命令の幅

| 状態／指定 | データ幅 | アドレス即値幅 | 命令取得のPC |
|---|---|---|---|
| ADL=0、指定なし | 16bit | 16bit | 16bit、バンク00 |
| ADL=1、指定なし | 24bit | 24bit | 24bit |
| 40h .SIS | 16bit | 16bit | 現在のADL状態に従う |
| 49h .LIS | 24bit | 16bit | 現在のADL状態に従う |
| 52h .SIL | 16bit | 24bit | 現在のADL状態に従う |
| 5Bh .LIL | 24bit | 24bit | 現在のADL状態に従う |

幅プレフィクスは通常、1命令分だけを指定する。短いデータ幅にしても、その命令を読むPCを16bitへ切り替えない。
JPの有効なモード移行指定は.SIS／.LIL。JPの.LIS／.SILは本試験の対象にしない。

工程6を実行する前提として、無条件即値JPを先行実装する。
JP.LILで24bitターゲットへ移りADL=1、JP.SISで16bitターゲット・バンク00へ戻りADL=0。
ADL中の無指定JPも24bit即値を読む。
ターゲット上位バイトとADL状態は、最後の即値を読み終えた時点でPC・外部アドレスと一緒に反映する。
MBASEレジスタはまだなく、Z80側はMBASE=00相当。

公式eZ80 CPU User Manual UM007715-0415、モード切替とJP Mmnの表：
https://www.zilog.com/docs/UM0077.pdf

ADLに入ると、R1〜R8で実装したデータ系命令の幅既定値も長くなる。
これは全命令をADL対応したという意味ではない。今回の実機COMで使うのは即値ロード、絶対ロード／ストア、インデックスアクセス、幅プレフィクス、無条件JPの検証済み部分。
R8までと同じく、短いレジスタ即値ロードの上位8bitには実装上の扱いがある。.SISの2バイトロードでは保持、.SILの3バイト取得・短い結果では00hとなる。後者をADL状態の消失と混同しない。

## PCと外部バス

PCの+1は共通24bit経路を使い、Z80モードでは結果の上位8bitを0にする。
64KiB境界をまたぐ命令本体・即値・DD／FD／ED・幅プレフィクスを、次のバンクから続けて取得する。
ADL中に短いデータアクセスを行う場合も、命令列の取得先はPC24を維持する。
データアクセスのアドレス幅と命令取得アドレスを別々に判断する。

M1のT2でWAITを受けている間はPCと命令アドレスを保持する。
WAIT解除時に命令バイトを捕捉・PCを1回進め、リフレッシュでは上位バンクを00にする。
次の命令／即値を要求するときに、登録したPCの上位8bitをアドレスへ出す。
SDRAMの要求アドレス／データ捕捉と保持は既存ブリッジ・コントローラに従う。
高位xxFFFFhの命令取得を、MSXのセカンダリスロットFFFFhへ流さない。
既存のVDP優先仲裁とCPU WAITは変更しない。

CEN停止は立上り／立下り許可をT-state全期間単位で対にし、途中の半周期だけを欠落させない。
これは機能試験の条件で、GOWINの実際のsetup／hold成立を証明するものではない。

## 工程6〜8との境界

**ADLのCALL／RET／RST、条件付きJP、JR／DJNZ、レジスタ間接JP、RETI／RETNは未対応。**
R9ではADL中のこれらの既知の制御命令をHALTで停止し、従来の16bitフレームをSPSへ誤って積んで処理を続けることを防ぐ。
これはeZ80本来の動作ではなく、工程6・7の実装前に設ける一時的な保護。
Z80モード中の明示的な長いCALL／RETなどもサポート外。今回の試験では実行しない。
未定義・未実装の全オペコードを完全に例外化した仕組みではない。

**ADL中のINT／NMI受付は抑止している。ADL割り込みは未実装。**
INTを長く保持してもADL中に16bit SPSへ割り込みフレームを作らないことを単体試験する。
既存同期回路のNMI_sは要求を保持するが、ADL用のフレーム・配送・Z80復帰後の再配送タイミングは未実装・未検証。ADL実機試験はDIで行い、NMIを発生させない。
R9でADL中にEIを使えると判断してはならない。単体試験内のEIは保護を確認するための刺激だけ。
Z80モードへ戻った後の従来IRQは、R6以降の回帰で確認する。

拡張ゲートを閉じるOUT E7E7h,00hは、ADL=0へ戻ってから使う。
ADL中のロック要求は受け付けず、途中でデータ幅だけが失われることを防ぐ。
MBASE、MADL、混在CALL／RETのフレームは工程8に残る。

## 新しい実機用テスト

今回は `hardware_test/EZ80F9.COM` を新規追加する。R9のビットストリームを書き込んでから、COMを一度コピーする。
R8以前では/RUNしない。既存のE7E7hのE1h応答は拡張ゲートを示すだけで、R9かどうかを判別する機能一覧ではない。

```
EZ80F9 /RUN
```

期待表示は **`EZ80F9 R9: PASS`**。
COMは9058バイト、SHA256：
`22c260a5c6d4b395488cfd2d215925d4e79767b6a4177a34d059fc51e7e71b80`
引数なしでは `EZ80F9 R9: READY - use /RUN` と表示して終了し、ADLコードを実行しない。
ADLの実行・コード領域の書換えは/RUNのときだけ。

| 試験番号 | 高位コードの開始 | 主な確認 |
|---|---|---|
| 1 | 02FFFEh | LD HLの即値が境界越え。無指定の長いデータ操作、40／52／5Bの幅指定と復元 |
| 2 | 03FFFFh | DDプレフィクスが境界越え。IXのロード・データ読書き |
| 3 | 04FFFEh | 49／EDと命令本体が境界越え。16bit即値アドレスと24bitデータ |
| 4 | 05FFFFh | JP.SISの40hが境界越え。ADL=0へ復帰 |
| 5 | 07FFFFh | FDプレフィクスが境界越え。IY+1のデータアドレスも64KiB越え |
| 6 | 08FFFDh | ADL内の無指定JP。3バイト即値が境界越えし、090010hへ分岐 |

stage 1..6はこのテストの番号で、大工程の工程番号ではない。
各コードはZ80側から書き込み、全バイトを読戻して確認してからJP.LILで実行する。
CALL／RETはADL内で使わず、各コードはJP.SISで低位ローダへ直接戻る。
戻った後で結果と、MSX側FFFFhから保存した値の不変性を検査する。

不一致では最初の比較箇所の `ADDR=xxxxxx EXP=xx ACT=xx` を表示する。
コード読戻し破損の例：`FAIL stage 1`、`ADDR=02FFFF EXP=56 ACT=57`。
ADL中に作成した結果の破損の例：`FAIL stage 1`、`ADDR=060100 EXP=56 ACT=57`。
ADLコードが停止して戻れない場合はDOSから診断文字列を出せないため、リセットが必要になる。

**保存済みのEZ80ADL.COM /RUNはまだ使わない。**
そのP1テストはADLのCALL／RETも含むので、工程6の実装・検証後に使用する。
EZ80MEM／ALU／BLK／MUL／LEAの既存COMは変更していない。

### 使用領域

今回のCOMが使用する専用RAMは、各表の開始からコード末尾までの領域、060100h..060116h内の結果バッファ、078001hと020000hのデータ試験領域。
コード6の090001h..09000Fhには、分岐で飛び越すパディングも書く。
正確な各コードのバイト列・長さ・低位復帰先は `hardware_test/EZ80F9.json` に収録する。
物理専用RAMは論理アドレス+640000h。MegaRAM／VRAMをこのCOMでは直接試験しない。
COM内の低位バッファと通常SPSも使う。上書きした専用RAMの元の内容は復旧しない。
FFFFhは読取りと比較だけで、実機COMから書き換えない。

DI区間はDOS／BIOSを一切呼ばない。モードをZ80へ戻し、拡張をロックしてからEI・BDOS表示・DOS復帰を行う。
SPSとIX／IYの復旧を確認する。BDOSモデル自体がEIすることを許容する。
PASS後にSofaRunからスペースマンボウを起動・プレイして通常動作を確認する。

## 機能検証と制限

現行集計は `verification_result.json`。

- R8までの回帰77条件。
- 新COMの10条件：正常4位相、コード破損、結果破損、拡張無効、/RUNなし、CPU_DIV=4、CPU_DIV=4とCEN停止の組合せ。
- PC単体12条件：16bit／24bit折返しを通常・WAITとCEN停止の組合せで4条件、未対応制御命令の保護8条件。
- R6由来の期待失敗2条件も継承する。

高位命令の取得アドレスと命令バイトは、作成したコードから求めた独立した列と照合する。
リフレッシュの上位バンクが00であること、全6回のJP.SIS復帰、ADLの解除、SPS・IX／IY、低位FFFFhガードを確認する。
SDRAMからのフェッチは実際のブリッジ／SDRAMモデルを通す。

24bit PCのFFFFFFh折返し単体試験だけは、全24bitを読める合成ROMモデルを使う。
実基板のFFFFFFhがRAMとして割り当てられたことや、そこでコードを実行できることを示すものではない。
未対応制御試験ではADL内でEIと保留INTを与え、CALL／RET／RST等でSPS・SPLやメモリを書き換えず停止することを確認する。
NMI保護の単体試験も含むが、正式なADL割り込みフレームの検証ではない。

GHDLのVerilog変換とIcarus Verilogによる機能試験。実MSX-DOS全体、BIOS起動、映像、配置配線後の遅延を再現しない。
I/O上位00h固定の追加命令は引き続き実装対象から除外し、通常Z80のI/O命令は維持する。
