# R31：デコード側で確定し、実行側で参照する範囲を広げる

## 基準と対象

R30はユーザー実機で個別10本、RUNALL全項目、SOFARUNからスペースマンボウ起動・PLAYが成功。GOWINではLogic16224/20736（79%）、LUT14330、Register6752、54MHz系Fmax43.350MHz、Setup違反362、Hold違反42。機能確認済みだがタイミング収束済みではない。

R31のFPGA差分はt80_pack_ez80.vhd、t80_ez80.vhd、t80_mcode_ez80.vhdの3ファイル。ラッパー、メモリ、MSX16bit／拡張24bitバス、MBASE窓、VDP、SDC/CST、GPRJ設定は変更しない。GSR利用は保留のまま。

## 追加した共通判定

Exec_Controlは62bitから73bitへ拡張。追加11種類をDecode_Executionで確定し、IRと同じ既存の更新条件で保持する。

| 制御 | 確定する内容 | 主な参照先 |
|---|---|---|
| EC_PAIR_HL | ペア番号10 | HL／IX／IY選択、演算の入力 |
| EC_PAIR_SP | ペア番号11 | SP／SPL選択、MLT、PUSH/POP時のAF選択など |
| EC_STACK_PUSH | 命令下位4bit=5 | 長PUSHのサイクル制御、上位バイト出力 |
| EC_STACK_POP | 命令下位4bit=1 | 長POPの上位バイト書込み、即値処理の分類 |
| EC_BYTE_STORE | 命令32 | 絶対バイト転送の書込み方向 |
| EC_IMM_PAIR | 拡張有効・基本ページ・ペア即値命令 | 旧Modeの上位バイト処理 |
| EC_INDEX_FETCH | 命令CBまたは36 | インデックス追加フェッチ判断 |
| EC_MADL_SET | 命令7D | MADLセット／リセットの値 |
| EC_MB_WRITE | 命令6D | MBASE書込み／読出しの方向 |
| EC_LD_MEM_IMM | 命令36 | インデックス即値ストアの後続処理 |
| EC_ABS_SP | 基本ページ以外・ペア番号11 | 絶対ペア転送のSP経路 |

これらは分類フィールドや補助判定であり、単独では命令有効を意味しない。既存のEC_STACK、EC_PAIR_ABS、EC_MB_VALID、EC_MADL_OPCODEなどによる命令の有効条件と組み合わせる。特にEC_PAIR_SPはペア番号11の共通分類で、PUSH/POPではAFを表す。既存T80の意味を変えない。

同じ判定を各実行箇所で別々に比較せず、CPU本体とmcodeの拡張実行側で共用する。PEAの判定には既存EC_PEA、絶対ペア転送のページ選択には既存EC_PAGE_BASEを再利用し、新しい同義フラグを追加しない。

## 捕捉・保持と実行側

- 通常命令：既存M1/T2、WAIT解除・ClkEn成立時にIRと同時確定。
- DD/FD CBの最終命令：既存M7/T2の命令捕捉でも更新。
- フレーム終了のNOP注入：既存のDecode_Execution呼出しと同時更新。
- リセットは従来どおり全0。WAIT／CEN停止時には保持する。
- 追加のTステート、クロック、アドレス／データの捕捉段は設けない。
- レジスタ値・キャリー値・Alternateなどの実行中の値を先取りしない。IRのレジスタ番号など、単純なオペランドフィールド配線は残す。
- mcodeのPUSH/POP・絶対ペア転送・絶対バイト転送・PEAの拡張実行分岐でも、静的な命令／ペア比較を保持制御へ置換。

## 分離の到達点と残項目

| 範囲 | R31の状態 |
|---|---|
| 有効なデータ幅・ストリーム幅・ADLスナップショット | 既存保持制御を継続 |
| R30の8種類の静的選択 | 保持制御を継続 |
| 今回の11種類の共通判定 | デコードで確定し実行側から参照 |
| 旧T80の主case ISet／case IRB | mcodeに残る。全命令の分類とサイクル制御の完全分離は未完了 |
| 命令ごとのSet_BusA/Set_BusB生成 | MCycleとの組合せ経路が残る |
| レジスタ番号の最終解決と書込み許可 | 一部の後段選択は残る |
| 割込み受付境界のPrefix／Width_Pending判定 | 動的境界のため維持 |
| 分岐条件・WAIT・CEN・BUSREQ・割込み到来 | 実行時に判断する |

R30の報告内CPU最悪はMCycle_2_s0からRegsU書込みCEへ向かい、mcodeのSet_BusB選択とRegAddrA解決などを通る。今回の静的比較の移動はその周辺の選択を整理するが、この経路を解消したとは断定しない。変更した主命令デコード全体の段数を「1段」などとは表現しない。

次の対象は旧T80の主命令分類を静的な命令記述へ変換し、MCycle別の制御生成へ渡す部分。ただし一括で巨大な制御語を保持する方式や命令数分のone-hot化はLUT／FF・配線が増える可能性があり、分類の共用を保って段階比較する。

## 検証と限界

1. GHDL合成：通常／診断／拡張無効の3構成。VHDL93でも6ファイルを解析。
2. mcode新旧比較：Mode0、256命令×4ページ×4XY状態×32幅／ADL／拡張条件×7MCycle×3割込み条件×2分岐条件。5505024条件で全49出力を比較。Interrupt_Modeは条件番号mod3で与える代表的な組合せ。条件フラグFはA5／5Aの代表値であり、F全256値の総当たりではない。最終命令と記述子が整合する組合せの比較で、プレフィクス途中の時系列証明とは分ける。
3. 実際のCOM30本：SDRAM RTLを含むモデルでR30と54MHzクロックの立上り・立下りごとに外部バスを比較。通常はCPU_DIV4・PHASE0。MR4では専用トレースMUXとメモリ履歴を接続した比較モデルを使用し、トレース選択値も新旧で比較する。
4. 10本をCPU_DIV4・PHASE3・CEN停止ありで比較。SDRAM待ちを含む。
5. 幅プレフィクス64ケース：通常32＋WAIT／CEN停止32。保持監視幅は73bit全体。

COM試験のDOS表示モデルは内部でEIするため、拡張アクセス中にDOS／BIOSのEIが影響する条件も従来どおり考慮する。COM自体は更新しない。

以上はRTL由来のゼロ遅延モデル。R31のGOWIN合成後論理、配置配線、LUT・FF使用量、Setup/Hold、実機は未確認。追加11bitが物理FFとして11個増えるとは事前に断定しない。タイミング例外・制約緩和による違反隠しは行わない。
