# R24.2 即値・絶対・間接／インデックス指定ロードの共通コミット

## 対象と基準

R24.1の24bitレジスタI/Fを基準にする。実機で確認済みの基準はR24（Logic97%、指定COM/RUNALL全PASS、SOFARUNゲームPLAY）。R24.1およびR24.2のGOWIN/実機結果はこの資料作成時点で未確認。
GSR利用は保留。CPUの拡張有効・Mode0でのみ新経路を使い、拡張ロック中の通常Z80ロード経路を維持する。

| 取得元 | 主な命令 | 最初のデータ読出しサイクル |
| --- | --- | --- |
| 命令内即値 | LD BC/DE/HL/IX/IY/SP,即値 | M2 |
| 絶対アドレスのメモリ | LD BC/DE/HL/IX/IY/SP,(nn/Mmn) | M4またはM5 |
| HL間接 | LD rr,(HL)、対応するIX/IY読出し | M2 |
| IX/IY変位間接 | LD rr,(IX+d)/(IY+d)、対応するIX/IY読出し | M3（M2は変位） |

例: LD BC,(IX+d)はDD 07 d。LD rr,(nn)では先にアドレスの2/3バイトを取得し、その後のデータ2/3バイトだけを共通ワークへ集める。命令中の即値アドレスと、メモリから読み出すデータを混同しない。

## 実装

1. 本命opcodeの受理時にDecode_ExecutionでLOAD_IMM/LOAD_ABS/LOAD_INDを確定し、Exec_Controlに保持する。
2. M1/T3で書込み先3bit、SP選択、最初と最後のデータサイクル番号を保持する。
3. 既存のData_Long/Stream_Long FFを命令の有効幅として使う。実行途中でADL/プレフィクスを再解釈しない。
4. 対象データのT3で、EX_SP_Readワークの下位／中位／上位バイトを収集する。
5. 最後のデータT3で、保持した書込み先とバイトマスクを共通24bit書込みI/Fへ渡す。SPは保持したSP選択とデータ幅によりSPS/SPまたはSPLを更新する。

最終バイトは同じ立上りで初めてワークへ格納されるため、そのバイトを直接コミット値へ合成する。古いワーク上位バイトを参照する誤りを避け、追加T-stateを設けない。2バイト取得時は現在のDIを中位として合成し、3バイト取得時は現在のDIを上位として合成する。短幅即値で3バイト取得する場合は上位取得データを捨てる。

Exec_Controlは50bitから53bitへ拡張し、bit50=LOAD_IMM、51=LOAD_ABS、52=LOAD_INDを追加した。書込み先/最初/最後各3bit＋SP選択1bitでソース上10bitの保持を追加。3個の新しいデコードビットを合わせて最大13bitのソース上のFF増であり、実合成後のFF数ではない。24bitデータワークは既存のEX_SP_Readを共有する。

Mode0の対象ロードでは旧Read_To_Regのバイトごとの遅延書込みを停止する。上位側の旧イベント0/7もMode0では使わず、一括コミットへ置換する。POP、ストア、EX(SP)、演算、ブロック転送等は今回の一括ロード対象外であり、従来経路を維持する。

## 幅の区別

| suffix | 即値の取得 | 絶対アドレスの取得 | 絶対／間接ロードのデータ取得 |
| --- | ---: | ---: | ---: |
| SIS | 2バイト | 2バイト | 2バイト |
| LIS | 2バイト | 2バイト | 3バイト |
| SIL | 3バイト | 3バイト | 2バイト |
| LIL | 3バイト | 3バイト | 3バイト |

上位の保持・ゼロ拡張はR24の結果を維持する。即値LISは24bitへゼロ拡張、即値SILのGP上位は0、即値SISのGP上位は保持。絶対／間接の短幅読出しではGP上位を保持する。SP短幅ロードは16bit SPだけを更新しSPLを保持、長幅ロードはSPLだけを更新する。上位未定義の本家仕様に対しても、この実装が従来選んでいた値を変更しない。

## WAIT・CEN・割込み

データの受理は既存バス制御に従い、T2でWAITが解除されて進んだT3で収集する。WAIT保持中のT2ではワークや収集段階を進めない。CEN/ClkEnが止まれば保持し、レジスタの実書込みも止まる。レジスタ書込み先は読出しMUXの選択番号から切り離してあるため、その読出し選択が0へ戻っても別レジスタへ誤書込みしない。

MCycles/TStates、PC進行、メモリ要求、割込み/NMI受付の制御は変更しない。途中で要求された割込みは元の命令完了境界で扱う。命令完了前の部分ロード値をアーキテクチャレジスタへ公開せず、最後のバイトでまとめて更新する。

## ワーク共有の根拠

EX_SP_Readを書き込む新ロード群とEX(SP)の同時有効化を、Decode_Executionの524288入力（全4 Mode、拡張/ADL/有効幅/明示幅、全ページ/XY/opcode）で検査した。新ロード3クラスは互いに排他的で、EX(SP)用クラスとも重ならない。

割込みフレームが使う別のワークや、間接アドレスを保持するEX_SP_Address、ストアデータを保持するEX_SP_Sourceは共有対象へ混ぜていない。

## 検証

- 取得元3系統、GP5組＋即値/絶対SP、4幅を組み合わせた68ケースを通常/WAIT・CEN停止で計136ケース確認。SP/SPL分離、上位保持/ゼロ拡張、A/F維持、IX/IYと変位を確認。
- R24の実RTLシャドウCPUと、次命令取得境界で全8組の下位16bit・全64bit上位・SP/SPL/A/Fを比較。PCと外部バス制御・要求アドレス、有効WRデータは毎クロック比較。無効時のDO値と、意図して変更した命令途中の部分値は等価条件にしない。
- 9系列/条件で2773回、68ケースのストレス行列で544回、合計3317回の収集・コミットを比較。途中の部分書込み禁止、捕捉先保持、受理バイト数、SPルーティングをassertで検査。
- 書込み先を0へ誤固定した故障注入が、保持先不一致として検出されることも確認。
- EZ80MEM実COM9条件、MR4実COM8条件、LDH/LDX各6条件、MADL26ケースと混在64ケースの通常条件（各故障検出2条件も含む）、PFX/IM0/DEC実COMの通常/CE停止条件、幅寿命64ケース、VHDL-93解析を確認。

MADL/混在の全ケースを3種類のストレス条件で走らせたものではない。LDH/LDXのWAIT・CEN停止・IM1/NMIと、新行列のストレス条件は別に実施した。これらはCPU/ラッパとメモリモデルの検証であり、実BIOS/DOS/VDPを含む実機の代用ではない。

検証の条件・ログ・ソースSHA256はverification_r24_2。再実行はtools/verify_release_r24_2.py。過去版のverify_reg24_differential.py等の途中状態一致条件は、一括コミット方式には適用しない。

## 規模と実機確認

メモリブリッジ、SDRAM、16bit/24bitアドレスバス分離、ラッパ、top、GPRJ、制約はR24.1と同一。$FFFFのMSXセカンダリスロット遮断も維持する。既存34 COMとRUNALLは変更しない。

LUT/FF/CLS/Fmaxの新しい実測値は未取得。R24.1で示した読出しMUXだけの概算96 LUTは、R24.2全体の削減保証ではない。今回の収集・保持・コミット制御との差引を同じGOWIN設定で配置配線して比較する。GSRや制約緩和は混ぜない。新規フォルダでビルドし、READMEの順序で実機確認する。
