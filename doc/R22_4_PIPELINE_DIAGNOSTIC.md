# R22.4 メモリデータ経路の診断

R22.3で実機停止が消えた一方、010100の31→00、CE→08が残ったための観測版。
原因修正済み版ではない。CPU命令制御、バス分離、要求ハンドシェイク、WAIT、SDRAMスケジュール、SDC/CSTは維持。
過去事例との対応は `R22_4_MEMORY_HISTORY.md` を参照。

## 実機手順

1. このZIPを新規フォルダに展開し、`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj` を合成・配置配線する。
2. この版で生成したイメージを書き込み、再起動する。
3. **まず `EZ80MR6 /RUN` を実行し、出力全文を撮影する。** 010100の2行に絞った診断。
4. MR6がPASSなら `EZ80MX6 /RUN` を実行し、最終結果と不一致の行を報告する。
5. フリーズした場合は最後の表示を記録し、R22.3と同じLED/S2手順で停止状態を確認する。
   リセットはLED記録を消すので撮影後に行う。

MR6とMX6は今回新規。従来のMR5/MEM等のCOMはそのまま同梱。
旧FPGAでは新しい診断識別値がないためNOT READYとなる。
MR6は4916 bytes、CRC32 D7F12C22。MX6は37796 bytes、CRC32 EEC5294B。
MX6は通常のDOSプログラム領域を約38KB使用する。ADLコード実行やRST、反復I/O命令は使わない。

## 試験の2方式

| 行 | 書込み | その後 |
|---|---|---|
| G、EXP=31 | 24bit絶対指定 | 拡張をロックしてDOS表示→DI→再解除→絶対読出し2回とHL間接読出し2回 |
| B、EXP=CE | 24bit HL間接 | 書込みから4回の読出し・観測記録のコピーまでDOS呼出しなし |

各行の前のBEGIN表示も拡張ロック状態。DOSがEIすることを想定し、復帰直後にDI。
PC/SPはZ80のまま、MBASE=0。呼出し元のIX/IY/SPを維持して最後にEIでDOSへ戻る。
診断I/Oは既存のE7E7窓だけを使い、E2..EFはその窓の**セレクタ値**。物理のE2..EFポートへのアクセスではない。
D8は診断窓を有効にするが、IRQ/NMI注入コマンドは使わない。DOS前にロックして無効化する。

MX6は010100/101/102/103、070100、07FFFE、07FFFF、080000、0A6000の9アドレス×2方式、18行。
すべて予約済みの拡張私有RAMを破壊的に試験する。MSXのFFFFhやmapper/VRAM/MegaRAMへは到達させない。
全byteを元に戻すメモリ保存試験ではないため、作業データをこれらの予約領域に置かない。

## 出力の読み方

| フィールド | 意味 |
|---|---|
| A1/A2 | CPUの絶対読出し値2回 |
| I1/I2 | CPUのHL間接読出し値2回 |
| HL | 間接読出し後の24bit HL保存値 |
| W=物理アドレス/値 | ブリッジが最後に受理した書込み要求 |
| R=物理アドレス/値 | ブリッジの保持アドレスと返答値 |
| CAP | SDRAMコントローラが書込み要求を捕捉した時のデータ |
| CMD | 拡張書込みスロットのコマンド観測時のSdrDat下位byte（全レーンへ同じbyteを出す設計） |
| RAM | 最後の拡張読出し完了エッジで観測したRamDbi |
| RET | SDRAMコントローラのext_dout保持値 |
| DQ1/DQ2 | 既存RamDbiの早い／遅い2捕捉エッジに対応する、選択byte laneの内部DQ観測 |
| WCAP | コントローラが捕捉した最後の書込み物理アドレス |
| CTL | 書込み観測時のbank[1:0]、lane[1:0]、DQM[3:0] |
| VALID | bit0書込み捕捉、1書込みスロット、2DQ1、3DQ2、4読出し完了、5書込みowner=拡張、6WRITEコマンド一致、7予約 |
| COL | 書込み観測時のカラム下位8bit |

VALIDはリセットからの観測イベントのフラグであり、DQのデータ有効を保証する信号ではない。イベント数やFIFOではなく、各項目の最後の観測を保持する。
書込みCMD/CTL/COLはff_sdr_seq=3で、登録済みコマンド・データ・DQMの更新前値を観測する。
SDRAM外部ピン上の到達時刻、実セル書込み成立を独立に測定しているわけではない。
DQ1/DQ2は観測値として表示する。両方の値がEXPと一致することを単独の合否条件にはしない。
現行の機能回路がどちらの値を最終的にRamDbi/RETへ渡したかと併せて見る。

010100の場合、物理アドレス650100、bank=3、lane=0、DQM=E、CTL=CE、COL=28が目安。
G行の正常例: W=650100/31、CAP=31、CMD=31、RAM=31、RET=31、R=650100/31、A1/A2/I1/I2=31。
B行はCEへ置き換える。VALIDの正常な全観測後の値は7F。

| 不一致の位置 | 次の調査対象 |
|---|---|
| Wが正しいがCAP/WCAPが違う | 送信ラッチから受信サンプル／トランザクション保持まで |
| CAP/WCAPが正しいがCMD/CTL/COLが違う | 所有権、データ／bank／byte lane／マスク選択、出力保持 |
| CMD等は正しいがDQ1/DQ2/RAMが違う | 実書込み、読出しアドレス、SDRAM応答、捕捉位相 |
| DQ1は正しくDQ2/RAMが違う | 後の捕捉による上書きや有効期間を優先確認 |
| RAMとRETが違う | コントローラ完了時の保持 |
| RETは正しいがRが違う | 返答の保持・同期とブリッジ捕捉 |
| Rは正しいがCPU値が違う | CPU入力選択、ラッパDI_Reg、CPU取込み |

ADDR/EXP/ACTの最終行は最初に不一致となった検査を示す。CAP等の内部検査が最初の場合もあるため、同じ行の各フィールドを確認する。
観測回路追加で配置配線が変わるため、PASSに変わっても根本原因解消やタイミング収束とはみなさない。

## 観測回路の接続

コントローラの新しいTRACE_PIPELINEパラメータは既定0、実機topでは1。
追加レジスタは観測出力にだけ接続し、機能制御へ戻さない。既存のWAIT保存回路も維持。
既存F0..F7/FD/FEの診断互換を維持し、E2..EDへ96bit観測の12byte、EE/EFへ識別5B/A4を割り当てる。
ラッパにTrace_Pageを追加し、byte選択はVerilog側の共用muxへ置く。命令デコードや実行段の追加ではない。
追加FFとmuxの実資源量・配置・STAはGOWIN実行前には確定しない。

## シミュレーションのDQモデル

既存SDRAM機能モデルは、有効データを駆動する前後でDQをZにする。新しいDQ1観測はこの未駆動期間に当たり得る。
実機のFFはデジタル値を返すが、その値は保証されないため、DQ1単独を合否条件にしない。
新COM用の統合試験にはDQへの弱いpulldownを置き、未駆動観測を00として扱う。これはテストベンチだけの電気的仮定で、FPGAにpullやデータ置換を追加するものではない。
有効なコントローラ／SDRAMモデルの強い駆動は優先される。CPU状態がXになった試験は即FAILとする。
正常モデルの例はDQ1=00、DQ2=EXP、RAM=EXP、RET=EXP。実機のDQ1が00になるとは主張しない。
