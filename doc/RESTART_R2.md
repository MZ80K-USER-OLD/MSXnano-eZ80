# 再構築R2：24bit INC/DEC、独立SPによるPUSH/POP、メモリ診断

## 出発点と変更

R1を基準とする。R1の元T80、MSX周辺回路、メモリブリッジ、SDRAMコントローラ、
GOWINプロジェクト設定と制約は変更しない。CPUのcoreとmcodeに機能を追加する。
GOWINでのR1実機動作（SofaRun、スペースマンボウ、EZ80D1 PASS）はユーザー報告として記録する。
R2実機動作はまだ確認していない。

| 項目 | R2 |
|---|---|
| BC/DE/HL/IX/IYのINC/DEC | 明示.L系で下位16bitのキャリー／ボローを上位8bitへ反映 |
| SPのINC/DEC | 明示.L系は独立SPLを24bit更新。短い命令は従来のSPS |
| BC/DE/HL/IX/IYのPUSH/POP | 明示.L系は3バイト、独立SPL。通常のSPSは変更しない |
| AFのPUSH/POP | .L系は[F,A,00]の3バイト。POPは上位1バイトを読み捨てる |
| .SIS/.SILのスタック | 従来の2バイトSPS。次の命令へ幅を持ち越さない |
| PC・割込み・CALL/RET | 従来の16bit Z80。ADL割込み・24bit制御フローは未実装 |

.LISと.LILはデータブロックが長いので、上記PUSH/POPでSPLを使う。
この段階ではモード遷移を実装していない。明示プレフィクスによる単一命令の機能追加。
一般的な24bit ADD/SUB、LD SP,HL、EX DE,HL、絶対24bit命令群などはまだ対象外。
未対応のプレフィクス付き命令を検出するトラップはないので、対応済みとして使用しないこと。

### フレームと捕捉

PUSHは上位→中位→下位の順で1バイトずつ書き、各回のSPL減算は24bitで行う。
最終SPLが指すアドレスには下位バイトがある。POPは下位→中位→上位を読み、各回SPLを加算する。
アドレス上位と下位を同じT_Resで登録する。WAIT中に更新を繰り返さない。
INC/DECの上位更新は、既存T80の下位16bitを書き込むエッジと合わせる。
メモリ要求の登録と保持、VDP優先、CPU WAITはR1のまま。

### ED命令直後のプレフィクス修正

R1のプレフィクス捕捉は前命令のISetを参照していたため、完了したED命令の次に置いた
5Bhなどをプレフィクスとして捕捉できない場合があった。
次に読むバイトの命令体系を、直前のPrefix出力から判定するように修正した。
ED命令の第2バイトをプレフィクス扱いしない一方、完了後の新しい命令のプレフィクスは捕捉する。
R2のAF試験（ED 43で期待値保存→5B F5）で検出し、修正後の全試験で確認する。

## EZ80D2.COM

実体の生成元は `hardware_test/build_data_r2.py`。COM・hex・解決済みDEFBリスト・ラベルJSONを同梱。
R1用COMとは別名。実機では、このR2のビットストリームと組み合わせて使う。

| stage | 試験 |
|---|---|
| 1 | 01..1Bの27バンクへ別パターンを書き、逆順に読み出す |
| 2 | BC/DE/IX/IY経由のバイトアクセス |
| 3 | インデックス変位の64KiBキャリー／ボロー、高位FFFFhとMSXの分離 |
| 4 | 4種プレフィクスの即値長とデータ幅、命令間の幅漏れ |
| 5 | SPLのロード・3バイト読出し、SPSの不変性 |
| 6 | BC/DE/HL/IX/IY/SPLのINC/DEC。64KiB境界、FFFFFFh→000000h、逆方向、通常値 |
| 7 | 5組の.LIL/.LIS PUSH/POP、64KiBをまたぐSPL、AFの3バイトフレームと復帰 |
| 8 | .SIS/.SILの通常スタック、SPL不変性とSPSの保存、通常CALL/RET |

stage6のペア値は、SPL=060103hへPUSHしてメモリ上の3バイトを別のHLアクセスで確認する。
PUSHとPOPの誤りが互いに相殺してPASSにならないよう、stage7ではPOP前のメモリ内容と
POP後のレジスタを再PUSHした結果の両方を確認する。
SPLの境界試験では050001hからPUSHし、050000h、04FFFFh、04FFFEhの順で書き込む。
POP後は050001hへ戻ることを読出しで確認する。

### アドレス・期待値・実際値

全てのメモリ比較には、意図した24bit論理アドレスと、1バイトの期待値／取得値を対応付ける。
不一致を検出した時点で取得値を保存し、最初の不一致について以下の形式で表示する。

```
EZ80D2 R2: FAIL stage 7
ADDR=04FFFE EXP=56 ACT=57
```

この例は故障注入シミュレーションの結果であり、ユーザー実機の観測値ではない。
ADDRはテストの要求先。CPU内部やSDRAM端子が本当にその値だったとの観測ではない。
物理アドレスは、専用RAMでは論理アドレス+640000h。例：04FFFEh→68FFFEh。
取得値ACTは比較に用いた最初の読出し値で、再読出し値で置き換えない。
レジスタ単体比較の不一致はADDR=------。期待値と実際値は同じ形式で表示する。
正常時は各アクセスを逐次表示せず、最後にPASSだけを表示する。

### DOS／BIOSのEI

DI区間ではシステムコール・BIOSコールを一度も行わない。
全出口は拡張ロック→通常Z80の16進変換→EI→BDOS9→IX/IY復帰→DOSへRET。
診断の変換に使うCALL/PUSH/POPも通常のSPSだけを使用する。
BDOS9のモデル内でも明示的にEIする。呼出し前のDIが維持される前提を置かない。
拡張が解除されている間にIFF1が有効になった場合はテストベンチが失敗する。
NMIとADL割込みは対象外。通常のMSX-DOSコマンド入口での割込み許可状態を前提とする。

### 破壊するRAM

- R1と同じ：018000h、028000h、…、1B8000h（各1バイト）。
- 020100h..020103h、030000h、02FFFFh、01FFFFh。
- 060100h..060102h：ペアの3バイト確認用。
- 04FFFEh、04FFFFh、050000h：3バイトスタック試験用。
- 低位MSX空間：COM自身のバッファと通常のSPS。

VRAM/MegaRAMをこのCOMから書き換えない。専用RAMの既存データを保存するテストではない。

## 制約と検証の範囲

R1の制約を変更しない。証明できないmulticycleは無効のまま、新規false_pathも追加しない。
実際のGOWIN違反経路と捕捉・保持期間の照合は、R2の配置配線後レポートで行う必要がある。
周期を広げて違反を消す対応は行っていない。

今回の結果は `verification_result.json`。元T80とのロック状態比較16ケース、
実COM実行8ケース（正常4位相・バンクの誤共有・読出しデータ破損・スタック書込み破損・拡張無効）。
故障注入ケースでは、FAILだけでなくADDR/EXP/ACTの文字列も照合する。
R1のメモリ26ケースは今回再実行せず、同一メモリRTLを使う回帰の参考とする。
実COM試験には今回のCPU、メモリブリッジ、SDRAMコントローラ、SDRAMモデルを含む。
低位メモリとBDOS9は簡易モデル。実MSX-DOS全体／BIOS起動完了のシミュレーションではない。
GHDL変換と部分Verilog構文確認はGOWIN合成・配置配線の代替ではない。

## 再生成とチェック

CPUを元T80から再生成する場合は、順に実行する。

```
python3 tools/rebuild_from_t80.py
python3 tools/extend_r2.py
python3 hardware_test/build_data_r2.py
```

GHDL、Icarus Verilog、vvpをPATHへ設定し `tools/run_checks.sh` を実行する。
実機でPASSを確認するまではADLフェッチや割込みへ進めない。
