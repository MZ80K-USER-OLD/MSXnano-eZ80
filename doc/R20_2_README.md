# R20.2 — 診断SLP解除の修正候補と進行表示テスト

ユーザー報告は、EZ80SLP /RUNでフリーズ、EZ80REF /RUNで画面が乱れる、です。今回使用したビットストリームのタイミングレポート/ネットリストは未受領です。実機原因は未確定で、R20.1/R20.2を安定版とは扱いません。最後の実機確認済み基準はR19.1です。

## コードで確認・再現した問題

R20/R20.1の診断解除はカウンタ終端の1回だけ発行し、CPUが受け付けたことを確認せずD5（完了）へ進んでいました。解除入力を1回抑止する故障注入では、旧版がSLPから戻れず停止し続けることを再現しました。

R20.2では、既存のDiag_SelectのD6を「解除要求保留」として使い、要求を保持します。CPUのSleep状態が解除され、次のM1/T2フェッチがWAITなしで受理されてからD5へ進みます。解除待ちに入る時はNMIアームを消し、D6で診断NMIが発生することも防ぎます。

この再現は解除入力を意図的に抑止したモデルです。実機のフリーズや画面乱れがこの条件で発生したと断定するものではありません。通常条件の理想RTLシミュレーションだけでは、報告された実機症状そのものは再現できていません。

変更するFPGAファイルは `fpga/G80A_eZ80/g80a_ez80.vhd` のみです。CPU本体・命令デコード・レジスタ選択・SDRAMコントローラ・top・16/24bitバス分離はR20.1と同じです。CPU全体の停止方式そのものやGOWIN制約を変更した版ではありません。新しいFF/カウンタを追加せず、既存の選択レジスタを共用します。実際のLUT/FF増減・STAは未測定です。

## 最初に実行する新しいテスト

R20.2を新しいフォルダへ展開し、`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj` をビルドしてください。GPRJ、DualPin、SystemVerilog設定、CST、SDCは変更していません。

まず再起動して、次だけを実行してください。

```text
EZ80SL2 /RUN
```

実行中に `CASE 0` から `CASE 3` を表示します。期待する最後の表示は `EZ80SL2 R20.2: PASS` です。

| CASE | 命令ストリーム | MADL | 診断IRQ |
|---|---|---|---|
| 0 | Z80 | 0 | なし |
| 1 | Z80 | 1 | 保留＋EI直後にSLP |
| 2 | ADL | 0 | なし |
| 3 | ADL | 1 | 保留＋EI直後にSLP |

PASSを確認後に、長時間側を実行してください。

```text
EZ80RF2 /RUN
```

`CASE 0`（Z80）、`CASE 1`（ADL）を表示し、最後は `EZ80RF2 R20.2: PASS` が期待値です。どちらもMADL=1で、108MHzなら約70〜73msの長時間診断SLP後にメモリを照合します。

停止/画面乱れが再発したら、最後に読めたCASE番号、FAILならStage/ADDR/EXP/ACTを記録してください。CASEが一つも出ない、NOT READYになる、といった情報も切り分けに使えます。

| ファイル | バイト数 | CRC32 |
|---|---:|---|
| EZ80SL2.COM | 5178 | 4692989D |
| EZ80RF2.COM | 3537 | FB95EAF3 |

名前を変え、R20.2識別値F2=01/F3=FEを確認してから停止試験へ進みます。旧ビットストリームや診断なしはNOT READY、拡張なしはUNSUPPORTED、/RUNなしはREADYです。従来COM30本は変更せず、新規2本を加えた32本をテストZIPに収録します。既存RUNALL.BATには新テストを追加していません。

## テストの構成とDOS割り込み

進行表示は、Z80/MBASE=0・MADL=0、元のDOSスタック、診断停止・拡張ロックへ戻した状態で行います。表示前はEI、DOSから戻ったらDIをやり直し、アンロック/診断設定を復元してから次の私有試験へ進みます。私有SLP中にはDOS/BIOSコールを行いません。

短時間/長時間ともAF、SPS/SPL、解除完了記録を照合します。長時間側のデータ期待値は030000=96、03FFFF=C9、07FFFE=31、07FFFF=52、080000=A6、0EFFFF=5Aです。メモリの失敗はStage/ADDR/EXP/ACTを表示します。コード/結果は0A:6000/7000/8000/8100と0E:8200、SPLは05:0001近傍です。私有領域のデータは上書きします。MSX/DOSベクタ、VRAM/MegaRAM予約領域は書き換えません。

通常SLPの復帰は引き続きRESETのみです。D3/D7/D6は診断専用解除の仕組みで、通常のIRQ/NMI復帰ではありません。SLP中のSDRAM更新はR20.1の処理を維持します。メモリ保持COMのPASSだけで全行の更新周期や電気的保持を証明するものではありません。

## 検証

`verification_r20_2/summary.json` とログを収録します。

- 旧R20.1モデルへ解除入力1回抑止を注入し、戻らないことを確認。
- 新しい2本の実COMで、通常、故障検出、READY、UNSUPPORTED、旧版/診断なしのNOT READY、解除入力1回抑止を確認。D6保留と次フェッチ受付を各SLPについて監視。
- クロックモデルは100/50/25MHz、外部CPUクロック入力とPINFILTER/エッジ検出による不均一CENを使用。PINFILTER内部のZは直前の二値レベルを保持する抽象化を行っています。GOWIN合成後の回路やクロック位相を完全再現したモデルではありません。
- 長時間COMのシミュレーションではタイマー入力をFreeCounter[8]へ接続し128倍速めます。実機のFreeCounter[15]と同様、タイマー立ち上がりがリフレッシュ周期境界に重なる位相を保ちます。実際の約70ms停止を実COMシミュレーションで再現したという意味ではありません。
- 従来SLP/REF、MEM、RW2、NMI診断、ロック互換性、VHDL-93、topのCPU/メモリ/ブリッジ接続、通常モードのSDRAMピン比較を回帰。
- SDRAM単体では83.9ms/8192回の更新とVDP/CPU要求の機能試験を再実行。モデルは電荷漏れや全電気タイミングを再現しません。

GOWIN実行、使用率測定、実機PASS、タイミング収束は未確認です。シミュレーションでの解除遅延への対策と、実機症状の原因確定を区別してください。
