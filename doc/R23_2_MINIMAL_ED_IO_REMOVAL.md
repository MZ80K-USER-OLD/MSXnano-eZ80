# R23.2 — R21.3からEDページだけを変更するI/O削除比較版

2026-11-21。I/O削除を優先し、レジスタ再構成・全FF化は実施しない。

## 基準

R21.3はユーザーによる再ビルド後、EZ80MEM、EZ80MR4、RUNALL全項目、SOFARUNからスペースマンボウの起動・PLAYが成功。今回のimplではLogic19439/20736（94%）、LUT17208、Register7393。

R23.1は4命令のマイクロコード削除に加えて、CPU本体のBlock_IO2補助判定、フラグ処理、通常処理の抑止条件、分類関数を整理した版。実機ではIONのCASE0停止とMEM異常が報告された。原因は未確定。LUTは17287へ増加した。

今回はR23.1を修正せず、保存済みFPGA SHA-256一覧と一致するR21.3から再作成した。

## FPGA差分は2ファイルだけ

| ファイル | 変更 |
|---|---|
| t80_mcode_ez80.vhd | ED84/8C/A4/ACを既存のNOP行に追加し、通常ブロックI/O行からその4番号を外す |
| g80a_ez80.vhd | 旧IO2対応識別F8/F9を01/FEから00/FFへ変更。旧IO2テストの誤実行を防止 |

CPU本体t80_ez80.vhd、分類関数t80_pack_ez80.vhd、レジスタファイル、ALUはR21.3とバイト一致。メモリブリッジ、SDRAM制御、top、トレースMUX、GPRJ、CST、SDCもバイト一致する。

**R23.1で行ったCPU本体の簡略化は、この版には入っていない。** 通常Z80のIN/OUT・ブロックI/Oは保持する。

INI2/IND2/OUTI2/OUTD2は実行時にI/Oもレジスタ更新も起こさないNOPになる。INIRX/INDRX/OTIRX/OTDRX/TSTIOは追加しない。R21.3で未実装だった追加I/Oも引き続き未実装。SLPはNOP、未定義命令TRAPは非対応。

### 専用回路の完全除去とは分ける

今回の目的は、EDページ内の実行停止だけなら、基本メモリ動作を維持できるかの確認。CPU本体のBlock_IO2判定、Opcode_Class(8)のIO2番号、パッケージの分類、到達しなくなったマイクロコード分岐は意図的に維持している。

したがってこれは機能削除の最小差分比較版であり、すべての専用論理をソースから除去した最終削減版ではない。合成が到達不能な分岐をどこまで削除するか、最終LUT/CLSが減るかはGOWINで測定する。回路が減ることやメモリ不良が解消することを保証しない。

この版で実機が安定すれば、次に分類・補助制御を一つずつ整理して比較する。失敗すればCPU本体の簡略化を持ち込んでいない状態でも再現したことになり、EDデコード変更が共有論理・配置・捕捉タイミングに与えた影響を絞れる。

## テストプログラム

新しいCOMは作成せず、既存のEZ80ION.COMをそのまま再利用する。

| COM | bytes | CRC32 | 期待表示 |
|---|---:|---|---|
| EZ80ION.COM | 14730 | 89950529 | EZ80ION R23.1: PASS |

表示中のR23.1はCOMの版番号であり、今回のビットストリームR23.2と異なるのは正常。8ケースで4命令のZ80/ADL実行、AF/BC/DE/HLと両スタックを検査する。DOSのEIを想定し、表示時はZ80/MBASE0・拡張ロックへ戻し、DOS復帰直後にDI。メモリ不一致時はADDR/EXP/ACTを表示する。

R21.3の既存32本のCOMは不変。IONをルートとhardware_testに同梱。RUNALLから旧EZ80IO2を外してIONを追加した。旧IO2は手動実行するとNOT READYが正常。

## 実機での確認順序

1. 新規フォルダに展開し、`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj`で合成から配置配線まで実行する。以前のフォルダへ上書き混在させない。
2. 新しいイメージを書き込み、電源を切って入れ直す。
3. **EZ80MEM /RUNを最初に単独実行**。PASSするまでIONを実行しない。
4. EZ80MR4 /RUN。PASSならEZ80ION /RUN。
5. RUNALL.BATとSOFARUNからのスペースマンボウ起動・PLAY。
6. Logic/LUT/CLS/Registerとimplを保存する。

正常表示:

```
EZ80MEM P1: PASS
EZ80MR4 R21.3: PASS
EZ80ION R23.1: PASS
```

MEMでFAIL/FATALなら、そのStage/ADDR/EXP/ACTを保存し、次の試験へ進まない。停止後の状態と単独試験の結果を混同しない。

## 検証の範囲

新CPUをGHDLで変換して再実行した結果はverification_r23_2/summary.jsonとログに収録する。過去の検証資料は履歴であり、新版の合否を示さない。

- R21.3とのマイクロコード比較: Mode0〜3、各458752入力。意図した4命令の拡張ED条件を除外し、それ以外の出力を比較。
- 削除NOP: 160ケース。Z80/ADL・幅指定・WAIT/CE停止、I/Oなし・レジスタ不変。既にNOPだった4反復opcodeも含む。
- 実COM: MEM9条件、MR4の8条件、IONの7条件。故障注入やNOT READY等、期待した異常終了を含む。
- VHDL-93の6ファイル解析。

**本版のGOWIN合成、規模、配置後タイミング、実機動作は未確認。** ローカルシミュレーションはGOWINの遅延やMSX/Nextor/VDP全体を再現していない。

16bit MSXバスと24bit拡張バスの分離、既存WAIT、VDP優先は維持。MBASE連動窓、24bit加算器統合、レジスタFF化、タイミング制約の一律緩和は今回行わない。
