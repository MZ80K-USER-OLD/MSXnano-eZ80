# R24.1 24bit読出し・書込みインターフェースと選択回路の共通化

## 方針

実機確認済みR24を比較基準にする。GSR利用は保留。一般レジスタの格納方式やCPUの実行タイミングを変更せず、I/Fと選択回路の共通化を先に評価する。

## 変更

- t80_reg_ez80.vhdに下位・中位・上位バイトの格納を集約し、DOA/DOB/DOCを24bit化。
- DIを24bitとし、WMask[2:0]で上位／中位／下位バイトの更新を選択。
- 読出しA/B/Cと書込みAddrWを分離。命令の遅延したバイト書込み先を維持する。
- 上位8bitの任意読出しはA/B/Cと補助Uの4ポートへ整理。補助UはPUSH・絶対転送の上位バイト出力用。
- ADD/ADC/SBC、INC/DEC、インデックス計算、JP(HL等)、LD SP,HL、間接転送、EX(SP)等が同じ24bit読出し結果を使う。
- EX DE,HLの上位バイト同時交換は従来どおり維持。通常書込みが交換より優先する元の順序も維持する。

下位・中位のリセットなし配列、上位の非同期ゼロ初期化を別プロセスのまま保持する。RAM/FFを一律に全FF化しない。PC・SP・SPLはこのレジスタファイルへ統合せず、従来のまま。幅16bit時の上位保持・ゼロ設定は元の命令別制御を維持する。

## 書込みアドレスに関する重要な検出

最初の比較で、LD HL,nnの上位バイト書込み時に旧Upper_Port_Index=2、旧RegAddrA=0となる例を検出した（opcode21h、M4/T3）。下位のバイト書込みはパイプライン経由であり、上位書込み時には読出し側アドレスが先へ進むことがある。

そのため、Upper_Port_Indexを無条件にRegAddrAへ置換する案は不採用とした。最終版は次の関係を使う。

```
AddrW = Upper_Port_WE ? Upper_Port_Index : RegAddrA
```

Upper_Port_Indexの既存の命令別選択を維持する。上下両方へ同時に書く時のアドレス一致は、R24のシャドウCPUに対する検証assertで確認する。これは実行した命令列に対する時系列検証であり、すべての内部状態の形式証明ではない。

## アドレス分離を観測した命令と時点

R24実RTLの追加トレースでは次を観測した。実行した幅指定付き5系列における結果であり、全命令の形式証明ではない。

| 命令 | opcode | 上位書込み時点 |
| --- | --- | --- |
| LD DE,nn / HL,nn / IX,nn / IY,nn | 11 / 21 / DD 21 / FD 21 | M4/T3 |
| LD DE,(nn) / HL,(nn) / IX,(nn) / IY,(nn) | ED 5B / 2A / DD 2A / FD 2A | M6/T3またはM7/T3 |
| POP DE / HL / IX / IY | D1 / E1 / DD E1 / FD E1 | M4/T3 |

上位書込み先はDE=1、HL=2、IX=3、IY=7に対し、下位の読出しRegAddrA=0を観測した。裏DE/HLでは5/6に対し読出し4も観測。いずれもその時点のRegWEH/RegWELは両方0で、上位だけを書き込む。LD HL即値ではData_Long=0/Stream_Long=1で上位を更新するケースも記録された。BCは今回この不一致を記録していない。

LD HL,nnの時系列をR24で追うと、M3ではSet_BusA_To=4、RegAddrA_r=2。M4へ入るとSet_BusA_Toは既定の0になる。M4/T1の立上りでは更新前のRegAddrA=2を使ってHを書き込むと同時に、RegAddrA_rを0へ更新し、直後のM4/T2は0となる。M4/T3でも保持値0のままだが、上位書込み先はHL=2となる。

またRegAddrAの組合せ選択にはT2でINC/DEC用アドレスへ切り替える分岐がある。この例ではM2/T2、M3/T2でも一時的に0となり、T3で保持値2へ戻る。保持レジスタの更新と組合せMUXの出力を区別する必要がある。

これらは内部レジスタ番号。通常のリセットによって0にする操作ではなく、命令サイクルごとの制御による選択変更である。検証ログはverification_r24_1/checks/trace_reg24_addresses（cycle.logは単一命令の時点確認用で、COM全体を完走する試験ではない）。

## LUT削減見込みと限界

基準R24の配置後: Logic19951/20736、LUT17720、ALU1877、Register7431、SSRAM59、CLS10289/10368。

R24合成ネットリストでUpper_RAMOUT名のセルを集計するとLUT3が224個ある。専用MUX2_LUT5が112個、MUX2_LUT6が48個も存在する。専用MUXをLUT数へ二重計上してはいけない。

今回の上位バイト読出しは4ポート×8bit。8:1 MUXを4個のLUT3と専用上位MUXで構成すると128 LUT相当となり、224−128=96 LUT相当が局所的な削減余地になる。

これは均一なMUX構成を仮定した概算であって、新版の合成結果ではない。固定交換回路、入力の共有、補助ポートのアドレス選択、書込みAddrWの追加、ファンアウト、メモリ推論、配置配線による再最適化はこの差分へ含めていない。全体で96 LUT削減される保証や、LUT削減の下限はない。

96 Logic削減が全体でも実現した場合の計算値は19855/20736=95.75%。現在と同様に切上げ表示されれば96%になる。95%表示へ戻すには252 Logic以上の削減が必要であり、この局所概算だけではそこへ届かない。

GOWINはこの環境で実行できておらず、最終LUT/CLS/FF数とFmaxは未測定。GHDL合成は機能モデル生成であって、GOWINのLUT数測定の代用ではない。

## 検証

R24の実RTLをGHDLで変換したシャドウCPUと同じ入力を与え、毎クロックの両エッジ後に次を比較する。

- 全64bit上位レジスタ状態
- PC、SP、SPL、F
- 全外部出力
- 上下同時書込み時の旧アドレス一致

data_r3／mem_r4／alu_r5／blk_r6／lea_r8の5系列で比較。8種類の通常上位書込みイベント全てとEX DE,HL交換を通過する。LDH/LDXでは長幅・短幅・全プレフィクス・境界跨ぎ・WAIT・CEN停止・IM1・NMIを検証する。メモリ実COMの異常検出、混在CALL/RET/RST、MADL、EZ80DECも検証対象。

検証条件・ログ・対象SHA256はverification_r24_1を参照。SMOKE条件で実施したMADL/混在試験は通常クロック条件の全ケースであり、全ケースを3種類のストレス条件で再実行したものではない。

## 比較時の採否

同じGOWIN設定で配置配線し、Logic/LUT/ALU/SSRAM/FF/CLSと詳細Setup/Holdを比較する。GSR・制約・メモリコントローラ変更を混ぜない。規模やタイミングが悪化した場合はR24へ戻せるよう、R24_to_R24_1.patchを同梱する。実機の確認順序はREADME参照。
