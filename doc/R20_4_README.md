# eZ80 restart R20.4 — SLP解除回路の合成接続を確認する候補版

## 状態

実機でSL2/RF2がCASE 0に停止したR20.2を対象にした修正候補です。GOWINでの再合成・配置配線と実機は未確認です。修正済み・タイミング達成済みとは判定していません。最後の全体実機確認済み基準はR19.1です。

R20.3は別配布のSLPをNOPへ置き換えたEZ80SP0診断プログラムだけで、FPGAリリースではありません。

## 提供されたファイルの確認結果

`fpga.zip` 内のCPU VHDL 6ファイル、top_ez80.v、tang20k.sdc、project_eZ80/MSXNanoTang20K_eZ80.gprj は、配布R20.2とバイト単位で一致しました。利用者のファイル取り違えは確認されていません。

`impl(20261115-024004).zip` 内の合成ネットリストで、cpu1/u0/Sleep_FF_s0 のQはcpu_sleep_state、Dはn15033_7、CEはSleep_FF_5でした。n15033_7はcounter_reset[19]、counter_reset[20]、n114_7のNAND、n114_7は上位階層のリセットカウンタ由来です。D6の解除要求がSleep_FFを0へ戻す接続になっていません。CEは `CEN and ((not D) or ENTER)` です。D=1の場合、CEで保持を解除しても0は書けません。

これはRTLの期待動作と不一致です。GOWINの原因箇所、合成内部の処理、ビルド生成物の状態までは特定できていません。「GOWINの既知バグ」とは判断していません。今回のフリーズを説明する有力な不一致ですが、実機修正確認までは原因確定としません。

## 変更内容

FPGAの変更はG80A_eZ80内の3ファイルだけです。

- g80a_ez80.vhd: CPUを `entity work.T80_eZ80` で直接指定。D6解除要求を独立した54MHz動作の1ビットFF `Diag_SLP_Wake` へ登録します。CPU内部のCore_CENで停止しません。D6保持・新しい命令フェッチ受理後D5というプロトコルは維持します。
- t80_ez80.vhd / t80_pack_ez80.vhd: 解除入力を `SLP_Wake_Req` とし、既定値0を廃止。接続省略を許しません。
- F4=01/F5=FEを新しい診断識別値に追加します。既存の機能識別値は維持します。

新しい制御FFは論理上1ビットです。新規タイマはありません。実際のLUT/FF使用量はGOWINで再測定が必要です。MSX 16bit/拡張24bitバスの分離、メモリ回路、通常のリセットのみで解除するSLPの方針、SDC、GPRJは変更しません。

## GOWINでの確認

`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj` をビルドします。以前のimplを別名へ退避し、古い生成物を再利用せずSynthesisからPlace & Routeまで実行してください。

合成後のimplを先に送ってください。確認対象は `Diag_SLP_Wake` のFFと、そこからCPUのSleep_FFのDまたはCEへの解除経路です。レジスタ名だけの存在確認で正常とは判定しません。回路の接続と制御極性の確認が必要です。配置配線後のタイミングも別途確認します。

今回提供された実機R20.2のLogicは19380/20736(94%)、LUT17149+ALU1877、FF7318/15552(48%)です。54MHzのFmax32.119MHz、全体のSetup違反端点902、Hold違反端点44でした。Sleep_FF→mem1/sleep_metaのHold slackは-2.864nsです。この入力は同期1段目なので、違反数だけで実機故障と断定はできません。同期2段目、利用条件、保持期間の評価が必要です。一律のマルチサイクル指定や制約緩和は追加していません。

## 実機テスト

新しいCOM名で、旧版の取り違えを避けます。再起動後にまず次を実行します。

```
EZ80SL4 /RUN
```

CASE 0～3を経て `EZ80SL4 R20.4: PASS` が期待値です。PASSの場合だけ次を実行します。

```
EZ80RF4 /RUN
```

CASE 0～1を経て `EZ80RF4 R20.4: PASS` が期待値です。停止した場合は再起動し、最後のCASE番号を記録してください。SL4が止まる場合、RF4を繰り返す必要はありません。

| COM | サイズ | CRC32 |
| --- | ---: | --- |
| EZ80SL4.COM | 5178 | 5B66BD02 |
| EZ80RF4.COM | 3537 | 2612A915 |

R20.2以前のビットストリームでは新しいCOMはNOT READYとなります。旧32本のCOMはバイト単位で維持します。RUNALL.BATも維持し、SL4/RF4は上記の順番で手動実行します。DOS/BIOSがEIすることを想定し、表示は拡張をロックしたZ80状態で行い、戻った直後DIします。メモリ不一致のADDR/EXP/ACT表示も維持します。

## ローカル検証の範囲

GHDLで変換したCPUとIcarusの実COM・メモリモデルで検証します。COMモデルのメモリcpu_sleepはactual_sleepに接続しました。R20.2の0固定という検証不備を修正しています。

新COMではZ80/ADL、MADL、IRQ pending、WAIT、解除受理の1CE遅延、非対応・NOT READY・故障検出を確認します。長時間試験のCOMモデルは128倍に短縮したタイマを使います。メモリ回路の長時間試験は別に実施します。

CPUクロックは14ケースで分数クロック、追加2ケースで実機同様の108MHz系30分周（モデル全体は100/50/25MHzへ比例縮小）を使います。CPUクロックモデルにはPINFILTERのZ値を保持として扱う抽象化、簡略DOS、固定位相があり、GOWINの合成回路や配置配線後遅延を再現しません。CPUクロックは実機topでは108MHzを30分周した内部3.6MHzです。従来の約3.58MHz分数クロックだけのモデルでは不足するため、分周比を合わせた追加ケースを設けました。GOWINの配線遅延は再現しません。モデルPASSで実機修正済みとは判定しません。

検証結果とログはverification_r20_4に収録します。
