# R33：ブロック命令の上位バイト更新経路を短縮する

## 基準と目的

R32はGOWINビルド成功、Logic 80%、EZ80MEM／EZ80MR4／EZ80DECとRUNALLがすべてPASS、SOFARUNからスペースマンボウの起動・PLAYを実機で確認済み。R33の機能比較基準はこのR32である。

R32の配置配線レポートではCPU最悪SetupはPath 78、`Base_Group_0_s0/Q` → `Regs/RegsU[6]_3_s0/D`、54MHz同一立上り間、関係18.518ns、データ遅延22.984ns、Slack −4.501nsだった。経路には命令制御・RegAddrA選択・下位レジスタRAM読出し・Block_Inc_Resultの桁上がり・上位書込み選択が含まれる。Logic Level 23は経路全体の値で、デコーダだけの段数ではない。

R33はこの経路のうち、下位16bitの読出し後に上位8bitまで伝搬する加減算を対象とする。変更は `fpga/G80A_eZ80/t80_ez80.vhd` のみ。

## 変更

| 用途 | R32 | R33 |
|---|---|---|
| ブロック命令の上位8bit | Reg24A全24bitの±1結果から抽出 | 下位16bitの境界を判定し、既存の上位8bit用±1を共用 |
| 境界以外の上位書込み | 同じ値を再書込み | 上位WEを出さず値を保持 |
| 増減結果がゼロか | 24bit加減算結果と0を比較 | 減算前値000001h／加算前値FFFFFFhを直接比較 |
| INC/DEC rrの境界検出 | 個別に記述 | 同じPair_Low_Wrapを参照 |

対象ブロック命令は既存のLDI／LDD／LDIR／LDDR／CPI／CPD／CPIR／CPDRの長データ幅経路。I/O命令や対応命令の集合は変更しない。

## 算術上の対応

値を `U×65536 + L`、Uを上位8bit、Lを下位16bitとする。

- +1：L=FFFFhのときだけUを8bitで+1。それ以外はUを保持。
- −1：L=0000hのときだけUを8bitで−1。それ以外はUを保持。
- 全24bitの+1結果が0になるのは入力FFFFFFhだけ。
- 全24bitの−1結果が0になるのは入力000001hだけ。

上位8bitの更新も8bitで折り返すため、FFFFFFh→000000hと000000h→FFFFFFhを含め、24bit演算の結果と一致する。下位16bitは従来のID16をそのまま使用する。24bitの論理的な演算結果を変える変更ではない。

## 捕捉タイミングとWAIT

| 更新 | 維持する条件 |
|---|---|
| BCの減算 | M1/T3、従来の下位16bit書込みエッジ |
| HL/DEの増減 | メモリサイクルのT2でWait_n=1となる受付エッジ |
| 上位8bit | 上記エッジ、長データ幅、境界に到達した場合だけ |
| レジスタ書込み全体 | 従来どおりClkEnで許可 |
| IncDecZ保持FF | 従来のT2またはM1/T3の条件を維持 |

新たな要求・オペランドFF、先行捕捉、待ちサイクルは追加しない。追加FF間の保持期間を仮定せずに経路を短くする。下位16bitと上位8bitは境界更新時も同じクロックで確定する。

上位WEを省略した場合の書込みアドレスはRegAddrAになる。元のブロック用Upper_Port_IndexもRegAddrAなので、下位16bitの書込み先は変わらない。上位書込みイベントの重複は差分シミュレーションで検査する。

16bit MSXバスと24bitバス、MBASE窓判定、FFFFhの遮断、要求ラッチ、SDRAM配置、VDP、SDC/CST、GOWINプロジェクト設定はR32と同一。GSRも変更しない。

## 検証方法

実行結果の集計は `R33_VALIDATION.json`、ログは `R33_evidence`。

- 変更RTLから境界・上位8bit演算・ゼロ判定の式を直接抽出し、395,776組をVHDL-93シミュレーションで独立した24bit±1結果と比較。下位16bit全65,536通りは上位00/01/FFで、上位全256通りは境界を含む5種類の下位値で確認。24bit全入力の総当たりではなく、上記の桁分割による対応と組み合わせて確認する。
- R32のCPU・ラッパー6ファイルをそのまま参照モデルとしてGHDL合成し、実COMのバス、上位レジスタ全8本、PC、SPL、F、IncDecZを半クロックごとに比較。
- 通常30 COMと、SDRAM WAIT・CEN停止・位相変更を含む13 COMを比較。実際のSDRAM RTLを使用する。MSX-DOS出力処理がEIするテスト環境も維持する。
- テストベンチ内で境界検出／ゼロ判定をそれぞれ無効にした2試験は、R32とのレジスタ不一致で期待どおり停止。検査が故障を検出することも確認する。
- 幅・プレフィクス保持64ケース、VHDL-93の6ファイル解析、通常／診断／拡張無効のGHDL合成、30 COMとRUNALLの不変性を確認。
- mcodeおよび主分類関数はR32から変更していない。R32で実行した5,505,024組のmcode比較をR33の再実行結果とは表記しない。

これらは遅延なしモデルでの機能検証であり、GOWINの配置配線・タイミング検証を代替しない。

## GOWINと実機での確認

通常版プロジェクトは `fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj`。R32とは別のフォルダから再ビルドする。

COM30本とRUNALLは更新していないので、FLASHのテスト書換えは不要。

```
EZ80BLK /RUN
EZ80MEM /RUN
EZ80MR4 /RUN
RUNALL.BAT
```

それぞれ従来のPASS表示、RUNALL全PASS、SOFARUNからスペースマンボウの起動・PLAYを確認する。Logic使用数・LUT・ALU・Register、CPU最悪Setupの始終点とSlack、54MHz Fmax、全体Setup/HoldをR32と比較する。

下位16bitから上位のデータ入力への直列キャリーはRTLから除去したが、境界検出からWE/CEへの経路やレジスタ選択経路は残る。実際の経路短縮幅とLogic使用率はGOWINレポートで判断する。既存のVDP跨ぎ経路、Hold違反、DI_Frame_Valid_Reg入力経路も今回の修正では解決済みとしない。タイミング例外の追加・緩和は行っていない。
