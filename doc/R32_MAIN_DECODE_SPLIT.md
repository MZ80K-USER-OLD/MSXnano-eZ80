# R32：主命令分類と実行制御の分離

## 基準と変更範囲

基準R31はユーザー実機でRUNALL全項目PASS、SOFARUNからスペースマンボウ起動・PLAY成功。GOWINではLogic16182（79%）、LUT14288、Register6762、54MHz系Fmax36.834MHz、Setup違反434、Hold違反42。機能確認済みだがタイミングは未収束。R30も比較用に保持する。

FPGA差分はt80_pack_ez80.vhd、t80_ez80.vhd、t80_mcode_ez80.vhdの3ファイルのみ。GPRJ、SDC/CST、ラッパー、メモリ、MBASE窓、MSX16bitと拡張24bitバスの分離、VDPは維持する。GSR利用は保留のまま。

## 今回の境界

R31ではmcode内の基本・CB・EDそれぞれの主caseで8bit IRBを分類し、その中でMCycle別の制御を作っていた。
R32は主分類をDecode_Base_Group／Decode_CB_Group／Decode_ED_Groupへ移し、結果をCPUのグループ保持レジスタへ格納する。mcodeはBase_Group／CB_Group／ED_Groupの主caseから、同じMCycle別処理へ進む。

| ページ | グループ数 | 保持幅 | 実行側の主case |
|---|---:|---:|---|
| 基本 | 59 | 6bit | case to_integer(unsigned(Base_Group)) |
| CB | 8 | 3bit | case to_integer(unsigned(CB_Group)) |
| ED | 28 | 5bit | case to_integer(unsigned(ED_Group)) |

合計14bitのコンパクトな番号であり、95グループ分のone-hot FFを作る方式ではない。既存のExec_Control73bitは変更しない。14bitはRTL上の保持幅で、GOWINの物理FF増分を事前に断定する値ではない。

元の分岐本体（MCycle別動作、動的条件、モード別挙動）は維持し、主caseの選択肢をグループ番号へ置換した。基本・CB・EDの3箇所にある「case IRB is」は実行側からなくなった。

## 捕捉とページの扱い

- リセット：IR=00hに対応する各グループへ初期化。基本はNOPのグループ32、CBとEDはグループ0。番号0を全ページ共通のNOPと仮定しない。
- 通常命令：既存M1/T2、WAIT解除・ClkEn成立の命令受理と同時に、実際にIRへ格納するDec_Opから分類する。割込み／HALT等でNOPへ置換される場合も、置換後の値に合わせる。
- DD/FD CB：既存M7/T2で最終命令がIRへ入る時に、3種類のグループも更新する。
- フレーム終了のNOP注入：IRと同時に00hの分類へ更新。
- その他：WAIT、CEN停止、フレーム処理中はIRと同じ条件で保持する。

DD/FD CBではM6でISetがCBへ切り替わり、M7/T2で最終IRを捕捉する。現在ページだけの単一グループ番号をM1で保持すると、この途中状態と不整合になる可能性がある。
そのため3ページの分類を同じIRから並列に保持し、既存ISetで選択する。ページの遷移、追加フェッチ、割込み禁止区間を変えない。

新たな14bitは内部信号で、mcodeのentity／componentに明示接続する必須入力。既定値付きの追加入力は設けない。CPU外部のバスやラッパーのポートは増やさない。

## 分離の到達点

| 項目 | 状態 |
|---|---|
| データ幅・ストリーム幅・ADL等の命令制御 | 既存の保持制御を継続 |
| R30/R31の静的判定 | 既存の共通保持制御を継続 |
| 基本・CB・EDの主命令分類 | 今回、命令確定時の分類と保持へ移動 |
| ISetによるページ選択 | 既存の保持状態と遷移を継続 |
| MCycle別の動作・分岐条件・WAIT・割込み | 実行側で判断 |
| IRのレジスタ番号／ALU種別／ビット番号等 | オペランドフィールドとして継続参照 |
| 命令内のサブ判定・一部のIR比較 | 残る。主分類を移しただけで全ての生IR参照は消えていない |
| レジスタ番号解決・書込み許可・入力選択の後段MUX | 残る。物理経路と合わせて次に評価 |

複数命令の同時フェッチ・デコード・実行は行わない。3段パイプライン化ではなく、同一命令内で命令分類とサイクル別制御の間に既存の捕捉タイミングを利用して境界を作る変更。

## タイミング上の評価範囲

実行側で8bit命令の大きなグループ判定を繰り返す経路を、保持されたグループ番号の選択へ移す。ただしグループ生成は保持FFのD側へ移るので、前段経路にも遅延が加わる。

R31で問題となったDI_Frame_Valid_Reg入力の半周期経路と、上位レジスタへの書込み経路を、この変更で解消したとは扱わない。命令データ選択、MCycleのファンアウト、グループFF入力、後段MUX、配線遅延をGOWIN実レポートで比較する。
制約緩和や未証明のマルチサイクル指定は行わない。VDP→SDRAMのHold違反も別に残る。

## 検証

- GHDL合成：通常／診断／拡張無効。VHDL93でCPU6ファイルを解析。
- 構造照合：R31から移した95分岐の処理本体、主case前後の制御、IR捕捉の許可条件が不変であることをソースから直接照合。新規クラスを除いたCPU本体がR31と一致することも確認。
- 分類照合：新VHDLの分類関数を実行し、基本／CB／ED×256命令の768件が、未変更R31の分岐選択と対応することを確認。分類が正しい既知のバイトであり、同じIRと同時に捕捉される条件の下で、元の処理本体へ進むことを照合する。
- mcode新旧出力比較：Mode0〜3それぞれで256命令×4ページ×4XY状態×代表8幅／ADL／拡張条件×7MCycle×3割込み条件×2分岐条件。各1376256、合計5505024条件で全49出力を比較。
- 代表条件番号は0,1,3,7,11,15,17,31（5bitの各ビットが拡張有効／ADL／データ幅／ストリーム幅／明示幅）。FはA5／5A、Interrupt_Modeは条件番号mod3。出力比較は全条件フラグの総当たりではなく、上記の構造・分類照合と組み合わせた検証。eZ80公式仕様全体との照合、未初期化状態・タイミング違反時の保証は対象外。
- 実際のCOM30本：CPUとSDRAM RTLを含むモデルで、R31との外部バス一致を54MHz立上り／立下りごとに確認。通常CPU_DIV4・PHASE0。
- 停止条件13本：CPU_DIV4・PHASE3・CEN停止あり。幅／ページ遷移に関わるDEC、IRQ、NMIを追加。SDRAM待ちも含む。
- 幅プレフィクス64ケース：通常32＋WAIT/CEN停止32。既存73bitと新規14bitの計87bitについて、受理以外で保持されることを監視。
- MR4には専用トレースMUXとメモリ履歴を接続し、トレース選択値も比較する。
- DOS表示モデルは内部でEIするため、DOS／BIOS呼出しによる割込み再許可を従来どおり考慮。

単体mcodeベンチでは、入力グループを設定する前の0nsに数値変換の未初期化警告が1件/Mode出る。出力の照合は入力が既知値になった1ns以降で行い、全ケースでPASSした。CPU側は既存リセットと同時に各グループを初期化する。

VHDL93ではcaseの配列型を固定長にするため、分類関数内で8bit bit_vector変数へ写してからcaseを実行する。修正後の分類768件と構造照合はPASS。修正前後の通常／診断／拡張無効モデルと比較基準モデルは、等幅の内部wire別名と生成信号名・コメントを除く正規化後の構造が一致した。演算・FF・幅・公開ポート・クロック・定数は比較から除外しない。COM比較とmcode出力比較はこの構造一致により修正後にも対応する。詳細はR32_VHDL93_MODEL_EQUIVALENCE.json。

これはRTL由来のゼロ遅延モデルの検証。R32のGOWIN合成後、配置配線、LUT／FF使用量、実機動作は未確認。COM30本とRUNALLはR31と同一で更新不要。
