# R18 実装監査・残工程

R17はユーザー実機確認済み：GOWIN合成成功、Logic94%、全RUNALL PASS、D3 R3:PASS、SofaRunからスペースマンボウの起動・PLAY。R18はこのソースを基準にする。R18のGOWIN・実機・タイミングは未確認。

この一覧は機能群ごとの監査であり、全オペコード・全プレフィクス・全オペランドの網羅認証ではない。RUNALLの全PASSと全eZ80命令の完成を区別する。

| 項目 | 状態 | 根拠・残る制限 |
| --- | --- | --- |
| 工程1〜4：レジスタ・データ・演算・メモリブロック | 試験対象範囲を実装済み | R3/MEM/ALU/BLK。全条件の独立モデル照合ではない |
| 工程5〜6：ADLフェッチ・分岐 | 試験対象範囲を実装済み | F9/ADL/CT1。混在サフィックスに制限あり |
| 工程7：割り込み | 部分対応 | ADL IM1/IM2/NMI等は試験済み。**ADL IM0は未完** |
| 工程8：混在フレーム | R18でRSTを追加 | 正規ソース幅の4サフィックス、MADL裸RST。非正規ソース幅は保護HALTを維持 |
| 工程9：追加命令 | 監査継続 | LDH/LDXは実装済み。**SLP・未定義オペコードの扱い・追加I/O群の確認が残る** |
| 工程10：全体検証 | 継続 | GOWINの詳細Setup/Hold、実LUT/CLS数、実機回帰が必要 |

## 明確に残っている点

1. ADL IM0：周辺からのRST/CALL、その他入力時の扱い、MADL=0/1でのスタックと復帰を実装・検証する。0038固定やFF固定のテストだけでは完了しない。
2. SLP（ED76）：現在のEDデコーダはED56とED76をIM1として扱う。スリープ機能は未実装。拡張ロック時のZ80互換を守り、クロック・WAIT・復帰条件を定義してから追加する。
3. 混在命令の正規ソース幅以外と、未定義オペコードの扱い：現在のガードをeZ80の正式な不正命令動作と同一とは主張しない。
4. I/O群：ユーザー方針どおり**16bitポートの上位8bitを00に固定する追加命令は実装しない**。一方、BC/DEの16bitポートを使うその他の追加ブロックI/Oは、除外扱いで一括処理せず、命令ごとに監査する。
5. 全体回帰・規模・タイミングと実機確認。

残りの版数を固定で約束しない。まずADL IM0、次にSLP/残命令監査、最後に全体回帰とタイミングを進め、未実装を隠さず工程表を更新する。

## 一次資料と独立性

[Zilog eZ80 CPU User Manual UM0077](https://www.zilog.com/docs/um0077.pdf) のMemory Mode Switching（RST/RET）とInterrupt Mode0、命令表を参照。Table17の一部のAssembled Code欄にCALL形の表記があるため転記せず、RSTの実オペコードC7/CF/D7/DF/E7/EF/F7/FFを試験する。

RTL監査・期待フレーム生成器・実COM試験は別々の構成とし、正しいPC値と各バイトのアドレス/値を照合する。共通フレーム回路を使うことだけを正しさの根拠にしない。
