# R19 — ADL/MADL IM0対応

R18.3を基準に、ADLまたはMADLが有効な場合のIM0を追加しました。RST、CALL、その他の入力値のNOP扱いを実装しています。GOWIN合成・配置配線・規模・STA・実機動作は未確認です。

## 基準となる実機結果

R18.3はユーザー確認済みです。EZ80MEM /RUN、EZ80RW2 /RUN、RUNALL全項目、EZ80RS8 /RUNがPASSし、SofaRunからスペースマンボウを起動してPLAYできています。R19の基準としてR18.3とそのimplを保存してください。

R18.3のGOWIN結果はLogic94%、CLS99%、Setup違反端点790、Hold違反端点42でした。機能の復旧とタイミング収束は別です。R19はこれらの違反を解消した版ではなく、制約緩和も追加していません。

## 今回の機能

外部IACKで受け取るC7/CF/D7/DF/E7/EF/F7/FFは各RSTベクタへ、CDはCALLへ接続します。それ以外の247種類の入力値はNOPとして完了し、PC、汎用レジスタ、フラグ、SP/SPLを命令実行によって変更しません。割り込み受付によるIEF1/IEF2のクリアは行います。周辺からの幅プレフィクスもNOP扱いです。

IACKは1回です。CALLの後続3バイトは、割り込まれた側のPCが指すメモリから通常読み出しし、その分進んだPCを戻りアドレスとして保存します。周辺機器に追加のIACKを要求しません。

| 呼び出し元 | MADL | スタック | ハンドラのモード | 復帰命令 |
|---|---|---|---|---|
| ADL | 0 | SPLへPC24の3バイト | ADL | RETI |
| ADL | 1 | SPLへPC24の3バイト＋03タグ | ADL | RETI.L |
| Z80 | 1 | SPLへPC16の2バイト＋02タグ | ADL | RETI.L |

RSTのIACK自体ではPCを増やしません。CALLの対象取得では、元の命令ストリームのPC幅とMBASEを維持し、飛び先は24bitとします。通常Z80モード（ADL=0/MADL=0）と拡張ロック状態のIM0は、既存T80経路を維持します。その経路の任意オペコードをeZ80のNOP制限へ一律に変更した版ではありません。

## 共用と変更範囲

- R18.3で導入したT3の要求保持FFをIM0にも共用します。
- CALL対象取得、frame_push、Ctrl_Target/Return、SP/SPLの共通加減算器、Address_Reg/Data_Out_Regを共用します。
- NOP完了には既存のframe_mode状態をバス非アクセス状態として使います。既存8状態のままで、新しいFSM状態を増やしていません。
- CPUのワークレジスタ・状態保持ビットはRTL上追加していません。診断オペコードも既存Diag_Selectレジスタを使い、専用8bitレジスタを追加していません。GOWINでの実際のLUT/FF増減は未測定です。
- フレーム中は既存のWAIT/CEN/BUSRQ処理を使用し、途中のバス要求許可や未完了データでの復帰を避けます。
- R18.3比で変更するFPGAソースはCPU本体とG80Aラッパーの2ファイルです。メモリブリッジ、SDRAM、VDP、top、GPRJ、CST、SDC、命令分類表、マイクロデコーダは維持します。
- 16bit MSXアドレスバスと24bit拡張バスの分離、および拡張アクセスのFFFFセカンダリスロット判定からの遮断を維持します。

## 新しい実機用テスト

`hardware_test/EZ80IM0.COM`（数字の0）を追加しました。同じファイルをプロジェクト直下にも収録します。旧COMは変更していません。

```text
EZ80IM0 /RUN
```

期待表示：`EZ80IM0 R19: PASS`

COMのサイズは36114バイト、CRC32は`8B49F120`です。

24ケースです。ADL/MADLなしでは全8 RST、タグ付きADLとZ80→ADLでは00/38ベクタ、3モードのCALL、3モードの無効入力76/FB/5Bを確認します。ハンドラごとに異なるマーカー、入口のSPL/SPS、フレームのアドレス・各バイト、復帰後のSPL/SPS、IEF2のクリアを照合します。メモリ不一致は最初のStageとADDR/EXP/ACTを表示します。

診断回路から周辺機器のIACKデータを注入する試験です。物理的な外部周辺機器との接続・電気的タイミングを検証した結果ではありません。全256値の外部入力は、別途CPU単体のバス試験で検証します。

MSX/DOSの低位ベクタは書き換えません。既存のD8診断読み出し窓を使い、0F:0000付近に私有RSTベクタ、0A:6000/7000/8000/8100/9000付近と0E:8200/8130付近にコード・結果、SPL=050001近傍にフレームを配置します。MegaRAM/VRAM予約領域は触りません。

MSX-DOS/BIOSのEIを考慮し、私有試験中にはシステムコールを行いません。診断中の外部IRQは既存の診断窓でマスクし、意図したIM0だけEIで受け付けます。DOSへ戻る前にDI、Z80/MBASE=0、MADL=0、元のDOSスタック、IM1、診断停止・拡張ロックへ戻します。DOS表示呼び出し後もDIをやり直してレジスタを復元し、最後にEIで終了します。

/RUNなしはREADYのみです。旧版、診断回路なし、またはCA/CB識別値が異なる場合はNOT READYとして私有試験へ進みません。

## ビルド・実機確認

同じプロジェクトを使います。

`fpga/project_eZ80/MSXNanoTang20K_eZ80.gprj`

ZIPを新しいフォルダへ展開して合成・配置配線してください。古いimplやbitstreamは同梱していません。DualPin/言語設定はR18.3から変更していません。

1. 合成後にLogic、実LUT/FF、CLS、Setup/Hold結果を記録。
2. 実機で `EZ80MEM /RUN`、`EZ80RW2 /RUN` を確認。
3. 両方PASSしたら `EZ80IM0 /RUN`。
4. `RUNALL.BAT`、`EZ80RS8 /RUN`。
5. SofaRunでスペースマンボウを起動・PLAY。

RUNALL.BATは既存のままです。新しいIM0試験は別途実行してください。最初の失敗があればStage・ADDR/EXP/ACTを記録し、再起動後の単独試験で比較します。

## 識別と診断フック

C4〜C9の既存機能情報は維持します。E7E7ポートのCA選択読み出し=01、CB=FEがR19のIM0識別値です。診断有効時だけE0〜E7を選ぶとRST00〜38、E8はCD、E9は76、EAはFB、EBは5BをIACKへ供給します。既存D1がIRQ要求、D4が解除です。従来の選択値の場合は既存FEを維持します。

命令フェッチ用入力とデータラッチの双方へ同じ診断値を供給します。通常フェッチと診断無効時の外部データ経路はそのままです。

## 検証・限界

今回の結果・ログは `verification_r19/summary.json` に集約します。

- IM0全256入力値×3コンテキスト×通常／ストレス=1536ケース。
- HALT復帰、IM0より優先するNMI、フレーム中に保留したNMI、WAIT/CEN/BUSRQ、PCの64KiB境界、SPLの24bitラップを検査。
- 入口A/F、IEF1/2、全フレーム書き込み、CALLの各オペランド読出しアドレス、復帰先とSP/SPL、無効入力の副作用なしを照合。
- 実COMのCPU・ブリッジ・SDRAMモデル試験には、成功、故障注入、READY、NOT READY、拡張無効を含めます。BDOSスタブがEIを実行し、DOS側のIM1を実際に受け付ける条件も含めます。
- RST、混在CALL/RET、割り込み、メモリ、ロック状態の互換性を回帰確認。

これらはGHDL/Icarusでの機能検証です。全MSX-DOS/BIOSのエミュレーション、全eZ80命令の網羅認証、GOWIN実行、実機PASS、タイミング収束を意味しません。

## 残項目と一次資料

SLP、混在命令の一部幅指定、追加I/O群の命令別監査、非法命令のTRAP、全命令の独立照合、全体タイミング・規模検証が残ります。ポート上位8bitを00固定する追加I/O命令を実装しない方針は維持します。

公式UM007715のp46には非法命令TRAPが規定されています。以前の「未定義オペコードの扱いを監査」としていた項目を、TRAP規定を含む未実装項目として明確化しました。IM0で周辺が供給する無効値をNOPにする規定とは別です。

参照：
- [Zilog eZ80 CPU User Manual UM007715-0415](https://zilog.com/docs/UM0077.pdf)、p38〜40 IM0/Table22、p46 Illegal Instruction Traps。
- [Zilog Z80 CPU User Manual UM008011-0816](https://www.zilog.com/docs/z80/um0080.pdf)、p184 IM0の後続バイトの通常メモリ読出し。本実装はこのバス方式を継承し、ADL/MADL時のオペランド幅とフレームを拡張しています。
