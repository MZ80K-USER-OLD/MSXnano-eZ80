# R10：大工程6・24bit制御フロー

追記：その後ユーザーのGOWIN合成成功・LUT85%・CTL／ADL／F9全PASS・SofaRunからスペースマンボウのプレイで通常ADL制御は実機合格。以下はR10配布当時の記録。現在の対応範囲はRESTART_R11.mdを参照。

## 基準と現在地

R9のGOWIN合成成功、LUT使用率84%、実機の `EZ80F9 R9: PASS`、その後SofaRunからスペースマンボウを起動してプレイできた、というユーザー報告を基準にする。
工程1〜5は実機合格。R10は工程6の通常ADL制御フローを実装する版であり、R10自体のGOWIN合成・配置配線・タイミング・リソース量・実機確認は未実施。
工程7のADL割り込み、工程8のMBASE／MADL／混在復帰フレーム、工程9の残項目、工程10の最終検証が残る。最終リリース番号は未確定。

## 実装範囲

| 命令・状態 | R10の動作 |
|---|---|
| 無指定ADL JP／JP cc | 即値3バイトを取得。条件不成立でも3バイトを消費し、モードを変えず次命令へ |
| JP (HL)／(IX)／(IY) | 通常ADLでは24bitレジスタ値へ分岐 |
| JR／JR cc／DJNZ | 命令後PCに符号付き8bit変位を加算。ADLの結果は24bitで折返し、DJNZはBだけ減算 |
| 無指定ADL CALL／CALL cc | 条件成立時だけSPLへ復帰PCを3バイト保存。条件不成立時はスタック不変 |
| 無指定ADL RET／RET cc | 条件成立時だけSPLから3バイト復帰PCを読む。条件不成立時はスタック不変 |
| 無指定ADL RST | SPLへ3バイト復帰PCを保存し、000000h〜000038hの該当ベクタへ。ADLを維持 |
| Z80無指定CALL／RET／RST | 既存の16bit SPSフレームを維持 |
| プレフィクス付きCALL／RET／RST | 工程8の混在フレームが必要。今回はHALTで停止させる。ADL内の5Bh指定も通常の無指定フレームとは異なる |
| ADL RETI／RETN、IRQ／NMI | 工程7に残る。ADL割り込みディスパッチは抑止。実機ADL試験はDIで実施し、NMIを発生させない |

通常CALLの復帰PCは、3バイト即値をすべて読み終えた直後のPC。RSTは命令の次のPC。
初期SPLをSとすると書込み順は `(S-1)=PC[23:16]`、`(S-2)=PC[15:8]`、`(S-3)=PC[7:0]`。
RETは最終SPLから下位・中位・上位の順に読み、3回進める。加減算は24bitで折り返す。
フラグは制御命令で変更しない。CALLのターゲットと復帰PCはレジスタへ捕捉し、DOも各書込みサイクルのT1で登録してWAIT中は保持する。
元T80のMC6／MC7にはインデックス処理の特例があるため、新しいCALL中はそれを抑止する。
SPL更新は既存のWAIT解除時点に合わせ、WAIT保持中やCEN停止中の重複更新を防ぐ。

JPのモード移行は、既存の即値.SIS／.LILに条件付きJPを追加する。条件不成立時はADL状態を維持する。
レジスタ間接JPは通常ADLの長いレジスタ参照を実装する。短いJP指定と混在モードの網羅的確認は工程8で行う。
即値JPの.LIS／.SILは対応範囲に含めない。

リセットはADL=0、ゲートはロック状態。SPSは16bit、SPLとADL中のPCは24bit。
元G80A、CPUラッパー、トップ、メモリブリッジ、SDRAM制御、GPRJ、CST、SDCを変更しない。
GPRJにはIDE全体のオプション値が列挙されていないため、IDE側ではR9で成功した設定を維持する。付属build.tclに記載の値は -use_sspi_as_gpio 1、-use_mspi_as_gpio 1、-verilog_std sysv2017。これは今回のGOWINビルドで設定値を実測したという意味ではない。CPU→メモリ要求の捕捉と保持、VDP読出し優先・CPU WAIT、高位xxFFFFhのMSXスロット分離を維持する。
一律のタイミング制約緩和は行わない。GOWINでの実捕捉点・保持期間の確認は実レポートが必要。
上位I/Oアドレス00h固定の追加I/O命令は引き続き除外し、従来Z80のI/O命令は維持する。

未実装オペコード全体を例外化したCPUではない。今回の停止保護は表で挙げた命令群を対象にする。特にED75hには従来T80のRETN別名経路が残り、ADL用として使うとSPS側を参照する危険があるため実行しない。正式なRETN（ED45h）／RETI（ED4Dh）は停止保護対象である。ED55h／ED65hは拡張有効時にはLEA／PEAへ再割当て済み。残るZ80非公開別名とeZ80追加オペコードの衝突は工程7／9で洗い出す項目として記録する。これは無指定ADL RET（C9h）の3バイト対応とは別の未対応項目である。

NMIについてR9文書に「エッジの保存も未実装」と記した箇所は補足が必要。既存同期回路のNMI_sはNMICycleまで要求を保持する構造である。ただしADL用フレーム・配送とZ80復帰後の再配送タイミングは未実装・未検証であり、ADL NMI対応済みとは扱わない。

公式仕様参照：Zilog eZ80 CPU User Manual UM007715-0415、CALL／RET／RST／JP／JRの項。
https://www.zilog.com/docs/UM0077.pdf

## 実機テスト

同梱GPRJを新しい展開フォルダで全ビルドし、R10を書き込んでから実行する。
E7E7hポートのE1h応答は機能版番号ではない。古いCPUでも応答するため、/RUNはR10を書き込んだ後に限定する。

```
EZ80ADL /RUN
EZ80CTL /RUN
EZ80F9 /RUN
```

期待表示：

```
EZ80ADL P1: PASS
EZ80CTL R10: PASS
EZ80F9 R9: PASS
```

EZ80ADL.COMは先行配布P1の1195バイトをそのまま使用する。更新不要。
01FFFEhのコードへ入り、030100h〜030103hへ56h／34h／12h／A6hを保存し、SPL=050001hからCALL／RETする。
04FFFEh〜050000hの復帰PC3バイトと最終SPLを照合する。

新規EZ80CTL.COMは090000hから1674バイトのコードを実行する。全8条件の成立・不成立のJP／CALL／RET、HL／IX／IY間接JP、JR条件、DJNZ、入れ子CALL／RETとF保持を177項目で確認する。
結果とAFスナップショットは030200h〜0302EAh、スタックは050001hから使用する。アドレスの正確な一覧・期待値は `hardware_test/EZ80CTL.json`。
不一致では `stage C ADDR=xxxxxx EXP=xx ACT=xx` を表示する。コード異常で復帰不能となった場合は表示まで到達しない可能性がある。
RSTはMSX BIOS領域を変更せず、実機COMでは実行しない。全8ベクタは合成RAMを使うCPU単体試験で確認する。

両COMとも、DI後はADLを抜けるまでDOS／BIOSを呼ばない。JP.SISでZ80へ復帰し、拡張ゲートを閉じ、SPS／IX／IYを復元してからEI／DOS出力する。
シミュレーションのDOSスタブは呼出し内でEIを実行し、システムコールをまたいでDIが残るという前提を置かない。
引数なしのEZ80ADLはPLANNED、EZ80CTLはREADYで終了し、ADL機能試験の合格ではない。

PASS後にSofaRunからスペースマンボウを起動してプレイを確認する。可能なら既存MEM／ALU／BLK／MUL／LEAテストも回帰する。
LUT使用率・配置配線後タイミングを記録する。R9の84%からの増分はまだ見積値を出さない。

## 機能検証と再現

`bash tools/run_checks.sh` でGHDL／Icarusの機能検証を実行する。必要な環境変数はGHDL／IVERILOG／IVL_ROOT／VVP。
GHDLのVerilog変換で使う--latchesは従来CPUのシミュレーション変換条件であり、GOWIN用設定の変更ではない。
合成・実機の代替ではなく、完全なMSX-DOS／BIOSのシミュレーションでもない。

- R3〜R8の既存回帰とR9のCOM／PC境界試験を再実行。R9で停止を期待した工程6の6ケースは廃止し、実動作オラクル試験で置換する。ADL RETI／RETNの停止保護は維持する。
- 実際のEZ80ADL.COMとEZ80CTL.COMを、CPU・ブリッジ・SDRAM制御・SDRAMモデルを通して実行。位相変更、WAIT、CEN停止、拡張なし、引数なし、結果値の故障注入を確認する。
- CPU単体の独立した簡易アーキテクチャモデルと命令フェッチ列、F、SPL、全スタック書込み／読出しのアドレスとデータを照合。条件全8種、入れ子、PCの64KiB境界、JRの24bit折返し、SPLの24bit折返し、RST全8個を含む。条件付きJP.SIS／JP.LILの成立・不成立によるADL遷移も照合する。現行オラクルは1回あたり557フェッチ、183スタック書込み、183スタック読出しを照合する。
- 混在CALL／RET／RSTの各幅プレフィクスが、未対応フレームをスタックへ書く前に停止することを確認。

最新の実行件数とSHA256は `verification_result.json`、各ログと機械可読オラクルはZIP同梱の `verification_logs` と `sim/flow_r10` を参照。
