# MBASE連動MSX窓とI/Oデバッグ制御の設計案

## 対象と結論

対象は実機でEZ80MEM、EZ80TIO、RUNALL全項目、SOFARUNからスペースマンボウ起動・PLAYが確認されたR25。RAM併用版を基準とし、R24.6のFF比較版は採用しない。

本書は検討結果であり、RTL・COM・bitstreamは変更していない。

推奨する通常メモリの選択条件は、`最終的な24bitアドレス[23:16] = MBASE`。CPUからこの一致結果を出し、ラッパーが要求アドレスと選択結果を同じ要求のT1で保持する。書込みデータは現行のT1／T2捕捉条件と実際のデータ有効期間を照合して保持する。MBASEの由来を示すフラグだけにはしない。

I/OでMBASEを設定できると、現在ADL専用のLD MB,Aを使わずZ80の診断プログラムからMSX窓を変更できる。ADLの読出しも有用。ADLの書込みは、通常のOUTの途中で1bitを変更する方式ではなく、明示的な移動先PCと一緒に命令完了境界で適用する方式を推奨する。

## 1. 新しい窓の意味

通常メモリアクセスについて、Z80／ADLやプレフィクスによらず、最終有効アドレスの上位バイトで判定する。

| 例：MBASE=0Eh | 行き先 |
|---|---|
| 0E1234h | MSX 1234h |
| 0EFFFFh | MSX FFFFh。選択された拡張スロットの条件ではセカンダリスロットレジスタに届く |
| 071234h | 拡張メモリ |
| 07FFFFh | 拡張メモリ。MSX側FFFFhへ到達させない |
| 001234h | 拡張側へ分類。現行のままではbank00hは未割当 |
| IN／OUT | 窓とは別の16bit I/O経路。TSTIOの00:Cも変更しない |

短いアクセスではCPUが上位バイトにMBASEを付けるため、通常はMSX窓へ入る。ADLの24bitアクセスでも、上位が一致すれば同じMSX空間へ入る。MSX窓に入っても、ADLのデータ幅やSPS／SPLが自動的に16bitへ変わるわけではない。

リセット値MBASE=00hを維持すれば、起動直後のZ80互換アクセスは従来どおり00xxxxhのMSX空間を使う。

MBASEがRAM／MEGARAM／VRAMに割り当てられたバンクと同じなら、その64KiB区画はMSX窓を優先する。例えばMBASE=60hでは、論理600000h～60FFFFhのVRAM用窓は通常アクセスから隠れる。一般的な診断設定例は00h／0Eh／FFhとし、実際のソフトウェア用割当は別途決める。

## 2. CPUから出す信号

| 信号案 | 意味 | MSX選択に使えるか |
|---|---|---|
| A_USES_MBASE | 16bitアドレスへMBASEを付けて生成したことを示す | それだけでは不足 |
| A_MSX_MATCH | 最終アドレス上位8bitと、その要求に適用するMBASEが一致 | 推奨 |

ADLでBC=0E1234hを指定しMBASE=0Ehだった場合、アドレスはMBASEから生成されていなくてもMSX窓に入れる必要がある。由来のフラグだけだと、この場合を取りこぼす。

同じ命令内でも、ブロック転送の読出しと書込み、3バイト転送のバンク境界前後で行き先が変わり得る。この信号は命令単位の固定属性ではなく、各メモリ要求の実効アドレスに対応させる。

### 最小変更案

CPU出力に次の意味の信号を追加する。

```vhdl
-- 概念。実際の要求分類ではI/O・refresh・診断を別に処理する。
A_MSX_MATCH <= '1' when Address_Bank_Reg = MBASE else '0';
```

ラッパーでは現行の `Bank_i=x"00"` 判定をCPUの一致結果へ置き換え、T1でRequest_Address、Request_MSX_Address、Request_Extendedを一緒に保持する。待機中に現在のMBASEと再比較しない。

これはCPU／ラッパーの責務を明確にする案であり、比較器をCPUへ置いただけで物理的な段数や遅延が減るとは限らない。8bitの動的一致比較になるため、GOWINの実測が必要。

### 必要に応じたタイミング改善案

CPUがアドレスを生成する時点で、Address_Bank_Regと同じエッジにMSXタグも保持する。新しい1段を後から挿入してタグだけ1サイクル遅らせてはならない。

この場合は、最終のBank_NextとMBASE_Nextを使ってタグを作る必要がある。アドレス代入経路が通常実行・フレーム・IRQ／NMI等に分かれているため、各代入点へ断片的なタグ更新を加えるだけでは更新漏れを起こしやすい。先に最小案を機能比較し、必要な経路だけを整理する。

## 3. 同じ要求として保持する

概念上の選択順序は次のとおり。

1. refresh：既存のMSX refresh経路。
2. I/O／IACK：既存のI/O要求処理。通常のBC16ポートとTSTIOの00:Cを維持。
3. 診断ベクタの読出し：既存のprivate vector overrideを優先。
4. 通常メモリ：A_MSX_MATCHでMSX／拡張を選択。

通常メモリがMSX窓なら、MSX16bitバスに下位16bitを出し、拡張要求を抑止する。拡張側ならMSXアドレスを0000hに遮断し、MSX MREQを無効にする。元の24bitアドレスは拡張側の要求として維持する。

既存のPREDECODED_MSX=1経路は利用できる。旧fallbackのbank!=00h判定を新方式で誤使用しないよう、新方式ではPREDECODED_MSX=1を必須にするか、fallbackにもMBASE情報を渡す必要がある。

Request_Extended、下位MSXアドレス、24bitアドレスは同じ要求の情報として保存する。WAIT／CEN停止／BUSRQ中に現在値で再分類しない。下位FFFFhの遮断は、捕捉済みタグとMSX MREQの両方で維持する。

診断Vector_Windowは現在bank00hを前提にしている。MSX窓移動後の短い割り込みと、ADLのbank00h固定ベクタの両方を区別して再設計する必要がある。private 0Fhへのoverride後に通常窓判定をやり直すと、MBASE=0Fhで診断メモリまでMSXへ戻す危険があるため、最終の行き先を保持する。

## 4. bank00hの拡張RAM割当

MBASEが00h以外になると、ADLで指定した000038h／000066hはMSX窓ではない。現在のブリッジはbank01h～1Bhだけをprivate RAMとして扱うため、bank00hはFFh読出し／書込み無視となる。

したがって、窓移動だけでADL割り込みが動作するとは扱えない。

推奨案は、通常メモリが拡張側へ分類された場合に、private RAMをbank00h～1Bhへ拡大すること。既存式 `640000h + bank*10000h + offset` を使えば、bank00hは物理640000h～64FFFFhになる。

現在のソースではmapperは000000h～3FFFFFh、MEGARAMは400000h～5FFFFFh、VRAM予約領域は600000h～63FFFFh、private bank01hは650000hから始まる。640000h～64FFFFhはこのデコーダでは未使用なので、候補にできる。ただし本書で接続・実機検証したわけではない。

MBASE=00hではbank00hはMSX優先のため、このprivate RAMは隠れる。MBASEを別値へ移す前に、ADL用コード・IM1／NMIハンドラ・必要なベクタ表を適切な拡張領域へ用意する必要がある。MSX BIOSのZ80ハンドラを、そのままADLの24bitスタック用ハンドラとして実行しない。

## 5. 既存COMに対する互換性

MBASEのeZ80レジスタとしての機能に、MSX窓選択という本プロジェクト固有の意味を追加する変更である。

R25のテストには、MBASE=0Ehとして0E8200hの拡張RAM上にあるZ80コードを実行するものがある。TSTIOの既存共通テンプレートもこの方式である。

新方式では同じフェッチがMSX 8200hへ向かうため、従来の「拡張RAM上のバンク付きZ80実行」と同じ結果にはならない。旧テストの失敗を直ちにRTL不良と判定してはならず、仕様に合わせてテストの配置を更新する必要がある。

更新方針：Z80コードはMSX RAMの既知領域へ置き、ADLコードは選択中のMBASEと異なる拡張バンクへ置く。MSX BIOS／DOS呼出し前にはZ80モードへ戻す。現在の診断COMはMBASE=0へ戻してから拡張をロックするため、この順序も維持する。

旧R25のCOMを全てそのまま使えるとは約束しない。新方式の診断IDを追加し、新旧テストを識別する。

## 6. I/Oデバッグ設定

### 有用な機能

| 機能 | 効果 | 推奨 |
|---|---|---|
| MBASE読出し | 窓の現在値を確認 | 既存C8hを継続利用 |
| MBASE書込み | Z80のOUTから窓を変更できる。LD MB,AのためにADLへ入る手順を減らす | 診断機能として追加する価値あり |
| ADL読出し | モード遷移後の状態確認 | 追加を推奨。MADLやData_Longと混同しない |
| ADLへの直接書込み | その後の命令長・PC・SP選択を変える | 生のビット書換えは避ける |
| ADL＋移動先PCの一括適用 | 明確な入口へ移動して新モードで実行 | 書込みが必要ならこの方式 |

### MBASE書込みの適用

設定要求と値を保持し、OUTの完了境界で一度だけ適用する。WAIT中の繰返し適用、SDRAM要求の途中での変更、ラッパーだけにMBASEの別コピーを持つことは避ける。

重要なのは次値である。Z80モードでMBASEを書き換えた場合、次の命令フェッチのbankも新しいMBASEにする。現在のVHDLでは同一プロセス内でMBASEへ代入しても、そのエッジ中の参照は旧値なので、単純な代入追加では次のアドレスだけ旧MBASEになる可能性がある。

MBASE_NextとAddress_Bank_Nextを整合させる。既存の拡張ロック操作によるMBASEクリアも同じ観点で監査する。

### ADL書込みの適用

推奨する診断要求は、TARGET_ADL、TARGET_PC[23:0]、必要なら新MBASEを事前設定し、MODE_GOで命令完了境界に一括適用するもの。

- 新規要求は診断有効時だけ受理し、busy／ack／errorを確認できるようにする。
- メモリ要求、WAIT、混在フレーム、プレフィクスの途中へ割り込んで適用しない。
- PC、次の取得アドレスとbank、ADL、新しい既定幅、IR／ページ状態を同じ遷移として更新する。既存モード切替付きJPと同じ状態更新を利用する方がよい。
- SPSとSPLはコピーせず保持する。ADLへ入る前にSPLを初期化し、Z80へ戻る前にSPSの有効性を確認する。
- IRQ／NMIと競合した場合の優先順位と保留規則を定める。DIだけでNMIを防げるとは扱わない。

PCを変えずADLだけ1にすると、次の命令長が変わり、MBASEが非ゼロなら次フェッチのbank解釈も変わる。割り込み復帰フレームが残ったままの切替も整合を崩し得る。

まずはMBASE書込みとADL読出しを追加し、ADL切替は既存の幅付きJP／CALLを使う段階分けが最小構成になる。I/OからADLを設定する必要がある場合にMODE_GOを追加する。

### ポートと通常版の扱い

通常版でもCOMのためにDIAGNOSTICSが有効なので、DIAGNOSTICSだけを条件に状態書込みを開放しない。別のDEBUG_CONTROL genericを初期値falseで設け、必要な診断ビルドでだけ有効にする案を推奨する。

既存のE7E7hはunlock／lockコマンド用で、00h出力は拡張をロックする。そのまま次のデータbyteをMBASE値として受け付ける仕様にすると、00hを書きたい場合などに衝突する。

インデックス／制御とデータを分離する。例としてフル16bitの診断データポートを別に確保し、通常MSX I/Oへ漏らさない。具体的なアドレスは既存I/Oとの全体照合後に割り当てる。本書では未割当。

TSTIOが使う00E6hのループバック、IM0の診断セレクタE8h～EBh、トレース用セレクタと重複させない。新しい診断IDを確認してから設定OUTを実行し、旧FPGAへ未知の設定書込みを流さない。

追加する待機レジスタや状態保持は診断版限定にできるが、面積削減量や追加LUT数はGOWINで測定するまで確定しない。

## 7. 検証計画

| 検証 | 確認する内容 |
|---|---|
| リセット・MBASE=00h | 従来のMSX起動とR25の動作を維持 |
| MBASE=0Eh／FFh等 | 一致bankだけMSX、非一致bankは拡張 |
| ADLの明示24bit | MBASE由来でないアドレスでも、一致ならMSX |
| 同じ下位16bit・異なる上位 | 特にxxFFFFhを読書きし、非一致側でslot要求が起きない |
| 短い／長い境界アクセス | 短いFFFF→0000はMBASE内で折返し、24bitは次bankへ進み要求ごとに分類 |
| ブロック転送 | MSX読出し・拡張書込みと逆向き、反復境界のIRQ／NMI |
| WAIT・CEN・BUSRQ | 捕捉済み要求とMSX遮断を保持 |
| MBASE書込み直後 | 次フェッチのbank、tag、低16bitが新値で整合 |
| I/O／IACK／refresh | 窓移動の影響を受けない |
| ADLベクタ | bank00h RAM候補への接続、IM1／NMI／IM2と復帰 |
| 診断ベクタ | MSX窓移動後もprivate overrideが正しく優先 |
| デバッグMODE_GO | 有効なPC／スタック、受付境界、割り込み競合、busy／ack |
| 実機 | 更新したMEM・MB・MAD・MIX・TIO等、RUNALL、SOFARUN／スペースマンボウ |
| GOWIN | 新しい一致比較→Request_ExtendedのSetup、Hold、LUT、FF、既存の最悪経路 |

この計画は未実行。下位FFFFhの実機書込み試験はMSXのスロット状態を変え得るため、シミュレーションで先に検証し、実機では保存・復元の手順を含める。

## 8. 実装の段階分け

1. メモリ経路だけ変更：CPU一致出力、要求との同時保持、bank00h RAM候補、診断ベクタ、対応COMを更新する。I/OのADL書込みは入れない。
2. MBASE書込み・ADL読出しの診断インタフェースを追加し、次値と次フェッチを確認する。
3. 必要ならTARGET_PC付きMODE_GOを追加する。

各段階でGOWINと実機回帰を分けて確認する。R25安定版のRTLをこの検討段階で置き換えない。制約を一律に緩和して一致比較の追加を隠さない。
