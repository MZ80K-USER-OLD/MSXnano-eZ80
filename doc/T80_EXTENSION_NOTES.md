# T80を24bit拡張するときの注意点（R11）

元G80Aは変更していない。以下は拡張との接続で確認した注意点であり、原版T80の全命令に不良があると断定する資料ではない。

| 項目 | 拡張時の問題と対処 | 検証 |
|---|---|---|
| MC6／MC7の特例 | 元設計にはインデックス演算用の遷移・レジスタ選択がある。7サイクルの24bit CALL／IM2に適用すると命令列やアドレスが壊れるため、専用経路中は特例を抑止 | CALL回帰、IM2の3バイト表読出し |
| EIとIFFの更新時点 | 内部IFF更新が次フェッチ側にあるため、EI終了境界のNMIにはEI後の実効値を保存。受付M1に旧EI／DIを持ち越して再設定しない | EI境界でNMIとIRQを保留し、NMI ISR実行後にIRQが来ることを確認 |
| RETN後の即時IRQ | PC復帰と同じ境界でIEF2から復元した許可状態を使わないと、次のDIまでIRQが遅延する | P2 NMIの保留IRQプローブ |
| NMI保留の解除 | NMICycle全期間で消す方式では受付中の別エッジを失う。ADLでは実際の受付境界で解除し、同時の新エッジを優先 | 受付中の次NMI、2段フレーム、2回のISR実行 |
| IACKデータの有効期間 | 外部ベクタ供給をM1とIORQのANDだけで切ると、M1が先に上がった後にデータが消える。試験デバイスはIORQ終端まで保持。内部FEh供給はIACK M1だけに限定 | 外部入力を使うIM2単体試験とP2診断IM2 |
| 古いRETN別名 | ED75hなどの旧別名をADL中に通すと16bit SPSを参照する危険がある。未実装命令の扱いを個別確認し、R11のADL ED75hは停止 | 書込み禁止・SPS／SPL不変の停止試験 |
| WAITの開始 | WRが出てからWAITを開始するとT2捕捉に間に合わない場合がある。MREQ/T1と読書き意図から要求を保持する | 実ブリッジ試験、最初のブロック書込みをT1から止める単体試験 |

ロック状態のZ80互換経路は原版との比較を継続する。上記のADL対応を、Z80互換の全ケースの修正・証明と混同しない。
未実装命令の一括トラップ、ネイティブIM0、混在フレーム、外部非同期NMIの電気的要件は残課題。
