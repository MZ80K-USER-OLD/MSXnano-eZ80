## MSX用アドレスも要求時に保持

従来は保持したRequest_Address上位8bitを比較し、その結果で下位16bitをゼロへ切り替え、各周辺回路へ配っていた。この経路にはバンク判定→16bit遮断MUX→周辺アドレスデコードが直列に存在する。

R11.3ではラッパの同じT1下降エッジで次の3種類を保持する。

| 保持値 | 内容 |
|---|---|
| Request_Address 24bit | 既存の全アドレス |
| Request_MSX_Address 16bit | MSXアクセスなら下位16bit、拡張アクセスなら0000h |
| Request_Extended 1bit | 拡張要求かどうか |

トップは新しいA_MSX／Extended_Window出力をブリッジへ接続し、PREDECODED_MSX=1で使用する。従来のREQUEST_BANK_QUALIFIED=1も維持する。
ブリッジの既定値PREDECODED_MSX=0では旧インタフェース動作を維持する。新しい入力を有効にするには必ず新ラッパの保持済み出力を接続する。
元のA出力は既存のライブ16bit端子のまま。ボードのMSXメモリデコードへは新しい遮断済みA_MSXを使用し、24bitアドレス系と分離する。

- バンク00hのFFFFhはMSXのセカンダリスロットを正しく選択する。
- 非ゼロバンクのxxFFFFhはMSX側アドレス0000h、MREQ無効となり、スロットレジスタへ到達しない。未割当バンクにも適用する。
- I/Oと割り込み応答M1はバンク00h。ADL割り込み入口のM2以降を00hへ固定しない。
- 診断ベクタ窓は00hから0Fhへ変換する時点でMSX側も遮断する。
- リフレッシュ中のみ00h＋コアのリフレッシュアドレスを一時出力し、終了後は元の保持済み要求へ戻る。
- WAIT中、T2以降、CPUイネーブル停止中は普通の要求の保持値を更新しない。

CPU命令を遅らせたりバスサイクルを追加したりする変更ではない。従来のバンク判定とMUXを保持レジスタの手前へ移したもので、要求捕捉までの半周期経路のSTAも引き続き確認する必要がある。

## 命令分類の拡張

Opcode_Classを6bitから16bitへ拡張し、ADD24、ADC/SBC24、ブロック命令、MLT、LEA/PEA、JP、CALL/RET/RST、RETI/RETN、I16読出しの入口分類もIRと同時に保持する。
ISet、幅、拡張許可、IRQ/NMIなどの資格条件は引き続き各経路で適用する。通常フェッチ、強制RST/NOP、DDCB等のIR更新点はすべて同じ分類関数を使う。
全デコーダの置換や命令フェッチのパイプライン化ではない。新規命令も追加しない。

## SDRAM：下降で捕捉し、次の上昇で受理を公開

送信payloadはブリッジの54MHz上昇エッジで保持する。受信側は次の順序とする。

| 受信108MHz時点 | 動作 |
|---|---|
| 上昇P0 | 要求をext_metaへ取り込む |
| 上昇P1 | ext_syncへ進める |
| 上昇P2 | 空き条件を確認しext_capture_armedを立てる |
| 下降P2.5 | 保持済みアドレス・データ・方向を捕捉 |
| 上昇P3 | ext_pendingを立て、既存のスロット選択へ渡す |

最短捕捉は初回要求サンプルから受信2.5周期後（108MHzで約23.15ns）、pending公開は従来どおり3周期後。アーム信号は1周期のワンショットで、同一要求を再捕捉しない。送信payloadは応答の同期受領まで保持する。
受信payloadのFFだけを下降エッジへ移し、同期器・pending・VDP優先・CPUスロット・リフレッシュ・外部SDRAM信号のスケジュールは変えない。

この変更はSTAからパスを除外しない。送信上昇→受信下降、アーム上昇→捕捉下降、捕捉下降→既存の受信上昇ロジックの各半周期経路を新しいGOWIN出力で確認する。
下降エッジ化で必ずHoldが解消する、全Setupが成立する、とは保証しない。PLL／CLKDIVの実際のクロック経路とスキューを含めて判定する。

## 検証

- R11.2の233条件に相当する既存回帰を現在のRTLで再実行する。CDC試験の監視点は実際の下降捕捉へ更新する。
- 実CPU＋SDRAMモデルの15種類のfixtureを新しいMSX接続へ切り替え、各エッジで全24bitアドレスとMSX側遮断の一致を監視する。
- 新規要求レジスタ単体試験：診断あり／なし2条件、各75,776チェック。全256バンク×8オフセット×7要求種別を走査し、WAIT/T2・CEN停止・リフレッシュ重畳と復帰を確認する。内部コア出力を駆動する境界単体試験であり、CPU実行の証明は既存COM回帰で補う。
- MSXアドレスの誤出力、遮断フラグ欠落を故障注入し、検出を確認する。
- CDCは送信側だけ0/2/5/8nsずらした4条件、SDRAM起動待ち1条件、拡張非動作時の旧コントローラとのピン比較4条件。早過ぎる受理と保持中payload破壊の故障を検出する。
- CDC fixtureの100/50/25MHzは4:2:1の関係を模擬する時間スケール。任意位相の全VDP回路動作、メタスタビリティ、物理遅延の証明ではない。
- VHDL-93解析、5ファイルのソース再生成、122プロジェクト参照、20本の先行COMの完全一致を確認する。

最終集計は235正条件と8故障注入の期待失敗。詳細はverification_result.jsonとログを参照。再現入口は`bash tools/run_checks.sh`。
