# 再構築R4：絶対バイトアクセスとEX(SPL)

## 基準と変更範囲

R3を基準とする。R3のGOWIN合成、実機起動、SofaRunとスペースマンボウのプレイ、
EZ80D3 R3: PASSはユーザーによる実機報告として記録する。R4実機は未確認。
変更するFPGAソースはCPU本体とmcodeの2ファイルだけ。
元T80、ラッパー、ALU、下位レジスタ、トップ、メモリブリッジ、SDRAMコントローラ、
GOWINプロジェクト設定、CST、SDCはR3と同一。multicycleやfalse_pathは追加しない。

## 実装した命令

| 命令 | 扱い |
|---|---|
| LD.LIL A,(nnn) / LD.LIL (nnn),A | 3バイトの即値アドレスを消費し、24bitアドレスで1バイト転送 |
| LD.LIS A,(nn) / LD.LIS (nn),A | 2バイトの即値アドレス、長いデータ空間の00:nnnnへアクセス |
| LD.SIL A,(nnn) / LD.SIL (nnn),A | 3バイト即値を消費。短いデータ空間なのでバンク00の下位16bitを使用 |
| LD.SISと無指定 | 従来の2バイトアドレス、Z80のバンク00アクセス |
| EX.L (SP),HL/IX/IY | 独立SPLを使い、3バイトの交換。49hまたは5Bhの長い指定 |
| EX.S (SP),HL/IX/IY | 従来SPSを使う2バイト交換。SPLは変更しない |

MBASEは未実装のため、短いデータ空間はバンク00固定。
プレフィクスはDD/FDの前に置く。データバスは外部8bitのまま。
PCと割込みは16bit。ADL状態・24bit命令フェッチ・24bit CALL/RET・ADL割込みは次の工程。

## EXの内部動作

サイクル1：SPLの先頭へアドレスを設定。
サイクル2～4：SPL、SPL+1、SPL+2を読み、24bitの一時レジスタへ保存。
サイクル5～7：同じ3アドレスへ旧レジスタ値の下位・中位・上位を書き込む。
最終書込み後、保存した3バイトをHL/IX/IYへ同時に反映する。SPL自体は一切変更しない。

各サイクルの24bitアドレスの上位と下位は同じT_Resで登録する。
WAIT中のT2ではアドレス・SP・結果を更新しない。
サイクル6/7を元T80のインデックス変位用の戻り経路と混同しないよう、R3と同様に分離する。
RegWEと上位レジスタの更新タイミングも最終書込みに合わせる。
これにより途中の書込み用データが新しい読出し値へ変わることを防ぐ。

## アドレスバスの分離

R1～R3のブリッジを変更しない。
実効アドレス上位が00以外のメモリアクセスでは、MSX側アドレスを0000h、MREQを非アクティブにする。
01FFFFhや03FFFFhを、バンクを無視してMSX側FFFFhへ接続しない。
バンク00の00FFFFhは従来どおりMSX空間なので、ソフトが意図的にアクセスすれば既存スロット動作になる。
VDPのスロット優先、CPU WAIT、要求時のアドレス／データ保持もR3のまま。

## 既にFLASHへ保存したCOM

使用するのは、先行P1／FLASHまとめZIPと同一の `EZ80MEM.COM`。
SHA256:

`b55c88d01325afe073d5562810dc43a133a811a8edf71709a8d02ecddcc6a9ff`

通常起動：PLANNEDを表示して終了。
R4の実機確認：`EZ80MEM /RUN`。
期待表示：`EZ80MEM P1: PASS`。
ヘッダのP1は先に作成したテストの版であり、R4の機能試験であることと矛盾しない。
同じCOMを新しいRTLの回帰に使うため、R4という表示へ書き換えていない。

### 試験内容

stage1は07FFFEh、07FFFFh、080000h、01FFFFh、1BFFFFhの各1バイトを検査する。
絶対書込み→独立したHL間接読出し、HL間接書込み→絶対読出しの両方向で比較する。
絶対経路の読みと書きの誤りが相殺されることを避ける。
stage2はSPL=03FFFFhでHL/IX/IYの各3バイト交換を検査する。
先に返却レジスタを低位SNAPへ保存してから、書き込まれた3バイトと返却値、SPL不変性を比較する。

破壊範囲：上記5アドレス、03FFFFh..040001h、COM自身の低位バッファと通常SPS。
COMの値確認は低位SNAPへ行うため、共通の高位060100h退避はこのMEMテストには必要ない。
物理RAMは専用領域の論理アドレス+640000h。03FFFFh→67FFFFh。
VRAM/MegaRAMをこのCOMから書き換えない。元のRAM内容は保存・復旧しない。

### 診断とDOS復帰

メモリ不一致時は最初の比較について、意図した論理ADDR、期待EXP、取得ACTを表示する。
ACTは再読出し値で置き換えない。返却レジスタの不一致なら低位SNAPのアドレスを表示する。
これは端子から取得したアドレストレースではない。
DI区間でDOS/BIOSを呼ばず、拡張をロックしてからZ80のSPSで診断変換・EI・BDOS9・DOS復帰を行う。
BDOS9モデル自身でもEIする。SPS、IX、IYが戻ることも確認する。
NMIとADL割込みの試験ではない。

## 今回の検証

合計36シミュレーション。`verification_result.json` が現行集計。

- 元T80とのロック状態バス比較16ケース。
- 未変更のEZ80D3.COMをR4で実行する回帰10ケース。
- FLASH保存済みEZ80MEM.COM /RUNを実行する8ケース。
- 追加のフラグ・幅・SP・境界試験2ケース。

MEMの8ケースは、正常4位相、絶対バイト書込み破損、交換書込み破損、交換読出し破損、拡張無効。
故障注入ではFAILだけでなくADDR/EXP/ACTも照合する。
通常の交換について、実際のブリッジ要求を観測し、3読出しの後に3書込みとなることと、全要求の物理アドレスを照合する。
1実行でHL/IX/IYの計18要求を確認する。

追加の内部COMは `sim/corners` に置くシミュレーション用の入力。
49h/5Bh×HL/IX/IY×03FFFFh/1BFFFDhの長い交換12件、
40h/52h×HL/IX/IYの短い交換6件、40h/49h/52hの絶対バイト3件を各位相で実行する。
交換後のSPL/SPS、全3バイトまたは下位2バイト、フラグS/Z/H/PV/N/Cの保持を確認する。
短い交換では通常スタック上に専用の2バイト枠を作り、終了後に破棄して保存済みIX/IYを壊さない。
内部COMの通常SPの期待アドレスはテストベンチのDOS風呼出し規約に固定しており、実機での追加実行を要求するものではない。

CPUはGHDLからVerilogへ変換し、実COM、SDRAMモデル、簡易低位メモリ、BDOS9モデルで機能確認する。
実MSX-DOS全体、BIOS起動完了のシミュレーションではない。
部分top Verilog構文確認は周辺VHDL・ベンダプリミティブをブラックボックス化している。
GOWIN合成・配置配線・実際のタイミング・HDMI出力・実機動作は未確認。
R4をビルドしたレポートでタイミング違反と捕捉・保持条件を照合する必要がある。

## 再生成

```
python3 tools/rebuild_from_t80.py
python3 tools/extend_r2.py
python3 tools/extend_r3.py
python3 tools/extend_r4.py
```

GHDL、Icarus Verilog、vvpの環境で `tools/run_checks.sh` を実行する。
EZ80MEM.COMは既配布バイナリを固定入力とし、このR4内で再生成しない。
